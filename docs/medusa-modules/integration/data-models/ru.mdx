# {frontmatter.title}

В этом справочнике перечислены модели данных Модуля интеграций. Как у любой модели данных Medusa, у каждой из них есть ещё поля `created_at`, `updated_at` и `deleted_at`.

<Note type="default" title="">

Читайте эти модели через [сервис](/medusa-modules/integration/service) модуля или [Admin API](/medusa-modules/integration/admin-api), а меняйте только через его [воркфлоу](/medusa-modules/integration/workflows).

</Note>

## Обзор связей

Две модели не связаны в базе данных. Запись `IntegrationChange` называет свою интеграцию только значением `provider_id`, как показывает схема.

```mermaid alt="Схема показывает модели Integration и IntegrationChange, связанные по provider_id без внешнего ключа"
erDiagram
  Integration {
    string id PK
    string provider_id UK
    enum category
    boolean is_enabled
    enum last_test_status
  }
  IntegrationChange {
    string id PK
    string provider_id
    string change_type
    string actor_type
    datetime created_at
  }
  Integration |o..o{ IntegrationChange : "provider_id"
```

Значение `provider_id` общее у `Integration` и `IntegrationChange`, но в `IntegrationChange` это обычный текст, поэтому внешнего ключа и каскадного удаления нет. Удаление интеграции оставляет её изменения на месте, поэтому запись об изменении переживает свою интеграцию.

## Integration

Сохранённые настройки одного инстанса интеграции, таблица `integration`. Модуль создаёт запись при первом сохранении любой секции и удаляет её, когда администратор магазина удаляет интеграцию. Зарегистрированный провайдер без записи получает статус **Не настроено**.

Признак полной настройки интеграции не хранится. Модуль проверяет его по текущему дескриптору провайдера каждый раз, когда он нужен, поэтому признак не устаревает при изменении дескриптора.

В таблице `integration` есть уникальный индекс по `provider_id`, который охватывает записи с пустым `deleted_at`, индекс по `category` и индекс по `deleted_at`.

В таблице `integration_change` есть индексы по `provider_id` вместе с `created_at`, по `created_at` и по `deleted_at`, а также индекс по `actor_id`, который охватывает только записи с заполненным `actor_id`.
