# {frontmatter.title}

В этом справочнике перечислены API-роуты, которые Модуль интеграций добавляет в `/admin/integrations`. Medusa Admin пользуется ими на всех страницах интеграций, а ваши скрипты и [собственные виджеты](/medusa-modules/integration/custom-sections) тоже могут ими пользоваться.

Как и любые роуты Medusa в `/admin`, они требуют аутентифицированного пользователя Admin или секретный ключ API. Роуты с `:provider_id` отвечают `404`, если под этим ключом не зарегистрирован ни один провайдер.

## Интеграции

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/admin/integrations` | Возвращает все зарегистрированные инстансы с их состоянием. |
| `GET` | `/admin/integrations/:provider_id` | Возвращает дескриптор инстанса, его сохранённые настройки и данные пакета. |
| `POST` | `/admin/integrations/:provider_id` | Сохраняет значения параметров через [`upsertIntegrationWorkflow`](/medusa-modules/integration/workflows#upsertintegrationworkflow). |
| `DELETE` | `/admin/integrations/:provider_id` | Удаляет сохранённые настройки через [`deleteIntegrationWorkflow`](/medusa-modules/integration/workflows#deleteintegrationworkflow). |
| `POST` | `/admin/integrations/:provider_id/enable` | Включает или выключает интеграцию через [`setIntegrationEnabledWorkflow`](/medusa-modules/integration/workflows#setintegrationenabledworkflow). |
| `POST` | `/admin/integrations/:provider_id/test-connection` | Запускает проверку соединения через [`testIntegrationConnectionWorkflow`](/medusa-modules/integration/workflows#testintegrationconnectionworkflow). |

Роуты, которые меняют настройки, передают в воркфлоу аутентифицированного автора, а также IP-адрес, клиент и ID запроса, чтобы в [истории изменений](/medusa-modules/integration/change-history) был указан автор.

### Список интеграций

`GET /admin/integrations` принимает такие параметры запроса:

- `q` – ищет по идентификатору провайдера или инстанса. Переведённые названия Admin ищет на своей стороне.
- `category` – одна категория, например `payment`.
- `limit` – от 1 до 1000, по умолчанию `20`.
- `offset` – по умолчанию `0`.

Роут возвращает `{ integrations, count, limit, offset, categories }`. Каждый элемент `integrations` содержит `provider_id`, `identifier`, `instance_id` и `category` инстанса, i18n-ключи `display_name` и `description`, `icon`, данные пакета `version`, `author` и `author_url`, флаги `supports_multiple_instances`, `has_test_connection`, `is_configured`, `is_enabled` и `is_complete`, а также `last_test_status`. `categories` перечисляет категории всех зарегистрированных инстансов независимо от фильтров.

### Сохранение значений параметров

`POST /admin/integrations/:provider_id` принимает тело с такими полями:

- `values` – значения параметров для сохранения, где ключом служит идентификатор параметра.
- `section_id` – необязательный. С ним записываются только параметры этой секции. Без него записываются все отправленные ключи, которые объявлены в дескрипторе.
- `title` – необязательный. Название сохранённой записи или `null`, чтобы очистить его.

Например, чтобы сохранить секцию с учётными данными интеграции `int_my`:

```bash
curl -X POST "http://localhost:9000/admin/integrations/int_my" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  --data '{ "section_id": "credentials", "values": { "apiKey": "sk_test_123", "sandbox": true } }'
```

В ответ приходит `{ integration }`, сохранённая запись без секретов. `apiKey` из запроса упоминается в ней только по имени, в `configured_secrets`. Если значение не проходит валидацию, роут отвечает `400`, а в сообщении каждая проблема записана как `<идентификатор параметра>: <сообщение>`.

## История изменений

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/admin/integrations/changes` | Возвращает изменения всех интеграций. |
| `GET` | `/admin/integrations/:provider_id/changes` | Возвращает изменения одной интеграции. |
| `GET` | `/admin/integrations/changes/:id` | Возвращает одно изменение. |
| `GET` | `/admin/integrations/changes/actors` | Возвращает авторов изменений для фильтра по автору. |
| `GET` | `/admin/integrations/changes/fields` | Возвращает параметры, которые упоминаются в истории, для поиска. |

История доступна только для чтения, и эти роуты принимают только `GET`.

### Список изменений

Оба роута со списком принимают такие параметры запроса:

- `limit` – от 1 до 100, по умолчанию `20`.
- `offset` – по умолчанию `0`.
- `order` – поле для сортировки, с `-` впереди для обратного порядка. По умолчанию `-created_at`.
- `provider_id` – один или несколько ключей инстансов. Роут одной интеграции его игнорирует.
- `change_type` – одно или несколько значений из `created`, `updated`, `enabled`, `disabled` и `deleted`.
- `actor_id` – один или несколько идентификаторов пользователей. `system` обозначает все изменения, сделанные не пользователем Admin.
- `created_at` – диапазон дат с операторами вроде `$gte` и `$lte`.
- `q` – ищет по email автора или названию ключа API и по `provider_id`.
- `q_fields`, `q_providers` – вместе с `q` находят ещё и изменения, которые затронули один из этих идентификаторов или ключей меток параметров или относятся к одному из этих инстансов. Admin заполняет их тем, что совпало с `q` в переведённых названиях.

Роуты возвращают `{ integration_changes, count, offset, limit }`, по умолчанию сначала новые.

## Каталог и лицензии

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` | `/admin/integrations/catalog` | Возвращает [каталог интеграций](/medusa-modules/integration/browse-integrations) с `installed` и `provider_id` для каждой записи, зарегистрированной в проекте. |
| `GET` | `/admin/integrations/license-status` | Возвращает последний результат проверки лицензии каждой платной интеграции Gorgo в виде `{ packages }`. |
| `POST` | `/admin/integrations/license-status/recheck` | Сразу проверяет лицензии и возвращает свежие результаты в том же виде. |
