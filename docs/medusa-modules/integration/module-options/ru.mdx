# {frontmatter.title}

В этом документе вы узнаете о параметрах Модуля интеграций. Эти параметры можно передать при регистрации модуля как плагина в `medusa-config.ts`.

## Все параметры модуля

Параметры описывает тип `IntegrationModuleOptions`, который экспортирует `@gorgo/medusa-integration`. В таблице перечислены его свойства:

| Параметр | Описание | Обязательный | По умолчанию |
| --- | --- | --- | --- |
| [`encryptionKey`](#encryptionkey) | Пароль, из которого модуль выводит ключ для шифрования параметров с `secret: true`. | Если у провайдера есть параметр с `secret: true` | – |
| [`providers`](#providers) | Провайдеры Модуля интеграций, которые нужно зарегистрировать. | Нет | `[]` |
| [`license`](#license) | Ключ проекта, по которому лицензируются платные интеграции Gorgo. | Нет | Переменная окружения `GORGO_LICENSE` |

---

## encryptionKey

Опция `encryptionKey` задаёт пароль, из которого модуль выводит ключ шифрования. Он шифрует (AES-256-GCM) каждый параметр с пометкой `secret: true` перед сохранением и расшифровывает эти значения обратно во время выполнения.

Задайте её при регистрации модуля:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        encryptionKey: process.env.INTEGRATION_ENCRYPTION_KEY,
      },
    },
  ],
})
```

Значением может быть любая непустая строка, но для продакшена лучше подходит значение с высокой энтропией, например результат `openssl rand -hex 32`. Модуль выводит ключ один раз, при первом обращении, и затем использует его для полей `secret` всех зарегистрированных интеграций. Без `encryptionKey` модуль выбрасывает ошибку при первой попытке сохранить интеграцию с хотя бы одним параметром `secret: true` или получить её параметры.

Модуль выбрасывает обычный `Error`, сообщение которого начинается с `[integration] encryptionKey is required`. Обычный `Error` не относится к типизированным ошибкам Medusa, поэтому API-роут Admin отвечает `500` с общим сообщением `An unknown error occurred.`, а настоящее сообщение попадает только в лог сервера. Если сохранение интеграции в Admin завершается ответом `500`, ищите это сообщение в логе.

<Note type="warning">

Задайте одинаковый `encryptionKey` во всех процессах Medusa, и на сервере, и в воркере, и не меняйте его, пока интеграции хранят секреты. Значение, зашифрованное другим ключом, модуль расшифровать не может, поэтому после смены ключа получение параметров такой интеграции завершается ошибкой, как и загрузка списка интеграций в Admin. Это собственная ошибка расшифровки Node.js (`Unsupported state or unable to authenticate data`), а не сообщение модуля, поэтому API-роут Admin отвечает `500`, а подробности есть только в логе сервера. Чтобы всё заработало, верните прежний ключ. Если он утерян, удалите затронутые интеграции через [`DELETE /admin/integrations/:provider_id`](/medusa-modules/integration/admin-api#интеграции), которому расшифровка не нужна, и настройте их заново.

</Note>

## providers

Опция `providers` содержит массив [провайдеров Модуля интеграций](/medusa-modules/integration/create-integration-module-provider).

При старте приложения Medusa эти провайдеры регистрируются в Модуле интеграций, и их параметры становятся доступны для настройки в Admin.

Например:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        providers: [
          {
            resolve: "@gorgo/medusa-payment-my/providers/integration-my",
            id: "my-1",
            options: {},
          },
        ],
      },
    },
  ],
})
```

Опция `providers` принимает массив объектов с такими свойствами:

- `resolve`: строка с именем пакета провайдера Модуля интеграций или путь до него.
- `id`: необязательная строка, задающая конкретную регистрацию. Не указывайте её для единственного безымянного инстанса провайдера, либо задайте её, чтобы зарегистрировать [несколько инстансов](/medusa-modules/integration/concepts#инстансы-и-их-идентификаторы) одного и того же провайдера.
- `options`: объект с собственными параметрами провайдера. Для провайдера Модуля интеграций это почти всегда `{}`, потому что настоящие настройки задаёт администратор магазина в Admin.

## license

Параметр `license` задаёт ключ проекта из [кабинета Gorgo](https://app.gorgojs.com). По нему модуль проверяет лицензию каждой установленной платной интеграции Gorgo, в фоне после запуска и затем раз в сутки. Бесплатные интеграции не проверяются, а без установленной платной интеграции модуль к сервису лицензий не обращается.

Если параметр не задан, модуль берёт ключ из переменной окружения `GORGO_LICENSE`, поэтому обычно достаточно задать переменную:

```text title=".env"
GORGO_LICENSE=gorgo_live_...
```

Проверка никогда не мешает серверу запуститься. Её результат показывается рядом с каждой платной интеграцией в Admin.

Модуль выполняет проверку в каждом процессе, который его загружает, поэтому ключ нужен и серверу, и воркеру. Если вы используете `GORGO_LICENSE`, задайте переменную в окружении обоих. Если ключа нет или он не похож на ключ проекта (`gorgo_live_…`), модуль не отправляет запрос в сервис лицензий, а Admin показывает **Не задан ключ лицензии** или **Ключ лицензии в неверном формате**. Если сервис лицензий недоступен, модуль повторяет запрос примерно через 15 минут, не дожидаясь следующей ежедневной проверки, а Admin пока показывает **Лицензия не проверена**.

Как получить ключ, читайте в разделе [Лицензии на платные плагины](/licensing).
