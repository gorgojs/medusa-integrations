# {frontmatter.title}

In this document, you'll learn about the options of the Integration Module. You can pass these options when you register the module as a plugin in `medusa-config.ts`.

## All Module Options

| Option | Description | Required | Default |
| --- | --- | --- | --- |
| [`encryptionKey`](#encryptionkey) | A passphrase the module turns into the key that encrypts `secret: true` options. | When a provider has a `secret: true` option | – |
| [`providers`](#providers) | The Integration Module providers to register. | No | `[]` |
| [`license`](#license) | The project key that paid Gorgo integrations are licensed with. | No | The `GORGO_LICENSE` environment variable |

---

## encryptionKey

The `encryptionKey` option is the passphrase the module derives its encryption key from. It encrypts every option marked `secret: true` (AES-256-GCM) before saving it, and decrypts those values back at runtime.

Set it when you register the module:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        encryptionKey: process.env.INTEGRATION_ENCRYPTION_KEY,
      },
    },
  ],
})
```

The value can be any non-empty string, though a high-entropy one is best for production, for example the output of `openssl rand -hex 32`. The module derives the key once, the first time it's needed, and reuses it for every registered integration's `secret` fields from then on. Without `encryptionKey`, the module throws the first time it tries to save or read an integration that has at least one `secret: true` option.

<Note type="warning">

Keep `encryptionKey` the same on every Medusa process, server and worker alike, and for as long as integrations store secrets. The module can't decrypt a value encrypted with another key, so after a change, reading such an integration's options fails with an error, and so does the integrations list in the Admin. Restore the previous key to bring them back. If it's lost, delete the affected integrations through [`DELETE /admin/integrations/:provider_id`](/medusa-modules/integration/admin-api#integrations), which doesn't decrypt anything, and configure them again.

</Note>

## providers

The `providers` option is an array of [Integration Module providers](/medusa-modules/integration/create-integration-module-provider).

When the Medusa application starts, these providers are registered under the Integration Module and their options become configurable in the Admin.

For example:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        providers: [
          {
            resolve: "@gorgo/medusa-payment-my/providers/integration-my",
            id: "my-1",
            options: {},
          },
        ],
      },
    },
  ],
})
```

The `providers` option is an array of objects that accept the following properties:

- `resolve`: A string indicating either the package name of the Integration Module provider or its relative path.
- `id`: An optional string identifying this particular registration. Omit it for the provider's single, unnamed instance, or set it to register [multiple instances](/medusa-modules/integration/concepts#identifiers-and-instances) of the same provider.
- `options`: An object of the module provider's own options. For an Integration Module provider, this is almost always `{}`, since the store admin sets the real configuration in the Admin instead.

## license

The `license` option is the project key from the [Gorgo dashboard](https://app.gorgojs.com). The module checks the license of every installed paid Gorgo integration against it, in the background after startup and then once a day. A free integration is never checked, and without a paid integration installed the module never contacts the license service.

Without the option, the module reads the key from the `GORGO_LICENSE` environment variable, so most projects only set the variable:

```text title=".env"
GORGO_LICENSE=gorgo_live_...
```

The check never blocks the server from starting. Its result shows next to each paid integration in the Admin. See [Paid Plugin Licensing](/licensing) for how to get a key.
