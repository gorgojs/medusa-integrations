# {frontmatter.title}

В этом руководстве вы узнаете, как управлять интеграциями в Medusa Admin.

## Просмотр списка интеграций

Чтобы открыть список интеграций:

1. Откройте Medusa Admin.
2. Перейдите в **Настройки → Интеграции**.

Откроется список всех интеграций, зарегистрированных в проекте: название и иконка, автор, описание и категория. Для каждой интеграции показан статус. Список можно фильтровать по категории и искать по названию.

![Список интеграций](/static/integration/ru/integrations-overview.webp)

### Статусы интеграций

Статус жизненного цикла показывается всегда и может быть одним из следующих:

| Статус | Описание |
| --- | --- |
| Не настроено | Ни одна секция настроек ещё не сохранена. |
| Не завершено | Часть секций сохранена, но не все обязательные поля заполнены или заполненные значения не проходят валидацию. |
| Включено | Интеграция полностью настроена и включена: провайдер получает её параметры во время выполнения. |
| Выключено | Интеграция полностью настроена, но отключена: провайдер перестаёт получать её параметры, как будто она не настроена. |

Если провайдер поддерживает проверку соединения, рядом со статусом жизненного цикла показывается ещё один, отдельный статус по результату последней проверки:

| Статус | Описание |
| --- | --- |
| Подключено | Последняя проверка соединения прошла успешно. |
| Ошибка подключения | Последняя проверка соединения завершилась ошибкой. |

Пока проверка соединения ни разу не запускалась, этот статус не показывается.

## Поиск и добавление интеграции

В каталоге показаны интеграции, которые ещё не зарегистрированы в проекте, наряду с уже зарегистрированными.

Чтобы добавить новую интеграцию:

1. Перейдите в **Настройки → Интеграции**.
2. Нажмите **Найти интеграции**.
3. Найдите нужную интеграцию.
4. Нажмите **Добавить**.
5. Следуйте инструкции по установке в открывшемся модальном окне: она содержит команду установки, фрагмент регистрации в `medusa-config.ts` и шаги настройки, которые нужно выполнить после перезапуска сервера. У каждого блока кода есть своя кнопка копирования.
6. Перезапустите сервер.

После этого интеграция появится в списке со статусом **Не настроено** и будет готова к настройке.

![Поиск интеграций](/static/integration/ru/browse-integrations.png)

## Настройка интеграции

Пока интеграция не настроена, её страница показывает секции с пустыми обязательными полями. Никакого отдельного действия для первого запуска нет: сохранение любой секции с заполненными полями и создаёт настройку.

Чтобы настроить интеграцию:

1. Перейдите в **Настройки → Интеграции**.
2. Откройте нужную интеграцию.
3. Нажмите на меню действий в заголовке нужной секции.
4. Выберите **Редактировать**.
5. Заполните обязательные поля в открывшейся боковой панели.
6. Нажмите **Сохранить**.

![Настройка интеграции](/static/integration/ru/configure-integration.png)

## Проверка соединения

Некоторые провайдеры поддерживают проверку соединения: она подтверждает, что введённые ключи принимаются провайдером, ещё до того как интеграция будет использована на практике. Если провайдер такую проверку не поддерживает, соответствующего пункта в меню действий не будет.

Чтобы проверить соединение:

1. Перейдите в **Настройки → Интеграции**.
2. Откройте нужную интеграцию.
3. Откройте меню действий у названия интеграции.
4. Выберите **Проверить соединение**.

Результат проверки появится в уведомлении.

![Проверка соединения](/static/integration/ru/test-connection.png)

## Редактирование секции

Секции настроенной интеграции редактируются точно так же, как при первой настройке.

Чтобы изменить секцию:

1. Перейдите в **Настройки → Интеграции**.
2. Откройте нужную интеграцию.
3. Нажмите на меню действий в заголовке нужной секции.
4. Выберите **Редактировать**.
5. Измените значения полей в открывшейся боковой панели.
6. Нажмите **Сохранить**.

---

## Включение и отключение интеграции

Отключённая интеграция сохраняет свои настройки, но провайдер перестаёт их получать, как будто интеграция не настроена.

Чтобы включить или отключить интеграцию:

1. Перейдите в **Настройки → Интеграции**.
2. Откройте нужную интеграцию.
3. Откройте меню действий у названия интеграции.
4. Выберите **Включить** или **Отключить**.

---

## Удаление интеграции

Удаление стирает только сохранённые данные: токены и остальные значения секций. Сам провайдер как источник интеграции при этом не удаляется. Он по-прежнему зарегистрирован в `medusa-config.ts` и снова появится в списке как ненастроенный. Чтобы полностью убрать провайдера, удалите его запись из `providers` в `medusa-config.ts`.

Удаление попадает в [историю изменений](/medusa-modules/integration/manage-integrations#история-изменений) вместе со снимком значений, которые были настроены.

Чтобы удалить интеграцию:

1. Перейдите в **Настройки → Интеграции**.
2. Откройте нужную интеграцию.
3. Откройте меню действий у названия интеграции.
4. Выберите **Удалить**.
5. Подтвердите удаление.

## История изменений

Модуль записывает каждое изменение настроек интеграции вместе с автором, временем и изменёнными полями. История хранится бессрочно и остаётся после удаления интеграции, поэтому по ней видно, как интеграция была настроена до удаления.

### Что записывается

| Событие | Когда записывается |
| --- | --- |
| Заданы поля | Первое сохранение любой секции, пока у интеграции нет настроек. В запись попадают все сохранённые поля. |
| Изменены поля | Каждое следующее сохранение секции. В запись попадают только поля, значение которых изменилось. Сохранение без изменений не записывается. |
| Интеграция включена | Включение отключённой интеграции. |
| Интеграция выключена | Отключение включённой интеграции. |
| Настройки удалены | Удаление интеграции. В запись попадает снимок всех значений, которые были настроены. |

Проверка соединения в историю не записывается. Не попадают в неё и изменения, которые плагин записывает напрямую через сервис модуля, а не через его воркфлоу.

Автором записи становится пользователь Medusa Admin, который сохранил изменение. Его email хранится вместе с записью, поэтому изменения удалённого пользователя остаются подписанными. Если настройки меняет код на сервере без участия пользователя, например seed-скрипт, автором записывается **Система**.

Значения параметров с пометкой `secret` в историю не попадают. Для них история показывает только действие со значением, например **Значение задано**, **Значение заменено** или **Значение удалено**. Если параметр стал секретным уже после записи, его прежние значения показываются как **Значение скрыто**.

Значения длиннее 512 символов записываются сокращёнными и помечаются **(сокращено)**.

### История интеграции

Секция **История изменений** на странице интеграции показывает пять последних изменений этой интеграции. Секция остаётся на странице и после удаления интеграции.

Чтобы посмотреть историю интеграции:

1. Перейдите в **Настройки → Интеграции**.
2. Откройте нужную интеграцию.
3. Найдите секцию **История изменений**.

Чтобы открыть все изменения этой интеграции в таблице, нажмите **Вся история** под списком.

![Секция «История изменений» на странице интеграции ЮKassa](/static/integration/ru/history-section.webp)

### Все изменения

Страница **История изменений** собирает изменения всех интеграций в одну таблицу со временем, интеграцией, событием, автором и изменёнными полями.

Чтобы открыть историю всех интеграций:

1. Перейдите в **Настройки → Интеграции**.
2. Нажмите **История изменений**.

Поиск находит изменение по таким признакам:

- email автора;
- идентификатор интеграции (`provider_id`);
- название изменённого поля на языке интерфейса или его идентификатор в дескрипторе.

Кнопка **Добавить фильтр** добавляет один из фильтров:

- **Интеграция**;
- **Событие** – тип записи из таблицы выше;
- **Автор** – пользователи, которые меняли настройки, и **Система**;
- **Дата** – период.

Отсортируйте таблицу по времени, интеграции, событию или автору в меню сортировки или нажатием на заголовок колонки. Повторное нажатие меняет направление.

Поиск, фильтры и сортировка сохраняются в адресе страницы, поэтому ссылкой на отфильтрованную историю можно поделиться.

![Страница «История изменений» с изменениями всех интеграций](/static/integration/ru/history-table.webp)

### Подробности изменения

Нажмите на изменение в таблице или в секции интеграции, чтобы открыть боковую панель **Подробности изменения**. В ней три блока:

- **Общее** – интеграция, автор и время изменения.
- **Метаданные** – IP-адрес, клиент (браузер или программа, которая отправила запрос) и ID запроса. Блок свёрнут по умолчанию.
- **Изменения** – каждое изменённое поле в виде «было → стало». У включения и отключения этого блока нет.

Кнопка **Скопировать как JSON** копирует изменение целиком, без значений секретов. Адрес страницы с открытой панелью ведёт прямо к этому изменению.

![Панель «Подробности изменения» с изменёнными полями](/static/integration/ru/change-details.webp)
