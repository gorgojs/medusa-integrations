# {frontmatter.title}

In this guide, you'll learn how to manage integrations in Medusa Admin.

## View Integrations List

To view the integrations list:

1. Open Medusa Admin.
2. Go to **Settings → Integrations**.

This opens the list of every integration registered in the project. Each row shows the provider's name and icon, the package version and author, its description, its category, and its status. The grey badge next to the name holds the ID Medusa knows the provider by, such as `pp_…` for a payment provider or `fp_…` for a fulfillment provider, and the integration's own `int_…` key for the other categories. You can filter the list by category and search it by the integration's name, description, or identifier.

![Integrations list](/static/integration/en/integrations-overview.webp)

The action menu at the end of a row enables, disables, tests, or deletes a configured integration without opening its page. To open the integration's page, click its row.

### Integration Statuses

The lifecycle status is always shown, and can be one of the following:

| Status | Description |
| --- | --- |
| Not configured | No section of the settings has been saved yet. |
| Incomplete | Some sections are saved, but not all required fields are filled in, or the values entered don't pass validation. |
| Enabled | The integration is fully configured and enabled. The provider receives its options at runtime. |
| Disabled | The integration is fully configured, but disabled. The provider stops receiving its options, as if it weren't configured. |

If the provider supports connection testing, a separate status is shown alongside the lifecycle status, based on the result of the last test:

| Status | Description |
| --- | --- |
| Connected | The last connection test succeeded. |
| Connection failed | The last connection test failed. |

While the connection test hasn't been run yet, this status isn't shown.

For a paid Gorgo integration, the list and the integration's page also show the result of its license check. Once the first check has answered, the license block on the integration's page has a **Check now** button that repeats the check right away. Refer to [Paid Plugin Licensing](/licensing) to learn how paid plugins are licensed.

## Browse and Add an Integration

The catalog lists the integrations available for Medusa, both the ones already registered in the project and the ones you can still add. To open it, click **Browse Integrations** above the list.

Refer to [Browse and Add Integrations in Medusa Admin](/medusa-modules/integration/browse-integrations) to learn how to find an integration in the catalog and add it to the project.

---

## Configure an Integration

Until an integration is configured, its page shows every section with its fields empty, except the fields the provider gives a default value. There's no separate action for the initial setup. Saving any section with its fields filled in creates the configuration.

To configure an integration:

1. Go to **Settings → Integrations**.
2. Open the integration you want to configure.
3. Click the action menu in the header of the section you want to fill in.
4. Choose **Edit**.
5. Fill in the required fields in the side panel that opens.
6. Click **Save**.

![Configuring an integration](/static/integration/en/configure-integration.png)

The module checks the section's values before saving them. A new integration is enabled by default, so its status changes from **Incomplete** to **Enabled** as soon as the saved values pass validation in full. Refer to [Validate Integration Options](/medusa-modules/integration/validation) to learn about the rules a provider can declare.

## Test Connection

Some providers support connection testing, which confirms that the provider accepts the values you entered before the integration is used for real. The action appears only for a provider that supports it, and only while the integration is enabled and complete.

To test the connection:

1. Go to **Settings → Integrations**.
2. Open the integration you want to test.
3. Open the action menu next to the integration's name.
4. Choose **Test connection**.

The result appears in a notification.

The action menu of the integration's row in the list shows **Test connection** under the same conditions.

![Test Connection](/static/integration/en/test-connection.png)

Besides the manual test, the module re-tests every enabled integration whose provider supports it once a day, at 03:00 by the server's clock. The connection status shows the result of the latest test, manual or scheduled. An enabled integration that is still incomplete fails the scheduled test with `Not configured`, so it shows **Connection failed** until you finish the setup.

## Edit a Section

You edit the sections of an already configured integration the same way as during initial setup.

To edit a section:

1. Go to **Settings → Integrations**.
2. Open the integration you want to edit.
3. Click the action menu in the header of the section you want to change.
4. Choose **Edit**.
5. Update the field values in the side panel that opens.
6. Click **Save**.

A field holding a secret, such as an API key, shows only that a value is set. Leave it blank to keep the stored value, or type a new value to replace it.

---

## Enable and Disable an Integration

A disabled integration keeps its stored settings, but the provider stops receiving them, as if the integration weren't configured.

The action is available as soon as the integration has saved settings, complete or not. An incomplete integration keeps the **Incomplete** status either way, so the notification is the only sign that the switch worked.

To enable or disable an integration:

1. Go to **Settings → Integrations**.
2. Open the integration you want to update.
3. Open the action menu next to the integration's name.
4. Choose **Enable** or **Disable**.

---

## Delete an Integration

Deleting an integration erases only its stored data, such as tokens and the rest of its section values. The provider itself stays registered in `medusa-config.ts` and reappears in the list as not configured. To remove the provider entirely, delete its entry from `providers` in `medusa-config.ts`.

The deletion goes into the [change history](/medusa-modules/integration/change-history) with a snapshot of the values that were configured.

To delete an integration:

1. Go to **Settings → Integrations**.
2. Open the integration you want to delete.
3. Open the action menu next to the integration's name.
4. Choose **Delete**.
5. Confirm the deletion.

---

## Change History

The module records every change to an integration's settings with its author, time, and the fields it changed. An integration's page shows its latest changes, and the **Change History** button above the list opens the changes of every integration in one table.

Refer to [View the Change History in Medusa Admin](/medusa-modules/integration/view-change-history) to learn how to search, filter, and open a change.
