# {frontmatter.title}

The Integration Module lets any plugin declare its options and lets store admins configure them in the Admin, no `medusa-config` edits and no redeploys. The module takes care of the UI, storage, encryption, and validation.

The Integration Module is a good fit for Medusa developers building plugins, providers, or custom modules with configurable options (API keys, credentials, modes, webhooks) who'd rather not write a separate UI page, data layer, and validation for each one.

## Features

- **[Settings management in Admin](/medusa-modules/integration/manage-integrations)** – Store admins set options in the **Settings → Integrations** section, with no `medusa-config` edits and no redeploys.
- **Any plugin, provider, or module** – Works across payment, fulfillment, ERP, notification, content, and other extensions.
- **[Declarative descriptor](/medusa-modules/integration/descriptor)** – A single description (`defineIntegration`) of the options, settings sections, validation, and connection test.
- **[Flexible typing and validation](/medusa-modules/integration/validation)** – Typed fields (`string`, `url`, `email`, `uuid`, `number`, `boolean`, `enum`, `json`) with per-option and cross-section rules, conditional visibility, and read-only fields. At runtime, the plugin gets a typed, decrypted object. Incomplete or disabled settings never resolve, so the plugin never gets an unfilled draft.
- **[Encrypted secrets](/medusa-modules/integration/descriptor#secrets-and-encryption)** – The module encrypts fields marked `secret` (AES-256-GCM) and never sends them to the browser.
- **[Multiple instances](/medusa-modules/integration/concepts#identifiers-and-instances)** – Register the same provider more than once, for example for several accounts in the same third-party service.
- **[Connection test](/medusa-modules/integration/descriptor#connection-test)** – Verify credentials against the third-party service right from the Admin, and let the module re-test them daily.
- **[Change history](/medusa-modules/integration/change-history)** – The module records who changed which fields of an integration's settings and when. You can search and filter the history in the Admin, and secret values never reach it.
- **[Extensible UI](/medusa-modules/integration/custom-sections)** – Sections can be reordered ([LayoutComposer](https://docs.medusajs.com/resources/admin-components/components/layout-composer)). If the generated sections aren't enough, you can implement any UI for your options using custom widgets.
- **[Localization](/medusa-modules/integration/localization)** – The settings UI speaks the admin user's language, with the translations your plugin ships.
- **[Integration catalog](/medusa-modules/integration/browse-integrations)** – Integrations from the Gorgo catalog are shown in the Admin, with a setup guide for each integration that provides one.

## Installation

The Integration Module requires Medusa v2.21.0 or later and Node.js v22.23.4 or later (22.x), v24.22.1 or later (24.x), or v26.12.1 or later. Install it in your Medusa application:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn add @gorgo/medusa-integration
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```bash
    npm install @gorgo/medusa-integration
    ```
  </CodeTab>
</CodeTabs>

Then register it as a plugin in `medusa-config.ts`, together with the providers of the integrations you install:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        encryptionKey: process.env.INTEGRATION_ENCRYPTION_KEY,
        providers: [
          // the providers of your integrations
        ],
      },
    },
  ],
})
```

Each provider in `providers` appears in Medusa Admin under **Settings → Integrations**. Refer to [Integration Module Options](/medusa-modules/integration/module-options) to learn about `encryptionKey` and the other options.

The module keeps integrations and their change history in its own tables. Run the migrations after you install or update it:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn medusa db:migrate
    ```
  </CodeTab>
  <CodeTab label="npx" value="npx">
    ```bash
    npx medusa db:migrate
    ```
  </CodeTab>
</CodeTabs>

Once the migrations run, restart the server, and the registered integrations are ready to configure.

## How to Use the Integration Module

In your Medusa application, an integration has two sides. A provider declares the options, and the code that needs them reads the values the store admin saved.

### Declare the Options

In a provider service, declare the options and the settings section they belong to in a descriptor:

```ts title="providers/integration-my/services/my-integration.ts"
import {
  AbstractIntegrationProviderService,
  defineIntegration,
  z
} from "@gorgo/medusa-integration"

const descriptor = defineIntegration({
  category: "payment",
  displayName: "my.name",
  options: {
    apiKey: {
      type: "string",
      control: "secret",
      secret: true,
      required: true,
      label: "my.apiKey"
    },
    sandbox: {
      type: "boolean",
      control: "switch",
      default: false,
      label: "my.sandbox"
    },
  },
  sections: [
    {
      id: "credentials",
      title: "my.credentials",
      options: ["apiKey", "sandbox"]
    },
  ],
})

export type MyOptions = z.infer<typeof descriptor.optionsSchema>

export default class MyIntegrationProvider extends AbstractIntegrationProviderService {
  static identifier = "my"

  get descriptor() {
    return descriptor
  }
}
```

The `sections` array draws the two options into one card of the settings page, and `secret: true` makes the module encrypt `apiKey` before it saves the value. `MyOptions` is the type of the options your code reads back later. Refer to [How to Create an Integration Module Provider](/medusa-modules/integration/create-integration-module-provider) to learn how to build a complete provider and register it in `medusa-config.ts`.

Once you register the provider, the store admin fills in its options under **Settings → Integrations**, as [Manage Integrations in Medusa Admin](/medusa-modules/integration/manage-integrations) describes.

### Read the Options at Runtime

In the code that needs the options, such as a payment provider that reads its credentials, call `resolveIntegrationOptions` with the provider's identifier:

```ts title="providers/payment-my/services/my-payment.ts"
import { resolveIntegrationOptions } from "@gorgo/medusa-integration"
import type { MyOptions } from "../../integration-my/services/my-integration"

// inside any provider method
const options = await resolveIntegrationOptions<MyOptions>({
  identifier: "my"
})
```

The returned `options` is typed as `MyOptions`, already decrypted and validated. When the integration is not configured, disabled, or incomplete, the helper throws a `MedusaError`. Refer to [Reading Options](/medusa-modules/integration/reading-options) to learn how to target an instance, handle the missing case, and read options from code that has the container.
