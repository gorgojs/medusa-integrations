# {frontmatter.title}

В этом руководстве вы узнаете о провайдере Модуля интеграций: что это такое, что нужно для его реализации, как модуль регистрирует его при старте приложения, и модель данных `Integration`, которая представляет каждый зарегистрированный инстанс в базе данных.

## Что такое провайдер Модуля интеграций

Провайдер Модуля интеграций объявляет интеграцию: её параметры, их группировку в секции настроек и необязательную проверку соединения. Администратор магазина настраивает её в Admin, без правок `medusa-config` и без повторного развёртывания.

Модуль интеграций не зависит от типа провайдера, поэтому, в отличие от встроенных коммерческих модулей Medusa, он не поставляется с провайдером по умолчанию или провайдером-заглушкой. Провайдером Модуля интеграций может быть любой плагин, провайдер или собственный модуль. Полный список сценариев смотрите в разделе [Где можно применять Модуль интеграций](/medusa-modules/integration/concepts#где-можно-применять-модуль-интеграций).

Каждый провайдер, зарегистрированный в параметре `providers` Модуля интеграций, представлен в базе данных [моделью данных `Integration`](#модель-данных-integration).

## Создание собственного провайдера Модуля интеграций

Провайдер Модуля интеграций представляет собой модуль, чей сервис расширяет `AbstractIntegrationProvider`, импортированный из `@gorgo/medusa-integration`. Как и у других провайдеров Medusa, один модуль может регистрировать несколько сервисов провайдера Модуля интеграций, каждый со своим `static identifier`, и каждый становится отдельным провайдером.

`AbstractIntegrationProvider` объявляет следующие члены класса:

| Член класса | Описание |
| --- | --- |
| `static identifier: string` | Обязательное поле. Стабильный идентификатор провайдера, общий для всех его инстансов. |
| `get descriptor()` | Обязательное абстрактное свойство. Возвращает дескриптор, созданный через `defineIntegration`: параметры, секции, валидацию и необязательную проверку соединения. |
| `static validateOptions(options)` | Необязательный метод. Fail-fast проверка конфигурации провайдера из `medusa-config.ts` при загрузке приложения. По умолчанию ничего не делает. |
| `getIdentifier()` | Реализован в базовом классе. Возвращает `static identifier` конструктора. |
| `getInstanceId()` | Реализован в базовом классе. Возвращает `id` регистрации этого инстанса или `null` для инстанса по умолчанию. |

Вот минимальная форма провайдера со всеми членами класса из таблицы выше, кроме тех, что уже реализует базовый класс:

```ts title="providers/integration-my/services/my-integration.ts"
import { AbstractIntegrationProvider } from "@gorgo/medusa-integration"

class MyIntegrationProvider extends AbstractIntegrationProvider {
  static identifier = "my"

  static validateOptions(options: Record<string, unknown>) {
    // необязательная fail-fast проверка
  }

  get descriptor() {
    return descriptor
  }
}

export default MyIntegrationProvider
```

`descriptor` здесь представляет собой результат `defineIntegration`, подробнее об этом в разделе [Основные концепции](/medusa-modules/integration/concepts#дескриптор). `getIdentifier()` и `getInstanceId()` в примере не показаны: `AbstractIntegrationProvider` уже реализует оба метода через аргумент `instanceId` конструктора, поэтому подкласс добавляет только `static identifier`, `descriptor` и, опционально, `static validateOptions`.

<Note type="default" title="">

Полный пошаговый пример с кодом смотрите в разделе [Как создать провайдер Модуля интеграций](/medusa-modules/integration/create-integration-module-provider).

</Note>

## Регистрация провайдеров Модуля интеграций

### Настройка провайдеров Модуля интеграций

Модуль интеграций принимает параметр `providers`, в котором вы настраиваете провайдеры, зарегистрированные в вашем приложении, а также параметр `encryptionKey`, используемый для секретных полей модуля. Точную структуру `medusa-config.ts` смотрите в [шаге 4 руководства «Как создать провайдер Модуля интеграций»](/medusa-modules/integration/create-integration-module-provider#4-подключите-провайдер).

### Регистрация при старте приложения

При старте приложения Medusa Модуль интеграций регистрирует каждый провайдер из параметра `providers`. Для каждой записи он объединяет `static identifier` класса провайдера с `id` записи в ключ `int_<identifier>[_<id>]`. Это тот же формат, что используется для `provider_id` этого инстанса в базе данных. Затем он создаёт провайдер через `new ProviderClass(container, options, instanceId)`.

### Модель данных `Integration`

Инстанс зарегистрированного провайдера Модуля интеграций представлен в приложении Medusa моделью данных `Integration`.

<Note type="warning">

Собственный `id` модели служит лишь её внутренним идентификатором записи, таким же, как у любой другой модели данных Medusa. Это не то же самое, что `provider_id`, поле, которое хранит ключ `int_<identifier>[_<id>]` из раздела [Инстансы и их идентификаторы](/medusa-modules/integration/concepts#инстансы-и-их-идентификаторы).

</Note>

| Поле | Описание |
| --- | --- |
| `provider_id` | Ключ инстанса, `int_<identifier>[_<id>]`. Уникальный. По этому полю CRUD API, резолвер и Admin находят нужную запись. |
| `category` | Категория интеграции, например `payment` или `fulfillment`, задаётся из поля `category` дескриптора. |
| `title` | Отображаемое название интеграции или `null`, если дескриптор его не задаёт. |
| `options` | Несекретные настройки интеграции, сохранённые администратором магазина. |
| `is_enabled` | По умолчанию `true`. Переключается из Admin, см. [Включение и отключение интеграции](/medusa-modules/integration/manage-integrations#включение-и-отключение-интеграции). |
| `last_test_status` | Результат последней проверки соединения: `passed`, `failed` или `skipped`, либо `null`, если проверка ещё не запускалась. |

### Удаление провайдера Модуля интеграций

Вы можете удалить зарегистрированный провайдер Модуля интеграций, удалив его запись из параметра `providers` в `medusa-config.ts`. В отличие от отключения интеграции из Admin, это не затрагивает сохранённую запись. Провайдер просто перестаёт регистрироваться, поэтому модуль больше не может найти его запись `Integration` по `provider_id`. Интеграция исчезает из списка в Admin, а её сохранённые данные становятся недоступны через собственные admin-роуты Модуля интеграций.

<Note type="warning">

Удалите интеграцию из Admin, прежде чем убирать провайдер из `medusa-config.ts`, а не наоборот. Как только провайдер исчезает из конфигурации, его запись `Integration` становится недостижима, в том числе через сам роут удаления, и остаётся в базе данных без возможности удалить её из Admin. Обычный порядок удаления описан в разделе [Удаление интеграции](/medusa-modules/integration/manage-integrations#удаление-интеграции).

</Note>

Чтобы временно прекратить использование провайдера, сохранив его настройки и возможность быстро вернуть его обратно, отключите интеграцию из Admin вместо удаления провайдера из `medusa-config.ts`. См. [Включение и отключение интеграции](/medusa-modules/integration/manage-integrations#включение-и-отключение-интеграции).
