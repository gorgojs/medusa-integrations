# {frontmatter.title}

This reference lists the workflows and steps the Integration Module exports. The module's own [Admin API routes](/medusa-modules/integration/admin-api) run these workflows, and your code can run them too, for example from an API route, a subscriber, or your own workflow.

<Note type="warning">

Change integration settings only through these workflows. A write through the module's service skips validation, encryption, the cache reset, and the change history, see [Integration Module Service](/medusa-modules/integration/service).

</Note>

## Import Paths

`upsertIntegrationWorkflow`, `getResolvedIntegrationOptionsWorkflow`, and `getResolvedIntegrationOptionsStep` are exported from the package root. Every workflow and step on this page is exported from the `@gorgo/medusa-integration/workflows` subpath.

For example, a workflow of your own that disables an integration as one of its steps:

```ts title="src/workflows/disable-my-integration.ts"
import { createWorkflow, WorkflowResponse } from "@medusajs/framework/workflows-sdk"
import { setIntegrationEnabledWorkflow } from "@gorgo/medusa-integration/workflows"

export const disableMyIntegrationWorkflow = createWorkflow(
  "disable-my-integration",
  () => {
    const integration = setIntegrationEnabledWorkflow.runAsStep({
      input: { provider_id: "int_my", is_enabled: false },
    })

    return new WorkflowResponse(integration)
  }
)
```

`runAsStep` runs the module's workflow as a step of yours. The input has no `actor`, so the change history records the change with the `system` actor type. If a later step of your workflow fails, the integration returns to its previous state and its history record is removed.

## Workflows

### upsertIntegrationWorkflow

Saves option values of an integration instance. It creates the stored record on the first save and updates it afterwards. This is the workflow behind saving a section in the Admin.

The workflow validates the written options against the stored configuration with the new values on top, encrypts secrets, and saves the record. Then it records a `created` or `updated` change, unless nothing changed, and emits `integration.updated`. It returns the stored `Integration` record, whose `options` hold the secrets encrypted.

It fails with a `not_found` error when no provider is registered under `provider_id`, and with an `invalid_data` error for an unknown `section_id` or values that fail validation.

      type: "IntegrationChangeActor",
      description: "Who makes the change, for the change history. Without it, the change is recorded with the `system` actor type.",
      optional: true,

      children: []
    }
  ]}
/>

The workflow sets `is_enabled` on the stored record, records an `enabled` or `disabled` change unless the integration was already in that state, and emits `integration.updated`. It returns the updated record. It fails with a `not_found` error when the integration has no stored record yet, since there is nothing to enable before the first save. If a later step fails, the previous state is restored.

### deleteIntegrationWorkflow

Deletes the stored settings of an integration instance. The provider stays registered, and the integration shows as not configured again.

      name: "provider_id",
      type: "string",

      optional: false,
      expandable: false,
      children: []
    },
    {
      name: "actor",
      type: "IntegrationChangeActor",
      description: "Who makes the change, for the change history. Without it, the change is recorded with the `system` actor type.",
      optional: true,
      expandable: false,
      children: []
    }
  ]}
/>

The workflow deletes the stored record, records a `deleted` change with a snapshot of the values that were configured, and emits `integration.updated`. It returns `{ deleted, diff }`, where `deleted` is `false` when there was nothing to delete. It never decrypts the stored secrets, so it works even when the encryption key has changed.

### testIntegrationConnectionWorkflow

Runs the connection test the provider's descriptor declares.

<MedusaTypeList
  sectionTitle="Input"
  types={[
    {
      name: "provider_id",
      type: "string",
      description: "The instance's key, `int_<identifier>[_<instanceId>]`.",
      optional: false,
      expandable: false,
      children: []
    },
    {
      name: "actor",
      type: "IntegrationChangeActor",
      description: "Who runs the test. It's passed on in the `integration.tested` event, and the test itself isn't recorded in the change history.",
      optional: true,
      expandable: false,
      children: []
    }
  ]}
/>

The workflow runs the test against the resolved options, stores the result as the record's `last_test_status`, and emits `integration.tested`. It returns `{ status, message? }`. A disabled or incomplete integration gets `failed` without the test being called, see [Connection Test](/medusa-modules/integration/descriptor#connection-test).

The module's scheduled job, `test-integration-connections-daily`, runs this workflow every day at 03:00 for each enabled integration whose provider declares a test, with the actor `{ type: "job", id: "test-integration-connections-daily" }`. That includes an enabled integration that is still incomplete, which gets `failed` with the message `Not configured`.

### getResolvedIntegrationOptionsWorkflow

Resolves an integration instance's options, the same way as `resolveIntegrationOptions` and the service's `getResolvedOptions`.

## Steps

The workflows above are built from these steps. Use them in a workflow of your own when you need only part of what a workflow does.

| Step | Input | What it does |
| --- | --- | --- |
| `getResolvedIntegrationOptionsStep` | `{ identifier, instance_id? }` | Returns the resolved options, or `null`. |
| `getIntegrationStateStep` | `{ provider_id }` | Returns `{ existed, title, is_enabled }` of the stored record before a change. |
| `applyIntegrationSectionStep` | `{ provider_id, section_id?, values }` | Picks the options to write, validates them, and returns `{ category, options, diff }`, where `options` is the full configuration ready to store, with secrets encrypted. Stores nothing. |
| `upsertIntegrationRecordStep` | `{ provider_id, category, options, title? }` | Creates or updates the stored record. |
| `setIntegrationEnabledStep` | `{ provider_id, is_enabled }` | Sets `is_enabled` on the stored record and restores the previous value on rollback. |
| `deleteIntegrationRecordStep` | `{ provider_id }` | Deletes the stored record and returns `{ deleted, diff }`. |
| `runTestConnectionStep` | `{ provider_id }` | Runs the connection test and stores its status as `last_test_status`. |
| `recordIntegrationChangeStep` | `{ provider_id, change_type, actor?, diff?, skip? }` | Writes a change history record, or nothing when `skip` is `true` or an `updated` change has no fields. Never fails the workflow, and removes the record on rollback. |
| `emitIntegrationEventStep` | `{ name, data }` | Emits an event through Medusa's event bus. |
