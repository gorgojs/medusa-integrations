# {frontmatter.title}

В этом справочнике перечислены воркфлоу и шаги, которые экспортирует Модуль интеграций. Их запускают собственные [API-роуты Admin](/medusa-modules/integration/admin-api) модуля, и ваш код тоже может их запускать, например из API-роута, подписчика или собственного воркфлоу.

<Note type="warning">

Меняйте настройки интеграций только через эти воркфлоу. Запись через сервис модуля обходит валидацию, шифрование, сброс кэша и историю изменений, подробнее на странице [Сервис Модуля интеграций](/medusa-modules/integration/service).

</Note>

## Пути импорта

`upsertIntegrationWorkflow`, `getResolvedIntegrationOptionsWorkflow` и `getResolvedIntegrationOptionsStep` экспортируются из корня пакета. Все воркфлоу и шаги с этой страницы экспортируются из подпути `@gorgo/medusa-integration/workflows`.

Например, собственный воркфлоу, который одним из шагов выключает интеграцию:

```ts title="src/workflows/disable-my-integration.ts"
import { createWorkflow, WorkflowResponse } from "@medusajs/framework/workflows-sdk"
import { setIntegrationEnabledWorkflow } from "@gorgo/medusa-integration/workflows"

export const disableMyIntegrationWorkflow = createWorkflow(
  "disable-my-integration",
  () => {
    const integration = setIntegrationEnabledWorkflow.runAsStep({
      input: { provider_id: "int_my", is_enabled: false },
    })

    return new WorkflowResponse(integration)
  }
)
```

`runAsStep` запускает воркфлоу модуля как шаг вашего. Во входных данных нет `actor`, поэтому история изменений запишет изменение с типом автора `system`. Если следующий шаг вашего воркфлоу упадёт, интеграция вернётся в прежнее состояние, а её запись в истории будет удалена.

<Note type="warning">

Откат есть только у шагов `setIntegrationEnabledStep` и `recordIntegrationChangeStep`. Если вы запустили `upsertIntegrationWorkflow`, `deleteIntegrationWorkflow` или `testIntegrationConnectionWorkflow` как шаг собственного воркфлоу и следующий шаг упал, сохранённые параметры, удаление и `last_test_status` остаются, а запись в истории удаляется. В итоге изменение может остаться без записи в истории изменений. Что делает при откате каждый шаг, описано в разделе [Шаги](#шаги).

</Note>

## Воркфлоу

Каждый воркфлоу ниже, кроме `getResolvedIntegrationOptionsWorkflow`, заканчивается шагом `emitIntegrationEventStep`, который отправляет [событие](/medusa-modules/integration/events) воркфлоу, когда выполнились все предыдущие шаги. Если запуск падает раньше, например с ошибкой `not_found` или `invalid_data`, событие не отправляется, а откат не отправляет второе событие.

### upsertIntegrationWorkflow

Сохраняет значения параметров инстанса интеграции. При первом сохранении создаёт запись, а дальше обновляет её. Именно этот воркфлоу выполняется, когда в Admin сохраняют секцию. Шаги идут в таком порядке.

```mermaid alt="Схема показывает, как upsertIntegrationWorkflow проходит шаги от чтения сохранённого состояния до отправки события integration.updated"
flowchart TD
  state["getIntegrationStateStep"] --> apply["applyIntegrationSectionStep"]
  apply --> save["upsertIntegrationRecordStep"]
  save -->|"пропускается, если обновление не меняет ни одного поля"| history["recordIntegrationChangeStep"]
  history --> emit["emitIntegrationEventStep"]
  emit -->|"отправляет"| event(["integration.updated"])
```

Первый шаг читает сохранённое состояние, благодаря чему история изменений отличает первое сохранение от обновления. Запись в истории пропускается, если обновление не меняет ни одного поля, а событие отправляется в любом случае.

Воркфлоу проверяет записываемые параметры по сохранённой конфигурации с наложенными новыми значениями, шифрует секреты и сохраняет запись. ### setIntegrationEnabledWorkflow

Включает или выключает настроенную интеграцию. Шаги идут в таком порядке.

```mermaid alt="Схема показывает, как setIntegrationEnabledWorkflow проходит шаги от чтения сохранённого состояния до отправки события integration.updated"
flowchart TD
  state["getIntegrationStateStep"] --> set["setIntegrationEnabledStep"]
  set -->|"пропускается, если интеграция уже в этом состоянии"| history["recordIntegrationChangeStep"]
  history --> emit["emitIntegrationEventStep"]
  emit -->|"отправляет"| event(["integration.updated"])
```

Состояние, которое читает первый шаг, позволяет воркфлоу пропустить запись в истории, если интеграция уже в нужном состоянии. Событие отправляется в любом случае.

Воркфлоу меняет `is_enabled` у сохранённой записи, записывает в историю изменение `enabled` или `disabled`, если интеграция ещё не была в этом состоянии, и отправляет событие `integration.updated`. Возвращает обновлённую запись. Завершается ошибкой `not_found`, если у интеграции ещё нет сохранённой записи, потому что до первого сохранения включать нечего. Если следующий шаг падает, прежнее состояние восстанавливается.

### deleteIntegrationWorkflow

Удаляет сохранённые настройки инстанса интеграции. Провайдер остаётся зарегистрированным, а интеграция снова показывается как ненастроенная. Шаги идут в таком порядке.

```mermaid alt="Схема показывает, как deleteIntegrationWorkflow проходит шаги от удаления сохранённой записи до отправки события integration.updated"
flowchart TD
  delete["deleteIntegrationRecordStep"] -->|"пропускается, если удалять было нечего"| history["recordIntegrationChangeStep"]
  history --> emit["emitIntegrationEventStep"]
  emit -->|"отправляет"| event(["integration.updated"])
```

Запись в истории пропускается, если удалять было нечего, а событие отправляется в любом случае.

Воркфлоу удаляет сохранённую запись, записывает в историю изменение `deleted` со снимком настроенных значений и отправляет событие `integration.updated`. Возвращает `{ deleted, diff }`, где `deleted` равно `false`, если удалять было нечего. Сохранённые секреты он не расшифровывает, поэтому работает даже после смены ключа шифрования.

### testIntegrationConnectionWorkflow

Запускает проверку соединения, которую объявляет дескриптор провайдера. Шаги идут в таком порядке.

```mermaid alt="Схема показывает, как testIntegrationConnectionWorkflow проходит шаги от запуска проверки до отправки события integration.tested"
flowchart TD
  run["runTestConnectionStep"] -->|"сохраняет статус, только если запись есть"| emit["emitIntegrationEventStep"]
  emit -->|"отправляет"| event(["integration.tested"])
```

Шаг проверки сохраняет `last_test_status`, только если у интеграции есть сохранённая запись, а событие отправляется при любом результате.

  sectionTitle="Input"
  types={[
    {
      name: "provider_id",
      type: "string",
      description: "Ключ инстанса, `int_<identifier>[_<instanceId>]`.",

      name: "actor",
      type: "IntegrationChangeActor",
      description: "Кто запускает проверку. Передаётся дальше в событии `integration.tested`, а сама проверка в историю изменений не записывается.",
      optional: true,
      expandable: false,
      children: []
    }
  ]}
/>

Воркфлоу выполняет проверку с итоговыми параметрами и возвращает `{ status, message? }`. Кроме того, что возвращает ваш `testConnection`, модуль сам формирует такие результаты, и воркфлоу не бросает исключение ни в одном из них:

- `{ status: "skipped", message: "No test configured" }`, если в дескрипторе нет `testConnection`.
- `failed` с сообщением `Unknown integration provider "<id>"`, если под `provider_id` не зарегистрирован ни один провайдер.
- `failed` с сообщением `Not configured`, если дескриптор объявляет проверку, а интеграция не настроена, выключена или не заполнена. В этом случае модуль не вызывает `testConnection`.
- `failed` с сообщением из ошибки, если `testConnection` бросает исключение, и с сообщением `Test failed`, если у ошибки сообщения нет.

Для каждого из этих результатов воркфлоу отправляет событие `integration.tested`. Что Admin показывает для каждого статуса, описано в разделе [Проверка соединения](/medusa-modules/integration/descriptor#проверка-соединения).

Запланированная задача модуля `test-integration-connections-daily` запускает этот воркфлоу каждый день в 03:00 для каждой включённой интеграции, провайдер которой объявляет проверку, с автором `{ type: "job", id: "test-integration-connections-daily" }`. В их число входит и включённая, но ещё не завершённая интеграция, которая получает `failed` с текстом `Not configured`.

### getResolvedIntegrationOptionsWorkflow

Получает параметры инстанса интеграции так же, как `resolveIntegrationOptions` и метод сервиса `getResolvedOptions`.

      optional: false,

    }

/>

Воркфлоу возвращает `{ options, meta }` или `null`, если интеграция не настроена, выключена или не заполнена. Если под этими идентификатором и инстансом не зарегистрирован ни один провайдер, он бросает исключение. Когда его использовать, читайте в руководстве [Чтение параметров](/medusa-modules/integration/reading-options).

## Шаги

Воркфлоу выше собраны из этих шагов. Используйте их в собственном воркфлоу, когда нужна только часть того, что делает воркфлоу модуля. В последнем столбце указано, что делает шаг, когда следующий шаг вашего воркфлоу падает.

| Шаг | Входные данные | Что делает | При откате |
| --- | --- | --- | --- |
| `getResolvedIntegrationOptionsStep` | `{ identifier, instance_id? }` | Возвращает итоговые параметры или `null`. | Отменять нечего. |
| `getIntegrationStateStep` | `{ provider_id }` | Возвращает `{ existed, title, is_enabled }` сохранённой записи до изменения. | Отменять нечего. |
| `applyIntegrationSectionStep` | `{ provider_id, section_id?, values }` | Выбирает параметры для записи, проверяет их и возвращает `{ category, options, diff }`, где `options` содержит полную конфигурацию, готовую к сохранению, с зашифрованными секретами. Сам ничего не сохраняет. | Отменять нечего. |
| `upsertIntegrationRecordStep` | `{ provider_id, category, options, title? }` | Создаёт или обновляет сохранённую запись. | Отката нет. Сохранённая запись остаётся. |
| `setIntegrationEnabledStep` | `{ provider_id, is_enabled }` | Меняет `is_enabled` у сохранённой записи. | Восстанавливает прежнее значение `is_enabled`. |
| `deleteIntegrationRecordStep` | `{ provider_id }` | Удаляет сохранённую запись и возвращает `{ deleted, diff }`. | Отката нет. Запись остаётся удалённой. |
| `runTestConnectionStep` | `{ provider_id }` | Выполняет проверку соединения и сохраняет её статус в `last_test_status`, если у интеграции есть сохранённая запись. | Отката нет. `last_test_status` остаётся. |
| `recordIntegrationChangeStep` | `{ provider_id, change_type, actor?, diff?, skip? }` | Создаёт запись в истории изменений или ничего не делает, если `skip` равно `true` или у изменения `updated` нет полей. Никогда не роняет воркфлоу. | Удаляет запись в истории. |
| `emitIntegrationEventStep` | `{ name, data }` | Отправляет событие через шину событий Medusa. | Отката нет. Отправленное событие остаётся. |
