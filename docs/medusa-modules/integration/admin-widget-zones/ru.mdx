# {frontmatter.title}

В этом справочнике перечислены зоны внедрения, которые Модуль интеграций предоставляет в Medusa Admin, и свойства, которые получает виджет в этих зонах.

<Note type="default" title="">

Пошаговое руководство по созданию виджета для этих зон смотрите на странице [Собственные секции на виджетах](/medusa-modules/integration/custom-sections).

</Note>

## Зоны страницы интеграции

Страница интеграции отрисовывает секции через [LayoutComposer](https://docs.medusajs.com/resources/admin-components/components/layout-composer) Medusa, а зоны названы по `static identifier` провайдера:

| Зона | Где отрисовывается виджет |
| --- | --- |
| `gorgo.integration.<identifier>` | Основная колонка страницы. |
| `gorgo.integration.<identifier>.main` | Основная колонка страницы, названная явно. Работает так же, как `gorgo.integration.<identifier>`. |
| `gorgo.integration.<identifier>.side` | Боковая колонка страницы. Она есть, только если дескриптор задаёт `preferredLayoutId: "core:two-column"`. |

Например, виджет для провайдера ApiShip с идентификатором `apiship` размещается в зоне `gorgo.integration.apiship`.

Зона охватывает страницы всех инстансов провайдера, поэтому один и тот же виджет отрисовывается и на странице `int_apiship`, и на странице `int_apiship_eu`. Различайте инстансы по `data.providerId`.

По умолчанию виджет отрисовывается после всего, что модуль помещает в его колонку. В основной колонке это карточка с названием и статусом интеграции и сгенерированные секции, а на странице с одной колонкой ещё и секция **История изменений**. На странице с двумя колонками секция **История изменений** завершает боковую колонку.

Если администратор магазина сохранил раскладку, в которой изменён порядок секций колонки, у нового виджета нет сохранённой позиции, и он появляется почти вверху колонки. Администратор магазина может переместить или скрыть его, как любую другую секцию. Сохранённая раскладка общая для всех инстансов провайдера, потому что Medusa хранит её под префиксом зоны `gorgo.integration.<identifier>`. Администратор магазина может сохранить раскладку для себя или как раскладку по умолчанию для всех.

Суффикс `.before` или `.after` в названии зоны Medusa считает устаревшим и игнорирует. Виджет в `gorgo.integration.apiship.main.after` отрисовывается в основной колонке, как и виджет в `gorgo.integration.apiship`.

На остальных страницах модуля, в списке интеграций, каталоге и истории изменений, зон нет.

## Типы зон

`defineWidgetConfig` принимает только те зоны, которые знают его типы. Объявите зоны своего провайдера, дополнив `InjectionZoneRegistry` из `@medusajs/admin-shared` в файле `index.d.ts` плагина, как показано в [шаге 2 руководства «Собственные секции на виджетах»](/medusa-modules/integration/custom-sections#шаг-2-объявите-зону).

При сборке виджета для зон с этой страницы Medusa выводит в консоль `The injection zone "<zone>" is not a core injection zone. Custom zones are not validated, verify it is correct.` Это ожидаемое поведение, потому что Medusa проверяет только собственные основные зоны, а виджет всё равно отрисовывается.
