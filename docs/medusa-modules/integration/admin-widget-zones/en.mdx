# {frontmatter.title}

This reference lists the injection zones the Integration Module exposes in Medusa Admin and the props a widget in them receives.

<Note type="default" title="">

For a walkthrough of building a widget for these zones, see [Custom Sections with Widgets](/medusa-modules/integration/custom-sections).

</Note>

## Integration Page Zones

The integration's page renders its sections with Medusa's [LayoutComposer](https://docs.medusajs.com/resources/admin-components/components/layout-composer), and the zones are named after the provider's `static identifier`:

| Zone | Where the widget renders |
| --- | --- |
| `gorgo.integration.<identifier>` | The main column of the page. |
| `gorgo.integration.<identifier>.main` | The main column of the page, named explicitly. It works the same as `gorgo.integration.<identifier>`. |
| `gorgo.integration.<identifier>.side` | The side column of the page. The page has one only when the descriptor sets `preferredLayoutId: "core:two-column"`. |

For example, a widget for the ApiShip provider, whose identifier is `apiship`, goes into `gorgo.integration.apiship`.

A zone covers the pages of every instance of the provider, so the same widget renders on the page of `int_apiship` and of `int_apiship_eu`. Tell the instances apart by `data.providerId`.

By default, the widget renders after everything the module puts in its column. In the main column that is the card with the integration's name and status and the generated sections, and on a single-column page it also includes the **Change History** section. On a two-column page, the **Change History** section ends the side column.

If the store admin has saved a layout that reorders the column, a new widget has no saved position and appears near the top of the column instead. The store admin can move it, like any other section, or hide it. A saved layout is shared by every instance of the provider, because Medusa keys it by the zone prefix `gorgo.integration.<identifier>`. The store admin can save it for their own account or as the default for everyone.

Medusa treats a `.before` or `.after` suffix of a zone as a legacy name and ignores it. A widget in `gorgo.integration.apiship.main.after` renders in the main column, the same as one in `gorgo.integration.apiship`.

The module's other pages, the list of integrations, the catalog, and the change history, expose no zones.

## Zone Types

`defineWidgetConfig` only accepts zones its types know. Declare the zones of your provider by augmenting `InjectionZoneRegistry` from `@medusajs/admin-shared` in your plugin's `index.d.ts`, as shown in [Step 2 of Custom Sections with Widgets](/medusa-modules/integration/custom-sections#step-2-declare-the-zone).

When Medusa builds a widget for one of the zones on this page, it prints `The injection zone "<zone>" is not a core injection zone. Custom zones are not validated, verify it is correct.` in the console. This is expected, because Medusa validates only its own core zones, and the widget still renders.
