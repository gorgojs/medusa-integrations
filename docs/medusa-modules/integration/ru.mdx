# {frontmatter.title}

Модуль интеграций позволяет любому плагину описывать свои параметры и даёт администраторам магазина настраивать их в Admin, без правок `medusa-config` и без повторного развёртывания. UI, хранение, шифрование и валидацию модуль берёт на себя.

Модуль интеграций подойдёт разработчикам Medusa, которые создают плагины, провайдеры или собственные модули с настраиваемыми параметрами (ключи API, учётные данные, режимы, вебхуки), но не хотят писать под каждый из них отдельную страницу UI, слой данных и валидацию.

## Возможности

- **[Управление настройками в Admin](/medusa-modules/integration/manage-integrations)** – Администраторы магазина задают параметры в разделе **Настройки → Интеграции**, без правок `medusa-config` и без повторного развёртывания приложения Medusa.
- **Любой плагин, провайдер или модуль** – Подходит для платежей, доставки, ERP, уведомлений, контента и других расширений.
- **[Декларативный дескриптор](/medusa-modules/integration/descriptor)** – Единое описание (`defineIntegration`) параметров, секций настроек, валидации и проверки соединения.
- **[Гибкая типизация и валидация](/medusa-modules/integration/validation)** – Типизированные поля (`string`, `url`, `email`, `uuid`, `number`, `boolean`, `enum`, `json`) с правилами на уровне параметров и между секциями, условной видимостью и read-only-полями. Во время выполнения плагин получает типизированный расшифрованный объект. Неполные или выключенные настройки никогда не отдают параметры, поэтому плагин не получит незаполненный черновик.
- **[Шифрование секретов](/medusa-modules/integration/descriptor#секреты-и-шифрование)** – Модуль шифрует поля с пометкой `secret` (AES-256-GCM) и никогда не отправляет их в браузер.
- **[Несколько инстансов](/medusa-modules/integration/concepts#инстансы-и-их-идентификаторы)** – Зарегистрируйте один и тот же провайдер несколько раз, например для нескольких аккаунтов в одном стороннем сервисе.
- **[Проверка соединения](/medusa-modules/integration/descriptor#проверка-соединения)** – Проверяйте подключение к стороннему сервису прямо из Admin, а модуль будет перепроверять его ежедневно.
- **[История изменений](/medusa-modules/integration/change-history)** – Модуль записывает, кто, когда и какие поля изменил в настройках интеграции. В Admin историю можно искать и фильтровать, а значения секретов в неё не попадают.
- **[Расширяемый UI](/medusa-modules/integration/custom-sections)** – Секции можно менять местами ([LayoutComposer](https://docs.medusajs.com/resources/admin-components/components/layout-composer)). Если готовых секций недостаточно, можно реализовать любой UI для своих параметров с помощью собственных виджетов.
- **[Локализация](/medusa-modules/integration/localization)** – UI настроек показывается на языке пользователя Admin, с переводами, которые поставляет ваш плагин.
- **[Каталог интеграций](/medusa-modules/integration/browse-integrations)** – Доступные интеграции отображаются в Admin вместе с инструкцией по установке каждой.

## Установка

Модулю интеграций нужна Medusa v2.17.2 или новее. Установите его в приложение Medusa:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn add @gorgo/medusa-integration
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```bash
    npm install @gorgo/medusa-integration
    ```
  </CodeTab>
</CodeTabs>

Затем зарегистрируйте его как плагин в `medusa-config.ts` вместе с провайдерами интеграций, которые вы устанавливаете:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        encryptionKey: process.env.INTEGRATION_ENCRYPTION_KEY,
        providers: [
          // провайдеры ваших интеграций
        ],
      },
    },
  ],
})
```

Каждый провайдер из `providers` появляется в Medusa Admin в разделе **Настройки → Интеграции**. Про `encryptionKey` и остальные параметры читайте на странице [Параметры Модуля интеграций](/medusa-modules/integration/module-options).

Модуль хранит интеграции и их историю изменений в собственных таблицах. Выполните миграции после установки или обновления модуля:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn medusa db:migrate
    ```
  </CodeTab>
  <CodeTab label="npx" value="npx">
    ```bash
    npx medusa db:migrate
    ```
  </CodeTab>
</CodeTabs>

Когда миграции выполнены, перезапустите сервер, и зарегистрированные интеграции будут готовы к настройке.
