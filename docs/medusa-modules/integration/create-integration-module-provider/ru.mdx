# {frontmatter.title}

В этом руководстве вы узнаете, как создать провайдер Medusa для управления своими настройками через [Модуль интеграций](/medusa-modules/integration).

<Note type="info" title="Что такое Модуль интеграций?">

Модуль интеграций позволяет любому плагину описывать свои параметры в виде схемы, а администраторам магазина настраивать их в Admin, без правок `medusa-config` и без повторного развёртывания приложения Medusa. Он генерирует UI, предоставляет CRUD API и валидацию, поэтому вам не нужно писать свои модели данных, роуты, формы или воркфлоу.

</Note>

## Пример реализации

При реализации провайдера интеграции полезно смотреть на то, как это сделано в существующих провайдерах. Полный код провайдера модуля фулфилмента ApiShip после миграции доступен в репозитории [`medusa-integrations`](https://github.com/gorgojs/medusa-integrations/tree/main/packages/providers/fulfillment-apiship).

## 1. Создайте директорию провайдера

Начните с создания новой директории для вашего провайдера интеграции. Для плагина она размещается в `src/providers`, например `src/providers/integration-acme`.

## 2. Создайте сервис провайдера интеграции

Создайте файл `src/providers/integration-acme/services/acme-integration.ts`, который объявляет дескриптор интеграции и сам сервис.

### Дескриптор

Дескриптор: единое описание параметров, их группировки в секции настроек и (опционально) проверки соединения. Создаётся через `defineIntegration`:

```ts title="providers/integration-acme/services/acme-integration.ts"
import { defineIntegration, z } from "@gorgo/medusa-integration"

const descriptor = defineIntegration({
  category: "payment",
  displayName: "acme.name",
  options: {
    apiKey: {
      type: "string",
      control: "secret",
      secret: true,
      required: true,
      label: "acme.apiKey"
    },
    sandbox: {
      type: "boolean",
      control: "switch",
      default: false,
      label: "acme.sandbox"
    },
  },
  sections: [
    {
      id: "credentials",
      title: "acme.credentials",
      options: ["apiKey", "sandbox"]
    },
  ],
})

export type AcmeOptions = z.infer<typeof descriptor.optionsSchema>
```

<Note type="default" title="">Полный список полей `options` (`type`, `control`, `default`, `required`, `secret`, `visibleWhen`, `validate` и другие) см. в разделе [Основные концепции](/medusa-modules/integration/concepts#поля-определения-параметра).</Note>

### identifier

Каждый провайдер интеграции имеет уникальный идентификатор, по которому администратор его настраивает, а потребитель резолвит параметры:

```ts
class AcmeIntegration extends AbstractIntegrationProvider {
  static identifier = "acme"
  // ...
}
```

### descriptor

Класс провайдера обязан реализовать свойство `descriptor`, возвращающее объявленный выше дескриптор:

```ts
import { AbstractIntegrationProvider } from "@gorgo/medusa-integration"

export class AcmeIntegration extends AbstractIntegrationProvider {
  static identifier = "acme"

  get descriptor() {
    return descriptor
  }
}

export default AcmeIntegration
```

<Note type="default" title="">В отличие от других провайдеров Medusa, конструктор переопределять не нужно: базовый класс сам получает id инстанса из контейнера, а параметры провайдер получает не через конструктор, а резолвит из модуля в рантайме (см. [Шаг 5](#5-протестируйте)).</Note>

### validateOptions

Как и другие провайдеры Medusa, провайдер интеграции может объявить статический `validateOptions`, чтобы падать на старте, если конфиг в `medusa-config.ts` некорректен:

```ts
class AcmeIntegration extends AbstractIntegrationProvider {
  // ...
  static validateOptions(options: Record<string, unknown>) {
    // необязательная fail-fast проверка options.providers[].options
  }
}
```

<Note type="default" title="">На практике `options.providers[].options` у провайдера интеграции почти всегда `{}`. Реальные настройки задаются в Admin, а не в `medusa-config.ts`, поэтому `validateOptions` здесь нужен реже, чем у других провайдеров Medusa.</Note>

### testConnection

В отличие от `validateOptions`, который проверяет конфиг провайдера в `medusa-config.ts`, `testConnection` проверяет сами параметры интеграции (например, API-ключ) против стороннего сервиса. Администратор запускает её из Admin. Объявляется прямо в дескрипторе:

```ts
const descriptor = defineIntegration({
  // ...
  testConnection: async ({ options }) => {
    const res = await fetch("https://api.acme.com/ping", {
      headers: { Authorization: `Bearer ${options.apiKey}` },
    })

    return res.ok
      ? { status: "passed" }
      : { status: "failed", message: `Acme responded with ${res.status}` }
  },
})
```

## 3. Создайте файл определения провайдера

Создайте файл `src/providers/integration-acme/index.ts` со следующим содержимым:

```ts title="providers/integration-acme/index.ts"
import { ModuleProvider } from "@medusajs/framework/utils"
import { INTEGRATION_MODULE } from "@gorgo/medusa-integration"
import AcmeIntegration from "./services/acme-integration"

export default ModuleProvider(INTEGRATION_MODULE, {
  services: [AcmeIntegration],
})
```

Это экспортирует определение провайдера, указывая, что `AcmeIntegration` является его сервисом.

## 4. Подключите провайдер

Чтобы использовать провайдер интеграции, добавьте его в массив `providers` модуля интеграций в `medusa-config.ts`:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        encryptionKey: process.env.INTEGRATION_ENCRYPTION_KEY,
        providers: [
          {
            resolve: "./src/providers/integration-acme",
            id: "acme-1",
            options: {},
          },
        ],
      },
    },
    // ...
  ],
})
```

<Note type="warning">

У провайдера Модуля интеграций задаётся параметр `id`, из которого собирается итоговый идентификатор инстанса вида `int_<identifier>_<id>`. Такой же `id` нужно передать потребителю, чтобы он знал, какие настройки читать. Если провайдер интеграций поддерживает несколько инстансов, то у каждого будет свой `id`, который можно передать разным потребителям.

</Note>

Далее, добавьте секретный ключ шифрования в переменные окружения. Он нужен модулю интеграций, чтобы зашифровать секреты перед сохранением в базу данных:

```text title=".env"
INTEGRATION_ENCRYPTION_KEY=supersecret
```

## 5. Протестируйте

Запустите сервер и откройте **Настройки → Интеграции** в Medusa Admin. Интеграция появится в списке. Заполните параметры и нажмите «Проверить соединение», чтобы вызвать `testConnection`.

Чтобы прочитать сохранённые параметры используйте `resolveIntegrationOptions`, передав тот же `identifier`, что объявлен в дескрипторе:

```ts title="providers/payment-acme/services/acme-payment.ts"
import { resolveIntegrationOptions } from "@gorgo/medusa-integration"
import type { AcmeOptions } from "../../integration-acme/services/acme-integration"

const options = await resolveIntegrationOptions<AcmeOptions>({
  identifier: "acme",
})
```

Способ чтения зависит от того, где выполняется ваш код: изолированный провайдер, роут или подписчик с доступом к контейнеру приложения, либо шаг воркфлоу. Все три разобраны в разделе [Использование провайдера интеграции](/medusa-modules/integration/reading-options).
