# {frontmatter.title}

В этом руководстве вы узнаете, как создать провайдер Medusa для управления своими настройками через [Модуль интеграций](/medusa-modules/integration).

<Note type="info" title="Что такое Модуль интеграций?">

Модуль интеграций позволяет любому плагину описывать свои параметры в виде схемы, а администраторам магазина настраивать их в Admin, без правок `medusa-config` и без повторного развёртывания приложения Medusa. Он генерирует UI, предоставляет CRUD API и валидацию, поэтому вам не нужно писать свои модели данных, роуты, формы или воркфлоу.

</Note>

## Пример реализации

При разработке своего провайдера Модуля интеграций бывает полезно посмотреть, как устроен готовый провайдер.

Если вам нужен пример реальной реализации, посмотрите [провайдер платежей YooKassa в репозитории Medusa Integrations](https://github.com/gorgojs/medusa-integrations/tree/main/packages/providers/payment-yookassa).

## 1. Создайте директорию провайдера

Начните с создания новой директории для вашего провайдера Модуля интеграций. Для плагина она размещается в `src/providers`, например `src/providers/integration-my`.

## 2. Создайте сервис провайдера Модуля интеграций

Создайте файл `src/providers/integration-my/services/my-integration.ts`, который объявляет дескриптор интеграции и сам сервис.

```ts title="providers/integration-my/services/my-integration.ts"
import {
  AbstractIntegrationProvider
} from "@gorgo/medusa-integration"

class MyIntegrationProvider extends AbstractIntegrationProvider {
  // TODO add methods
}

export default MyIntegrationProvider
```

### identifier

Каждый провайдер Модуля интеграций имеет уникальный идентификатор, по которому администратор его настраивает, а потребитель резолвит параметры.

#### Пример

```ts title="providers/integration-my/services/my-integration.ts"
class MyIntegrationProvider extends AbstractIntegrationProvider {
  static identifier = "my"
  // ...
}
```

### descriptor

Класс провайдера обязан реализовать свойство `descriptor`. Дескриптор содержит единое описание параметров, их группировку в секции настроек и метод проверки соединения (опционально). Он создаётся через `defineIntegration`.

<Note type="default" title="">Поля `options` (`type`, `control`, `default`, `required`, `secret`, `visibleWhen`, `validate` и другие) разобраны в разделе [Основные концепции](/medusa-modules/integration/concepts).</Note>


#### Пример

```ts title="providers/integration-my/services/my-integration.ts"
import {
  AbstractIntegrationProvider,
  defineIntegration,
  z
} from "@gorgo/medusa-integration"

const descriptor = defineIntegration({
  category: "payment",
  displayName: "my.name",
  options: {
    apiKey: {
      type: "string",
      control: "secret",
      secret: true,
      required: true,
      label: "my.apiKey"
    },
    sandbox: {
      type: "boolean",
      control: "switch",
      default: false,
      label: "my.sandbox"
    },
  },
  sections: [
    {
      id: "credentials",
      title: "my.credentials",
      options: ["apiKey", "sandbox"]
    },
  ],
})

export type MyOptions = z.infer<typeof descriptor.optionsSchema>

export class MyIntegrationProvider extends AbstractIntegrationProvider {
  // ...
  get descriptor() {
    return descriptor
  }
}

export default MyIntegrationProvider
```

<Note type="default" title="">В отличие от других провайдеров Medusa, конструктор переопределять не нужно: базовый класс сам получает id инстанса из контейнера, а параметры провайдер получает не через конструктор, а резолвит из модуля в рантайме (см. [Шаг 5](#5-протестируйте)).</Note>

### validateOptions

Как и другие провайдеры Medusa, провайдер Модуля интеграций может объявить статический `validateOptions`, чтобы проверить конфиг в `medusa-config.ts` уже при развёртывании приложения.

#### Пример

```ts title="providers/integration-my/services/my-integration.ts"
class MyIntegrationProvider extends AbstractIntegrationProvider {
  // ...
  static validateOptions(options: Record<string, unknown>) {
    // необязательная fail-fast проверка options.providers[].options
  }
}
```

<Note type="default" title="">На практике `options.providers[].options` у провайдера Модуля интеграций почти всегда `{}`. Реальные настройки задаются в Admin, а не в `medusa-config.ts`, поэтому `validateOptions` здесь нужен реже, чем у других провайдеров Medusa.</Note>

### testConnection

В отличие от `validateOptions`, который проверяет конфиг провайдера в `medusa-config.ts`, `testConnection` проверяет сами параметры интеграции (например, API-ключ) против стороннего сервиса. Администратор запускает её из Admin. Объявляется прямо в дескрипторе.

#### Пример

```ts title="providers/integration-my/services/my-integration.ts"
const descriptor = defineIntegration({
  // ...
  testConnection: async ({ options }) => {
    const res = await fetch("https://api.my.com/ping", {
      headers: { Authorization: `Bearer ${options.apiKey}` },
    })

    return res.ok
      ? { status: "passed" }
      : { status: "failed", message: `My responded with ${res.status}` }
  },
})
```

## 3. Создайте файл определения провайдера

Создайте файл `src/providers/integration-my/index.ts` со следующим содержимым:

```ts title="providers/integration-my/index.ts"
import { ModuleProvider } from "@medusajs/framework/utils"
import { INTEGRATION_MODULE } from "@gorgo/medusa-integration"
import MyIntegrationProvider from "./services/my-integration"

export default ModuleProvider(INTEGRATION_MODULE, {
  services: [MyIntegrationProvider],
})
```

Это экспортирует определение провайдера, указывая, что `MyIntegrationProvider` является его сервисом.

## 4. Подключите провайдер

Чтобы использовать провайдер Модуля интеграций, добавьте его в массив `providers` модуля интеграций в `medusa-config.ts`:

```ts title="medusa-config.ts"
module.exports = defineConfig({
  // ...
  plugins: [
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        encryptionKey: process.env.INTEGRATION_ENCRYPTION_KEY,
        providers: [
          {
            resolve: "./src/providers/integration-my",
            id: "my-1",
            options: {},
          },
        ],
      },
    },
    // ...
  ],
})
```

<Note type="warning">

У провайдера Модуля интеграций задаётся параметр `id`, из которого собирается итоговый идентификатор инстанса вида `int_<identifier>_<id>`. Если провайдер Модуля интеграций поддерживает несколько инстансов, то у каждого будет свой `id`.

</Note>

Далее, добавьте секретный ключ шифрования в переменные окружения. Он нужен модулю интеграций, чтобы зашифровать секреты перед сохранением в базу данных:

```text title=".env"
INTEGRATION_ENCRYPTION_KEY=supersecret
```

## 5. Протестируйте

Запустите сервер и откройте **Настройки → Интеграции** в Medusa Admin. Интеграция появится в списке. Заполните параметры и нажмите «Проверить соединение», чтобы вызвать `testConnection`.

Чтобы прочитать сохранённые параметры используйте `resolveIntegrationOptions`, передав тот же `identifier`, что объявлен в дескрипторе:

```ts title="providers/payment-my/services/my-payment.ts"
import { resolveIntegrationOptions } from "@gorgo/medusa-integration"
import type { MyOptions } from "../../integration-my/services/my-integration"

const options = await resolveIntegrationOptions<MyOptions>({
  identifier: "my",
})
```

Способ чтения зависит от того, где выполняется ваш код: изолированный провайдер, роут или подписчик с доступом к контейнеру приложения, либо шаг воркфлоу. Все три разобраны в разделе [Использование провайдера Модуля интеграций](/medusa-modules/integration/reading-options).
