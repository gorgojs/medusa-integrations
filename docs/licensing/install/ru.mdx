# {frontmatter.title}

В этом руководстве вы подключите реестр пакетов Gorgo с ключом проекта и установите платный плагин. Как зарегистрировать плагин в Medusa и настроить его, описано на странице самого плагина.

Для установки нужны:

- аккаунт в [кабинете Gorgo](https://app.gorgojs.com), зарегистрироваться можно по почте или через GitHub;
- проект в кабинете с доменами ваших окружений, подробнее в разделе [Проекты и окружения](/licensing/dashboard#проекты-и-окружения);
- подписка на плагин для этого проекта.

---

## Шаг 1: Создайте ключ проекта

Откройте проект в кабинете, перейдите на вкладку **Ключ** и нажмите **Создать ключ**.

<Note type="warning" title="">

Кабинет показывает ключ один раз, поэтому сохраните его сразу. Потерянный ключ придётся перевыпустить, и прежний перестанет работать везде, где он указан.

</Note>

Плагины и менеджеры пакетов берут ключ из переменной окружения `GORGO_LICENSE`. Задайте её везде, где ставятся зависимости и работает магазин, то есть на своей машине, в CI/CD и в окружениях бэкенда. В репозиторий проекта ключ при этом не попадает.

```bash title=".env"
GORGO_LICENSE=gorgo_live_...
```

---

## Шаг 2: Подключите реестр

Платные плагины опубликованы не в общем реестре npm, а в реестре `registry.gorgojs.com`. Укажите менеджеру пакетов этот реестр для пакетов `@gorgo-store`. Yarn 2 и новее читает настройки из `.yarnrc.yml`, npm и pnpm из `.npmrc`:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```yaml title=".yarnrc.yml"
    npmScopes:
      gorgo-store:
        npmRegistryServer: "https://registry.gorgojs.com"
        npmAuthToken: "${GORGO_LICENSE}"
    ```
  </CodeTab>
  <CodeTab label="pnpm" value="pnpm">
    ```text title=".npmrc"
    @gorgo-store:registry=https://registry.gorgojs.com/
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```text title=".npmrc"
    @gorgo-store:registry=https://registry.gorgojs.com/
    //registry.gorgojs.com/:_authToken=${GORGO_LICENSE}
    ```
  </CodeTab>
</CodeTabs>

<Note type="warning" title="pnpm 11.5.3 и новее">

Начиная с версии 11.5.3, pnpm не подставляет переменные окружения в токены авторизации из `.npmrc` проекта, и без отдельного шага установка не пройдёт авторизацию в реестре. Поэтому для pnpm в `.npmrc` указан только адрес реестра, а ключ сохраните в пользовательских настройках pnpm.

</Note>

Для pnpm выполните эту команду на своей машине и в CI до установки зависимостей:

```bash
pnpm config set //registry.gorgojs.com/:_authToken "$GORGO_LICENSE"
```

---

## Шаг 3: Установите плагин

Установите пакет так же, как пакет из общего реестра npm, например плагин 1С:Предприятие:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn add @gorgo-store/medusa-erp-1c
    ```
  </CodeTab>
  <CodeTab label="pnpm" value="pnpm">
    ```bash
    pnpm add @gorgo-store/medusa-erp-1c
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```bash
    npm install @gorgo-store/medusa-erp-1c
    ```
  </CodeTab>
</CodeTabs>

Дальше зарегистрируйте плагин в `medusa-config` по руководству на его странице, например [Начало работы с 1С:Предприятием](/medusa-integrations/1c-enterprise/getting-started).

---

## Шаг 4: Проверьте лицензию

Запустите магазин и откройте в панели администратора Medusa раздел **Настройки → Интеграции**. Там виден результат проверки лицензии по каждому платному плагину. Проверка идёт в фоне, магазин её не ждёт, поэтому статус может появиться через несколько секунд после запуска.

<Note type="default" title="">

На `localhost` и `127.0.0.1` проверка проходит всегда. В продакшене и на стейджинге домен бэкенда должен быть в одном из окружений проекта.

</Note>

---

## Если что-то не работает

- **403 при установке** – у проекта нет подписки на этот пакет, или подписка закончилась раньше, чем вышла эта версия. Оплаченные пакеты перечислены на вкладке **Ключ** проекта.
- **401 при установке** – ключ не подставился или отозван. Проверьте `.npmrc` или `.yarnrc.yml` и значение `GORGO_LICENSE`.
- **Отказ по домену** – домена бэкенда нет в окружениях проекта. Добавьте его в настройках окружения, и плагин увидит его после перезапуска магазина или при следующей суточной проверке.

Если ответа здесь нет, напишите нам, как описано на странице [Поддержка](/resources/support).
