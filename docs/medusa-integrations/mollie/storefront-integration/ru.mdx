# {frontmatter.title}

Для интеграции платёжного провайдера Mollie в витрину [Medusa DTC Starter от Gorgo](https://github.com/gorgojs/medusa-dtc-starter) начните с добавления необходимых UI-компонентов. Так провайдер появится на странице оформления заказа рядом с другими способами оплаты.

Выбор Mollie запросов не отправляет. Когда покупатель нажимает кнопку оплаты, она запускает платёжную сессию, провайдер создаёт платёж в Mollie и возвращает адрес платёжной страницы Mollie, а кнопка отправляет покупателя на эту страницу, где он платит картой, через iDEAL, PayPal или другим способом, включённым в вашем профиле Mollie.

После оплаты Mollie вызывает вебхук и перенаправляет покупателя обратно на витрину. Корзину завершит и новый заказ в Medusa создаст событие, пришедшее первым.

Для витрины на Next.js необходимо внести следующие изменения:

## Шаг 1: Настройте платёжный провайдер

Чтобы Mollie появился среди способов оплаты на странице оформления заказа, добавьте его конфигурацию в маппинг платёжных провайдеров в файле с константами вашей витрины. Этот маппинг определяет, как каждый провайдер отображается в интерфейсе.

Откройте [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/lib/constants.tsx#L55-L59) и добавьте следующий код:

![Структура каталогов витрины Medusa после изменения файла с константами](/static/mollie/storefront/src-lib-constants.webp)

```tsx title="src/lib/constants.tsx"
export const paymentInfoMap: Record<string, PaymentInfo> = {
  // ...
  pp_mollie_mollie: {
    title: "Mollie",
    subtitle: "Cards, iDEAL, PayPal",
    icon: <CreditCard />,
  },
  // Add more payment providers here
}

// ...

export const isMollie = (providerId?: string) => {
  return providerId?.startsWith("pp_mollie_")
}
```

Вы дополняете объект `paymentInfoMap` записью `pp_mollie_mollie`. Она задаёт название, подзаголовок и иконку Mollie на странице оформления заказа, а также служит запасным вариантом, когда для локали нет перевода. Mollie принимает много способов оплаты, поэтому запись использует общую иконку `CreditCard` из стартера.

Вспомогательная функция `isMollie` проверяет, относится ли `providerId` к Mollie. Её используют диспетчер кнопок оплаты и страница заказа в следующих шагах.

## Шаг 2: Инициализируйте платёжную сессию

Чтобы отправить покупателя в Mollie, платёжной сессии нужны адрес, на который покупатель вернётся после оплаты, и язык страницы Mollie.

Откройте тот же файл [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/lib/constants.tsx#L1-L2) и импортируйте в начале файла локаль по умолчанию и базовый URL витрины:

![Структура каталогов витрины Medusa после изменения файла с константами](/static/mollie/storefront/src-lib-constants.webp)

```tsx title="src/lib/constants.tsx"
import { defaultLocale } from "@i18n/config"
import { getBaseURL } from "@lib/util/env"
```

Затем добавьте язык страницы, адрес возврата и функцию сборки данных сессии [после маппинга платёжных провайдеров](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/lib/constants.tsx#L70-L121):

```tsx title="src/lib/constants.tsx"
/**
 * The language of the page. `<html lang>` carries the locale the checkout was
 * rendered in, which a provider with its own payment page takes to show that
 * page in the customer's language.
 */
const pageLocale = () =>
  typeof document === "undefined"
    ? defaultLocale
    : document.documentElement.lang || defaultLocale

/**
 * The address the customer comes back to after paying on the provider's own
 * page, in the language they left the shop with.
 */
const paymentReturnUrl = (providerId: string, cartId: string) => {
  const origin =
    typeof window === "undefined" ? getBaseURL() : window.location.origin

  return `${origin}/api/payment-return?provider=${providerId}&cart_id=${cartId}&locale=${pageLocale()}`
}

const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
  /**
   * The provider's own pay button starts the payment session when the customer
   * pays, so the checkout does not start one when the method is picked or the
   * cart changes. `isReady` still gates the pay button.
   */
  deferred?: boolean
}> = [
  {
    test: (providerId) => isMollie(providerId),
    // A Mollie payment is created with the session, and Mollie neither changes
    // its amount nor cancels it while it is open, so a session replaced at the
    // payment step would leave a payable page behind. The pay button starts the
    // session, once the checkout has the email, the address and the shipping
    // method the payment is created with.
    deferred: true,
    isReady: (cart) =>
      Boolean(
        cart.email &&
          cart.shipping_address &&
          (cart.shipping_methods?.length ?? 0) > 0
      ),
    build: (cart) => ({
      redirect_url: paymentReturnUrl("mollie", cart.id),
      locale: pageLocale(),
    }),
  },
]
```

После `buildPaymentSessionData` добавьте функцию, по которой оформление заказа понимает, что способ запускает сессию с кнопки оплаты:

```tsx title="src/lib/constants.tsx"
export const isPaymentSessionDeferred = (providerId: string | undefined) => {
  return !!paymentSessionDataBuilders.find((b) => b.test(providerId))?.deferred
}
```

При инициализации платежа Mollie функция `build` передаёт `redirect_url`, абсолютный адрес, на который вернётся покупатель, и `locale`, язык страницы. Провайдер создаёт с ними платёж в Mollie и сохраняет адрес платёжной страницы Mollie в сессии как `checkout_url`. Язык без страны, например `de`, провайдер превращает в `de_DE` по правилам Mollie, а для языка, которого у Mollie нет, оставляет выбор браузеру покупателя.

`redirect_url` ведёт на API-роут `/api/payment-return` вашей витрины и используется для оплаченных, отменённых и неудачных платежей. API-роут находит корзину по её `cart_id`.

С `deferred: true` выбор Mollie и изменения корзины сессию не запускают, а `isReady` держит кнопку оплаты неактивной, пока в корзине нет email, адреса доставки и способа доставки. Провайдер создаёт платёж в Mollie сразу при старте сессии, с итогом корзины и адресами покупателя. Сумму этого платежа Mollie не меняет и открытым его не отменяет, поэтому сессия, запущенная при выборе способа и потом заменённая, оставила бы после себя оплачиваемую страницу Mollie.

## Шаг 3: Запустите платёжную сессию с кнопки оплаты

Оформление заказа в стартере запускает платёжную сессию, когда покупатель выбирает способ, когда меняется корзина и когда сессия пропадает. Для Mollie её вместо этого запускает кнопка оплаты.

Откройте [`src/modules/checkout/components/checkout-payment-section/index.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/modules/checkout/components/checkout-payment-section/index.tsx#L49-L121) и пропустите отложенный способ в этих трёх местах:

```tsx title="src/modules/checkout/components/checkout-payment-section/index.tsx"
import {

  useEffect(() => {
    if (
      selectedPaymentMethod &&
      !latestSession &&
      !paidByGiftcard &&
      !isPaymentSessionDeferred(selectedPaymentMethod) &&
      isPaymentSessionReady(selectedPaymentMethod, cart)
      // ...

// ...

    if (
      !selectedPaymentMethod ||

    }

// ...

  const handleSelectPayment = async (providerId: string) => {
```

Эффект, который перезапускает пропавшую сессию, эффект, который запускает её заново при смене адресов, email, доставки или региона, и обработчик выбора способа теперь не трогают отложенный способ. Оформление заказа по-прежнему показывает Mollie выбранным, а когда создать платёж, решает кнопка оплаты.

## Шаг 4: Создайте кнопку оплаты

Для каждого платёжного провайдера витрине нужен свой компонент кнопки оплаты. По данным платёжной сессии он отправляет покупателя на платёжную страницу Mollie. Сам заказ создаётся позже, когда покупатель вернётся через `/api/payment-return`, или раньше по вебхуку, если тот придёт первым.

Создайте файл [`src/modules/checkout/components/payment-button/providers/mollie.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/modules/checkout/components/payment-button/providers/mollie.tsx) и добавьте следующий код:

![Структура каталогов витрины Medusa после создания файла кнопки оплаты Mollie](/static/mollie/storefront/src-modules-checkout-components-payment-button-providers-mollie.webp)

```tsx title="src/modules/checkout/components/payment-button/providers/mollie.tsx"
"use client"

import { buildPaymentSessionData } from "@lib/constants"
import { initiatePaymentSession } from "@lib/data/cart"
import type { HttpTypes } from "@medusajs/types"
import { useTranslations } from "next-intl"
import { useState } from "react"
import { PaymentButtonShell, type PaymentProviderButtonProps } from "../shared"

const MOLLIE_PROVIDER_ID = "pp_mollie_mollie"

const findSession = (payment_collection?: HttpTypes.StorePaymentCollection | null) =>
  payment_collection?.payment_sessions?.find((s) =>
    s.provider_id.startsWith("pp_mollie_")
  )

/**
 * The address of the payment page of a session started earlier, unless it is
 * missing or Mollie has let the payment expire. A customer who went back from
 * Mollie's page without paying returns to the same page this way, instead of a
 * second payment Mollie would refuse to cancel. A card payment expires after
 * 30 minutes.
 */
const liveCheckoutUrl = (session?: HttpTypes.StorePaymentSession) => {
  const url = session?.data?.checkout_url
  const expiresAt = session?.data?.expires_at

  if (typeof url !== "string" || !url) {
    return null
  }

  if (typeof expiresAt === "string" && Date.parse(expiresAt) <= Date.now()) {
    return null
  }

  return url
}

/**
 * Mollie collects the payment on its own page. This button starts the payment
 * session, which creates the Mollie payment, and sends the customer to its
 * page; the order is placed once they come back through `/api/payment-return`,
 * or by the webhook if that arrives first. A session started before, whose
 * payment is still open, is reused.
 */
const MolliePaymentButton = ({
  cart,
  notReady,
  label,
  cartUpdating,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) => {
  const t = useTranslations("Errors")
  const [submitting, setSubmitting] = useState(false)
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  const handlePayment = async () => {
    setSubmitting(true)
    setErrorMessage(null)

    try {
      const session = findSession(cart.payment_collection)
      let url = liveCheckoutUrl(session)

      if (!url) {
        const providerId = session?.provider_id ?? MOLLIE_PROVIDER_ID
        const { payment_collection } = await initiatePaymentSession(cart, {
          provider_id: providerId,
          data: buildPaymentSessionData(providerId, cart),
        })

        url = liveCheckoutUrl(findSession(payment_collection))
      }

      if (!url) {
        throw new Error(t("paymentFailed"))
      }

      window.location.assign(url)
    } catch (error) {
      setErrorMessage(error instanceof Error ? error.message : t("paymentFailed"))
      setSubmitting(false)
    }
  }

  return (
    <PaymentButtonShell
      label={label}
      onClick={handlePayment}
      disabled={notReady || cartUpdating}
      loading={submitting}
      errorMessage={errorMessage}
      errorTestId="mollie-payment-error-message"
      data-testid={dataTestId ?? "submit-order-button"}
    />
  )
}

export default MolliePaymentButton
```

Когда покупатель нажимает кнопку оплаты, компонент запускает платёжную сессию с данными из `buildPaymentSessionData`, читает `data.checkout_url` новой сессии Mollie и отправляет покупателя по этому адресу платить на странице Mollie.

У покупателя, который вернулся со страницы Mollie, не заплатив, уже есть сессия с открытым платежом. Кнопка отправляет его на ту же страницу, если срок `data.expires_at` не прошёл (карточный платёж истекает через 30 минут), и только иначе запускает новую сессию. Второй открытый платёж для той же корзины и предотвращает отложенная сессия, потому что первый Mollie отменить не даёт. Если адрес не пришёл, кнопка показывает сообщение об ошибке вместо перехода.

## Шаг 6: Обработайте возврат с оплаты

После оплаты, отмены или неудачи на странице Mollie покупатель возвращается на витрину. О статусе платежа Mollie сообщает и этим перенаправлением, и вебхуком, поэтому общий API-роут проверяет, нет ли у корзины заказа, прежде чем создать его сам.

Откройте [`src/app/api/payment-return/route.ts`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/app/api/payment-return/route.ts#L15-L80) и добавьте следующий код:

![Структура каталогов витрины Medusa после изменения файла API-роута](/static/mollie/storefront/src-app-api-payment-return-route.webp)

```ts title="src/app/api/payment-return/route.ts"
type ReturnContext = {
  cartId: string
  locale: string
  origin: string
}

/**
 * Comes back from a provider that takes the customer to its own payment page
 * and returns them with nothing but the cart id, as Mollie and YooKassa do.
 *
 * The provider's webhook and this redirect race each other, and whichever
 * arrives first places the order, so the cart is checked for an order before
 * one is placed.
 */
async function redirectProviderReturn({
  cartId,
  locale,
  origin,
}: ReturnContext) {
  const cart = await sdk.client
    .fetch<HttpTypes.StoreCartResponse>(`/store/carts/${cartId}`, {
      method: "GET",
      query: { fields: "id,order_link.order_id" },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    })
    .then(({ cart }) => cart)
    .catch(() => null)

  if (!cart) {
    return NextResponse.redirect(
      `${origin}/${locale}/cart?error=payment_failed`
    )
  }

  const orderId = (cart as unknown as { order_link?: { order_id?: string } })
    .order_link?.order_id

  if (orderId) {
    const orderCacheTag = await getCacheTag("orders")
    revalidateTag(orderCacheTag)
    await removeCartId()

    return NextResponse.redirect(
      `${origin}/${locale}/order/${orderId}/confirmed`
    )
  }

  // The customer backed out or the payment was declined, so they land back on
  // the checkout with their cart intact and can pick a method again.
  await setCartId(cartId)

  try {
    await placeOrder(cartId)
  } catch (error) {
    unstable_rethrow(error)

    return NextResponse.redirect(
      `${origin}/${locale}/checkout?error=payment_failed`
    )
  }

  return NextResponse.redirect(
    `${origin}/${locale}/checkout?error=payment_failed`
  )
}
```

Затем в функции `GET` направьте возврат из Mollie в `redirectProviderReturn`:

```ts title="src/app/api/payment-return/route.ts"
  if (provider === "mollie") {
    return redirectProviderReturn({ cartId, locale, origin })
  }
```

Этот API-роут обрабатывает возврат из Mollie после попытки оплаты. Он всегда получает актуальное состояние корзины без кэша, чтобы не пропустить изменения, внесённые во время оплаты.

Если у корзины уже есть заказ, значит подтверждение уже пришло по вебхуку. API-роут обновляет кэш заказа, удаляет cookie корзины и отправляет покупателя на страницу подтверждения.

Иначе API-роут пытается создать заказ сам. При успехе покупатель попадает на страницу подтверждения заказа. Если покупатель отменил оплату на странице Mollie или платёж не прошёл, заказ не создаётся, и покупатель возвращается к оформлению заказа с `error=payment_failed`, чтобы выбрать способ оплаты заново.

## Шаг 7: Покажите карту на странице заказа

При оплате картой провайдер сохраняет последние четыре цифры карты в данных платежа как `card_last4`, так же, как провайдеры Stripe и Authorize.net от Gorgo. Страница заказа стартера показывает их только для Stripe.

Откройте [`src/modules/order/components/payment-details/index.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-mollie/apps/storefront/src/modules/order/components/payment-details/index.tsx#L27-L33) и измените условие:

![Структура каталогов витрины Medusa после изменения файла с данными оплаты](/static/mollie/storefront/src-modules-order-components-payment-details-index.webp)

```tsx title="src/modules/order/components/payment-details/index.tsx"
  const { title, subtitle } = paymentMethodLabel(tm, payment.provider_id)
  const card =
    (isStripeLike(payment.provider_id) || isMollie(payment.provider_id)) &&
    payment.data?.card_last4
  // The card the order was actually paid with says more than the schemes the
  // method accepts, so it takes the subtitle when the payment carries one.
  const methodSubtitle = card ? `•••• ${card}` : subtitle
```

Теперь при оплате картой страница заказа показывает под Mollie `•••• 1234`. Для iDEAL, PayPal и других способов остаётся подзаголовок из локали.
