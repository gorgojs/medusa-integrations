# {frontmatter.title}

На этой странице собраны обработчики для частых задач обмена с 1С. Код примеров взят из тестов плагина, где каждый из них проверяется на настоящем обмене. Входные данные и результат каждого хука описаны на странице [Справочник хуков](/medusa-integrations/1c-enterprise/hooks/reference).

<Note type="default" title="">

Каждый пример регистрирует свой обработчик, а Medusa разрешает только один обработчик на хук. Чтобы применить несколько примеров к одному хуку, объедините их, как показано в разделе [Несколько правок в одном обработчике](#несколько-правок-в-одном-обработчике).

</Note>

## Не импортировать услуги

В 1С услуги ведутся в той же номенклатуре, что и товары, но магазину они не нужны, потому что у них нет ни остатков, ни карточки товара. Обработчик убирает из порции товары, у которых реквизит «ВидНоменклатуры» равен «Услуга». Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"
import { readRequisite } from "@gorgo-store/medusa-erp-1c/hooks"

importOnecProductsWorkflow.hooks.setProducts(async ({ products }) => {
  return new StepResponse({
    products: products.filter(({ source }) => readRequisite(source, "ВидНоменклатуры") !== "Услуга"),
  })
})
```

Услуга, убранная из порции, не создаётся в Medusa. Если она попала в магазин раньше, обработчик её не удалит, потому что импорт вообще не трогает убранные товары.

## Реквизиты и свойства в поля товара

Полное наименование, вес и материал 1С хранит в реквизитах и свойствах товара, а у товара Medusa для них есть поля `subtitle`, `weight` и `material`. Обмен эти поля не заполняет, поэтому значения переносит обработчик. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"
import { readProperty, readRequisite } from "@gorgo-store/medusa-erp-1c/hooks"

importOnecProductsWorkflow.hooks.setProducts(async ({ products, properties }) => {
  return new StepResponse({
    products: products.map(({ source, existing, product }) => {
      const fullName = readRequisite(source, "Полное наименование")
      const weight = Number.parseFloat((readRequisite(source, "Вес") ?? "").replace(",", "."))
      const [material] = readProperty(source, properties, "Материал")

      return {
        source,
        existing,
        product: {
          ...product,
          ...(fullName ? { subtitle: fullName } : {}),
          ...(Number.isFinite(weight) ? { weight } : {}),
          ...(material ? { material } : {}),
        },
      }
    }),
  })
})
```

Обработчик добавляет поле в товар, только если 1С прислала значение. Ключ со значением `undefined` импорт счёл бы изменившимся и стёр бы значение, заданное в Medusa Admin. 1С может прислать вес с десятичной запятой, поэтому перед разбором обработчик заменяет её точкой.

## Черновик без изображений

Товар без единого изображения выглядит на витрине пустой карточкой. Обработчик оставляет такой товар черновиком, пока не появится изображение. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

importOnecProductsWorkflow.hooks.setProducts(async ({ products }) => {
  return new StepResponse({
    products: products.map((item) => {
      const images = item.product.images ?? item.existing?.images ?? []

      return images.length ? item : { ...item, product: { ...item.product, status: "draft" } }
    }),
  })
})
```

Обмен публикует товар при каждом импорте, поэтому товар опубликуется сам, как только 1С пришлёт для него изображение. Обратная сторона в том, что товар без изображений, опубликованный вручную, следующий обмен снова переведёт в черновик.

## Черновик для скрытых от сайта товаров

Обмен публикует каждый товар из выгрузки. Если в вашей базе 1С часть номенклатуры скрыта от сайта свойством, например «Удалить с сайта», без обработчика первая же выгрузка выставит эти товары на витрину. Обработчик оставляет такие товары черновиками. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"
import { readProperty } from "@gorgo-store/medusa-erp-1c/hooks"

const HIDDEN_ON_SITE_PROPERTY = "Удалить с сайта"
const YES_VALUES = new Set(["true", "да"])

importOnecProductsWorkflow.hooks.setProducts(async ({ products, properties }) => {
  return new StepResponse({
    products: products.map((item) => {
      const hidden = readProperty(item.source, properties, HIDDEN_ON_SITE_PROPERTY).some((value) =>
        YES_VALUES.has(value.trim().toLowerCase()),
      )

      return hidden ? { ...item, product: { ...item.product, status: "draft" } } : item
    }),
  })
})
```

В типовой конфигурации 1С свойства «Удалить с сайта» нет, его заводят в конкретной базе, поэтому подставьте название своего свойства. Булево свойство 1С присылает значением `true`, а свойство со справочником значением из справочника, поэтому обработчик принимает и `true`, и «Да». Когда свойство в 1С снимут, следующий обмен снова опубликует товар.

## Не перезаписывать правки из Medusa Admin

Название и описание товара часто редактируют в Medusa Admin, а следующий обмен вернул бы значения из 1С. Обработчик удаляет эти ключи у существующих товаров, и импорт оставляет поля без изменений. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

importOnecProductsWorkflow.hooks.setProducts(async ({ products }) => {
  return new StepResponse({
    products: products.map((item) => {
      if (!item.existing) {
        return item
      }

      const { title: _title, description: _description, ...product } = item.product

      return { ...item, product }
    }),
  })
})
```

Новый товар получает название и описание из 1С, потому что без названия товар создать нельзя. После этого изменения названия и описания в 1С до магазина не доходят.

## Бренд в коллекцию

1С хранит бренд товара в свойстве «Бренд», а в Medusa бренды удобно вести коллекциями. Обработчик ищет коллекции с названиями брендов из порции и привязывает товар к найденной. Обработчик делает один запрос к базе на порцию.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { ContainerRegistrationKeys } from "@medusajs/framework/utils"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"
import { readProperty } from "@gorgo-store/medusa-erp-1c/hooks"

importOnecProductsWorkflow.hooks.setProducts(async ({ products, properties }, { container }) => {
  const brandByOnecId = new Map(products.map(({ source }) => [source.id, readProperty(source, properties, "Бренд")[0]]))
  const titles = [...new Set([...brandByOnecId.values()].filter((title): title is string => Boolean(title)))]

  if (!titles.length) {
    return new StepResponse({ products })
  }

  const query = container.resolve(ContainerRegistrationKeys.QUERY)
  const { data: collections } = await query.graph({
    entity: "product_collection",
    fields: ["id", "title"],
    filters: { title: titles },
  })
  const collectionIdByTitle = new Map(collections.map((collection) => [collection.title, collection.id]))

  return new StepResponse({
    products: products.map((item) => {
      const collectionId = collectionIdByTitle.get(brandByOnecId.get(item.source.id) ?? "")

      return collectionId ? { ...item, product: { ...item.product, collection_id: collectionId } } : item
    }),
  })
})
```

Обработчик только ищет коллекции, а создаёте их вы в Medusa Admin. Товар, для бренда которого коллекции нет, остаётся без изменений. Создавать коллекции можно и из обработчика, но тогда ему нужна функция отката, как описано в [правилах для обработчиков](/medusa-integrations/1c-enterprise/hooks#как-хук-влияет-на-скорость-обмена).

## Название варианта из опций

Вариант получает название предложения из 1С, например «Футболка (Красный, M)». Обработчик называет вариант значениями его опций, «Красный / M». Вариант без опций сохраняет название из 1С. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-variants.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecVariantsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

importOnecVariantsWorkflow.hooks.setVariants(async ({ products }) => {
  return new StepResponse({
    products: products.map((item) => ({
      ...item,
      variants: item.variants.map((variant) => {
        const values = Object.values(variant.options ?? {})

        return values.length ? { ...variant, title: values.join(" / ") } : variant
      }),
    })),
  })
})
```

Значения идут в том порядке, в котором 1С перечислила свойства предложения. Обработчик возвращает каждый вариант товара, поэтому Medusa ни один из них не удалит.

## Свой SKU при занятом артикуле

В 1С у характеристик часто общий артикул номенклатуры, а SKU в Medusa уникален. Плагин записывает артикул в SKU только одному варианту, а остальные сохраняет без SKU. Обработчик даёт такому варианту SKU из артикула и начала `Ид` характеристики, например `ART-1-7a1f86c0`. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-variants.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecVariantsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

importOnecVariantsWorkflow.hooks.setVariants(async ({ products }) => {
  return new StepResponse({
    products: products.map((item) => ({
      ...item,
      variants: item.variants.map((variant) => {
        const { id, article } = (variant.metadata?.onec ?? {}) as { id?: string; article?: string }

        return variant.sku || !article || !id ? variant : { ...variant, sku: `${article}-${id.slice(0, 8)}` }
      }),
    })),
  })
})
```

Артикул и `Ид` характеристики плагин хранит в `metadata.onec` варианта, поэтому разбирать предложение обработчику не нужно. Уникальность нового SKU обеспечивает обработчик. Если такой SKU уже есть у другого варианта, обмен остановится с ошибкой.

## Оптовая цена для группы покупателей

Тип цен «Оптовая цена» должен действовать только для покупателей из группы «Опт». Обработчик включает прайс-лист этого типа цен и добавляет ему правило по группе, поэтому гость по-прежнему видит розничную цену. Прайс-лист получает тип `override`, чтобы покупатель из группы платил ровно цену из 1С, а не меньшую из оптовой и розничной. Обработчик делает один запрос к базе на порцию и только если в порции есть этот тип цен.

```ts title="src/workflows/hooks/onec-prices.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { ContainerRegistrationKeys, PriceListStatus, PriceListType } from "@medusajs/framework/utils"
import { importOnecPricesWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

const WHOLESALE_PRICE_TYPE_NAME = "Оптовая цена"
const WHOLESALE_GROUP_NAME = "Опт"

importOnecPricesWorkflow.hooks.setPriceLists(async ({ priceLists }, { container }) => {
  if (!priceLists.some(({ source }) => source.name === WHOLESALE_PRICE_TYPE_NAME)) {
    return new StepResponse({ priceLists })
  }

  const query = container.resolve(ContainerRegistrationKeys.QUERY)
  const { data: groups } = await query.graph({
    entity: "customer_group",
    fields: ["id"],
    filters: { name: WHOLESALE_GROUP_NAME },
  })
  const groupId = groups[0]?.id

  if (!groupId) {
    return new StepResponse({ priceLists })
  }

  return new StepResponse({
    priceLists: priceLists.map((item) =>
      item.source.name === WHOLESALE_PRICE_TYPE_NAME
        ? {
            ...item,
            priceList: {
              ...item.priceList,
              status: PriceListStatus.ACTIVE,
              type: PriceListType.OVERRIDE,
              rules: { "customer.groups.id": [groupId] },
            },
          }
        : item,
    ),
  })
})
```

Создайте группу «Опт» в Medusa Admin заранее. Без неё прайс-лист останется черновиком, как и без обработчика. Обработчик задаёт статус, тип и правила этого прайс-листа при каждом обмене, поэтому следующий обмен отменит их изменения, сделанные в Medusa Admin.

## Не выгружать тестовые заказы

Заказы, которые команда оформляет для проверки витрины, не должны попадать в 1С. Обработчик убирает из выгрузки заказы с адресов в домене `@test.invalid`. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-orders.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { exportOnecOrdersWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

exportOnecOrdersWorkflow.hooks.setOrders(async ({ orders }) => {
  return new StepResponse({
    orders: orders.filter(({ source }) => !source.email?.endsWith("@test.invalid")),
  })
})
```

Убранный заказ не получает отметку о выгрузке. Поэтому он попадает в хук при каждой выгрузке, и обработчик каждый раз убирает его снова.

## Источник заказа и комментарий покупателя

Менеджеру в 1С полезно видеть, откуда пришёл заказ и что написал покупатель. Отдельного поля для комментария у заказа Medusa нет, поэтому витрина записывает его в `metadata.comment`. Обработчик переносит комментарий в документ и добавляет реквизит «Источник». Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-orders.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { exportOnecOrdersWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

exportOnecOrdersWorkflow.hooks.setOrders(async ({ orders }) => {
  return new StepResponse({
    orders: orders.map(({ source, document }) => {
      const comment = source.metadata?.comment

      return {
        source,
        document: {
          ...document,
          ...(typeof comment === "string" && comment ? { comment } : {}),
          requisites: [...document.requisites, { name: "Источник", value: "Интернет-магазин" }],
        },
      }
    }),
  })
})
```

Сохранять комментарий в `metadata.comment` заказа должна ваша витрина. Реквизит «Источник» попадёт в документ, а как его обработает 1С, зависит от вашей конфигурации.

## Контрагент-юрлицо и способ доставки

Покупатель из группы «Юрлица» должен попасть в 1С контрагентом с ИНН и КПП, а менеджеру нужен способ доставки. ИНН и КПП хранятся в `metadata` покупателя, способ доставки в заказе, и обработчик получает всё это одним запросом на всю выгрузку.

```ts title="src/workflows/hooks/onec-orders.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { ContainerRegistrationKeys } from "@medusajs/framework/utils"
import { exportOnecOrdersWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

const COMPANY_GROUP_NAME = "Юрлица"

exportOnecOrdersWorkflow.hooks.setOrders(async ({ orders }, { container }) => {
  if (!orders.length) {
    return new StepResponse({ orders })
  }

  const query = container.resolve(ContainerRegistrationKeys.QUERY)
  const { data } = await query.graph({
    entity: "order",
    fields: ["id", "customer.metadata", "customer.groups.name", "shipping_methods.name"],
    filters: { id: orders.map(({ source }) => source.id) },
  })
  const extraById = new Map(data.map((order) => [order.id, order]))

  return new StepResponse({
    orders: orders.map(({ source, document }) => {
      const extra = extraById.get(source.id)
      const isCompany = extra?.customer?.groups?.some((group: { name?: string } | null) => group?.name === COMPANY_GROUP_NAME)
      const { inn, kpp } = (extra?.customer?.metadata ?? {}) as { inn?: string; kpp?: string }
      const delivery = extra?.shipping_methods?.[0]?.name

      return {
        source,
        document: {
          ...document,
          counterparties: document.counterparties.map((counterparty) =>
            isCompany && inn ? { ...counterparty, inn, ...(kpp ? { kpp } : {}) } : counterparty,
          ),
          requisites: delivery
            ? [...document.requisites, { name: "Способ доставки", value: delivery }]
            : document.requisites,
        },
      }
    }),
  })
})
```

Запрос проходит через связь заказа с покупателем, поэтому в базе он превращается в три SQL-запроса, но на всю выгрузку, а не на каждый заказ. Плагин записывает ИНН и КПП после имени контрагента и перед адресом. На реальной конфигурации 1С такое расположение ещё не проверялось, поэтому убедитесь, что ваша конфигурация читает их оттуда.

## Версия схемы для старой конфигурации 1С

Плагин указывает в корне файла `ВерсияСхемы="2.10"`, а старая конфигурация 1С может ожидать другую версию, например 2.05. В модели товара и документа версии схемы нет, поэтому обработчик правит готовый XML через `setPayload` и в выгрузке каталога, и в выгрузке заказов. Обработчик не обращается к базе.

```ts title="src/workflows/hooks/onec-payload.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { exportOnecCatalogWorkflow, exportOnecOrdersWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"

const OLD_SCHEMA_VERSION = "2.05"

function withSchemaVersion(payload: string): string {
  return payload.replace(/ВерсияСхемы="[^"]*"/, `ВерсияСхемы="${OLD_SCHEMA_VERSION}"`)
}

exportOnecCatalogWorkflow.hooks.setPayload(async ({ payload }) => {
  return new StepResponse({ payload: withSchemaVersion(payload) })
})

exportOnecOrdersWorkflow.hooks.setPayload(async ({ payload }) => {
  return new StepResponse({ payload: withSchemaVersion(payload) })
})
```

Обработчик меняет только номер версии, а структура файла остаётся той, которую формирует плагин. Если ваша конфигурация ожидает и другую структуру, правьте XML в том же обработчике. Замена в строке ничего не знает о структуре XML, поэтому всё, что можно выразить через `setOrders`, надёжнее делать там.

## Несколько правок в одном обработчике

Medusa разрешает только один обработчик на хук, поэтому все правки проекта для одного хука нужно собрать в одном обработчике. Удобно оформить каждую правку отдельной функцией и вызывать их по очереди. Фильтрацию ставьте первой, чтобы остальные правки не тратили время на убранные элементы.

```ts title="src/workflows/hooks/onec-catalog.ts"
import { StepResponse } from "@medusajs/framework/workflows-sdk"
import { importOnecProductsWorkflow } from "@gorgo-store/medusa-erp-1c/workflows"
import { readRequisite, type ProductToImport } from "@gorgo-store/medusa-erp-1c/hooks"

function skipServices(products: ProductToImport[]): ProductToImport[] {
  return products.filter(({ source }) => readRequisite(source, "ВидНоменклатуры") !== "Услуга")
}

function keepManagerEdits(products: ProductToImport[]): ProductToImport[] {
  return products.map((item) => {
    if (!item.existing) {
      return item
    }

    const { title: _title, description: _description, ...product } = item.product

    return { ...item, product }
  })
}

importOnecProductsWorkflow.hooks.setProducts(async ({ products }) => {
  return new StepResponse({ products: keepManagerEdits(skipServices(products)) })
})
```

Функции, которым нужен доступ к базе, делайте асинхронными и вызывайте через `await`. Так каждая из них по-прежнему делает один запрос на порцию.
