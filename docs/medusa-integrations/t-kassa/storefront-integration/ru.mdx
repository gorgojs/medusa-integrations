# {frontmatter.title}

Для интеграции платёжного провайдера Т-Касса от Т-Банка в storefront [Medusa DTC Starter от Gorgo](https://github.com/gorgojs/medusa-dtc-starter) начните с добавления необходимых UI-компонентов. Таким образом провайдер будет отображаться на странице оформления заказа наряду с другими доступными методами оплаты.

Когда покупатель выбирает Т-Касса, оформление заказа инициализирует платёжную сессию, а провайдер создаёт её на стороне Т-Касса и возвращает адрес для оплаты. Кнопка оплаты отправляет покупателя на эту страницу, где он сможет выбрать предпочтительный способ оплаты.

После завершения оплаты Т-Касса одновременно отправляет вебхук и перенаправляет покупателя обратно в витрину. То событие, которое придёт первым, завершит корзину и создаст новый заказ в Medusa.

Для витрины на Next.js необходимо внести следующие изменения:

## Шаг 1: Настройте платёжный провайдер

Чтобы сделать Т-Касса доступным в качестве способа оплаты на странице оформления заказа витрины магазина, необходимо добавить её конфигурацию в маппинг платёжных провайдеров в файле с константами вашей витрины. Этот маппинг определяет, как каждый провайдер отображается в интерфейсе.

Откройте [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-tkassa/apps/storefront/src/lib/constants.tsx#L56-L60) и добавьте следующий код:

![Структура проекта Medusa Storefront после обновления файла с константами](/static/tkassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
export type PaymentInfo = {
  title: string
  subtitle?: string
  icon: React.JSX.Element
}

export const paymentInfoMap: Record<string, PaymentInfo> = {
```

Вы расширяете объект `paymentInfoMap`, добавляя в него запись `pp_tkassa_tkassa`. Эта запись определяет заголовок, подпись и иконку, которые будут отображаться для Т-Касса на странице оформления заказа, а также служит резервным значением, когда для локали нет перевода.

Вспомогательная функция `isTkassa` проверяет, принадлежит ли переданный `providerId` к Т-Касса. Она используется диспетчером ниже и функцией сборки данных платёжной сессии из следующего шага.

## Шаг 2: Инициализируйте платёжную сессию

Чтобы перенаправить покупателя в Т-Касса, платёжная сессия должна быть корректно инициализирована с необходимыми параметрами, включая адрес возврата после оплаты и корзину для формирования онлайн-чеков.

Откройте тот же файл [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-tkassa/apps/storefront/src/lib/constants.tsx#L76-L108) и добавьте адрес возврата и функцию сборки данных сессии:

![Структура проекта Medusa Storefront после обновления файла с константами](/static/tkassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
/**
 * Адрес, на который покупатель возвращается после оплаты на стороне провайдера.
 * `<html lang>` хранит локаль, в которой отображалось оформление заказа, поэтому
 * покупатель возвращается на том языке, на котором ушёл из магазина.
 */
const paymentReturnUrl = (providerId: string, cartId: string) => {
  const origin =
    typeof window === "undefined" ? getBaseURL() : window.location.origin
  const locale =
    typeof document === "undefined"
      ? defaultLocale
      : document.documentElement.lang || defaultLocale

  return `${origin}/api/payment-return?provider=${providerId}&cart_id=${cartId}&locale=${locale}`
}

const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isTkassa(providerId),
    // Т-Касса формирует чек из корзины, а чеку нужны email и телефон
    // покупателя. Инициализация сессии до того, как оформление заказа собрало
    // эти данные, создаёт платёж без чека.
    isReady: (cart) => Boolean(cart.email && cart.shipping_address),
    build: (cart) => {
      const returnUrl = paymentReturnUrl("tkassa", cart.id)

      return {
        SuccessURL: returnUrl,
        FailURL: returnUrl,
        cart,
      }
    },
  },
]
```

При инициализации платежа для Т-Касса `build` передаёт `SuccessURL` и `FailURL`, оба указывающие на один и тот же адрес возврата.

Оба адреса указывают на API-роут `/api/payment-return` вашей витрины и используются как для успешных, так и для неудачных попыток оплаты.

Объект `cart` включается в данные инициализации для формирования чека в соответствии с Федеральным законом № 54.

`isReady` удерживает сессию, пока в корзине не появятся email и адрес доставки, поскольку для чека нужны email и телефон покупателя.

## Шаг 3: Создайте кнопку оплаты

В витрине для каждого платёжного провайдера необходим отдельный компонент кнопки оплаты. Используя данные платёжной сессии, он перенаправляет покупателя на страницу оплаты Т-Касса. Сам заказ оформляется позже, когда покупатель вернётся через `/api/payment-return`, либо раньше по вебхуку, если тот придёт первым.

Создайте файл [`src/modules/checkout/components/payment-button/providers/tkassa.tsx`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-tkassa/apps/storefront/src/modules/checkout/components/payment-button/providers/tkassa.tsx) и добавьте следующий код:

![Структура проекта Medusa Storefront после создания файла для кнопки оплаты Т-Касса](/static/tkassa/storefront/src-modules-checkout-components-payment-button-providers-tkassa.webp)

```ts title="src/modules/checkout/components/payment-button/providers/tkassa.tsx"
"use client"

import type { HttpTypes } from "@medusajs/types"
import { useTranslations } from "next-intl"
import { useState } from "react"
import { PaymentButtonShell, type PaymentProviderButtonProps } from "../shared"

const paymentUrl = (cart: HttpTypes.StoreCart) => {
  const session = cart.payment_collection?.payment_sessions?.find((s) =>
    s.provider_id.startsWith("pp_tkassa")
  )

  return (session?.data as { PaymentURL?: string } | undefined)?.PaymentURL
}

/**
 * Т-Касса принимает оплату на собственной странице. Сессия, созданная оформлением
 * заказа, хранит адрес, куда отправить покупателя, а заказ оформляется, когда он
 * вернётся через `/api/payment-return`, либо по вебхуку, если тот придёт раньше.
 */
const TkassaPaymentButton = ({
  cart,
  notReady,
  label,
  cartUpdating,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) => {
  const t = useTranslations("Errors")
  const [submitting, setSubmitting] = useState(false)
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  const handlePayment = () => {
    const url = paymentUrl(cart)

    if (!url) {
      setErrorMessage(t("paymentFailed"))
      return
    }

    setSubmitting(true)
    window.location.assign(url)
  }

  return (
    <PaymentButtonShell
      label={label}
      onClick={handlePayment}
      disabled={notReady}
      loading={submitting || cartUpdating}
      errorMessage={errorMessage}
      errorTestId="tkassa-payment-error-message"
      data-testid={dataTestId ?? "submit-order-button"}
    />
  )
}

export default TkassaPaymentButton
```

Этот компонент находит `payment_session` Т-Касса в активной корзине и извлекает значение `data.PaymentURL`. Когда покупатель нажимает кнопку оплаты, он перенаправляется на этот URL для завершения оплаты на странице Т-Касса.

Если `PaymentURL` отсутствует, кнопка показывает сообщение об ошибке вместо перехода.

## Шаг 5: Обработайте возврат с оплаты

После того как покупатель завершает оплату на странице Т-Касса, он перенаправляется обратно на витрину магазина. Т-Касса сообщает статус платежа и через это перенаправление, и через вебхук, поэтому общий API-роут проверяет, есть ли у корзины заказ, прежде чем оформлять его самому.

Откройте [`src/app/api/payment-return/route.ts`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-tkassa/apps/storefront/src/app/api/payment-return/route.ts#L29-L80) со следующим содержимым:

![Структура проекта Medusa Storefront после создания файла для API route](/static/tkassa/storefront/src-app-api-payment-return-route.webp)

```ts title="src/app/api/payment-return/route.ts"
type ReturnContext = {
  cartId: string
  locale: string
  origin: string
}

/**
 * Обрабатывает возврат от провайдера, который принимает оплату на собственной
 * странице и возвращает покупателя только с идентификатором корзины — Т-Касса
 * в их числе.
 *
 * Вебхук провайдера и этот редирект соревнуются друг с другом, и какой из них
 * ни пришёл бы первым, он оформляет заказ, поэтому перед оформлением
 * проверяется, нет ли у корзины уже заказа.
 */
async function redirectProviderReturn({
  cartId,
  locale,
  origin,
}: ReturnContext) {
  const cart = await sdk.client
    .fetch<HttpTypes.StoreCartResponse>(`/store/carts/${cartId}`, {
      method: "GET",
      query: { fields: "id,order_link.order_id" },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    })
    .then(({ cart }) => cart)
    .catch(() => null)

  if (!cart) {
    return NextResponse.redirect(
      `${origin}/${locale}/cart?error=payment_failed`
    )
  }

  const orderId = (cart as unknown as { order_link?: { order_id?: string } })
    .order_link?.order_id

  if (orderId) {
    const orderCacheTag = await getCacheTag("orders")
    revalidateTag(orderCacheTag)
    await removeCartId()

    return NextResponse.redirect(
      `${origin}/${locale}/order/${orderId}/confirmed`
    )
  }

  // Покупатель отменил оплату, либо она была отклонена, поэтому он возвращается
  // на страницу оформления заказа с нетронутой корзиной и может выбрать способ
  // оплаты заново.
  await setCartId(cartId)

  try {
    await placeOrder(cartId)
  } catch (error) {
    unstable_rethrow(error)

    return NextResponse.redirect(
      `${origin}/${locale}/checkout?error=payment_failed`
    )
  }

  return NextResponse.redirect(
    `${origin}/${locale}/checkout?error=payment_failed`
  )
}
```

Затем в функции `GET` направьте возврат Т-Касса в `redirectProviderReturn`:

```ts title="src/app/api/payment-return/route.ts"
  if (provider === "tkassa") {
    return redirectProviderReturn({ cartId, locale, origin })
  }
```

Этот API-роут обрабатывает возврат от Т-Касса после попытки оплаты. Он всегда получает актуальное состояние корзины без кэша, чтобы не пропустить изменения, внесённые во время оплаты.

Если у корзины уже есть заказ, значит подтверждение уже пришло по вебхуку. API-роут обновляет кэш заказа, удаляет cookie корзины и отправляет покупателя на страницу подтверждения. Это гарантирует корректное завершение платёжного процесса и сохранение актуальных данных в витрине.

Иначе API-роут пытается оформить заказ сам. В случае успеха покупатель оказывается на странице подтверждения заказа. Если же возникает ошибка, покупатель возвращается на оформление заказа с `error=payment_failed` и может выбрать способ оплаты заново.

## Шаг 6: Добавьте подписи провайдера в локали витрины

Добавьте `pp_tkassa_tkassa` в [`messages/ru.json`](https://github.com/gorgojs/medusa-integrations/blob/5c7c2f15ccfb90f15d5d94abe7d303137550a421/examples/payment-tkassa/apps/storefront/messages/ru.json#L529) и в каждую другую локаль под `messages/`:

```json title="messages/ru.json"
{
  "PaymentMethods": {
    // ...
    "pp_tkassa_tkassa": {
      "title": "Т-Касса",
      "subtitle": "Карты, СБП"
    }
  }
}
```

Если для локали нет записи, используются английские `title` и `subtitle` из `paymentInfoMap` в [Шаге 1](#шаг-1-настройте-платёжный-провайдер).
