# {frontmatter.title}

To integrate the T-Kassa payment provider by T-Bank into the [Medusa DTC Starter by Gorgo](https://github.com/gorgojs/medusa-dtc-starter) storefront, start by adding the required UI components, so the provider is displayed on the checkout page alongside other available payment methods.

When the customer selects T-Kassa, the checkout initiates a payment session, and the provider creates it on T-Kassa's side and returns the payment address. The payment button then sends the customer there, where they can choose a payment method.

Once the payment is completed, T-Kassa concurrently sends a webhook and redirects the customer back to the storefront. Whichever event arrives first completes the cart and creates a new order in Medusa.

For the storefront on Next.js, you need to make the following changes:

## Step 1: Configure Payment Provider

To make T-Kassa available as a payment method on the storefront checkout page, you must add its configuration to the payment provider mapping in your storefront's constants file. This mapping determines how each payment provider is displayed in the UI.

Open [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-tkassa/apps/storefront/src/lib/constants.tsx#L56-L60) and add the following code:

![Directory structure in the Medusa Storefront after updating the file for constants](/static/tkassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
export type PaymentInfo = {
  title: string
  subtitle?: string
  icon: React.JSX.Element
}

export const paymentInfoMap: Record<string, PaymentInfo> = {
  // ...
  pp_tkassa_tkassa: {
    title: "T-Kassa",
    subtitle: "Cards, SBP",
    icon: <TKassa />,
  },
  // ...
}

// ...

export const isTkassa = (providerId?: string) => {
  return providerId?.startsWith("pp_tkassa")
}
```

You extend the `paymentInfoMap` object to include a `pp_tkassa_tkassa` entry. This entry defines the title, the subtitle, and the icon that will be shown for T-Kassa on the checkout page, and also serves as the fallback when a locale carries no translation.

The helper function `isTkassa` checks whether a given `providerId` belongs to T-Kassa. It's used by the dispatcher below and by the session data builder in the next step.

## Step 2: Initialize Payment Session

To redirect a customer to T-Kassa, the payment session must be properly initialized with the required parameters, including the return address for the post-payment callback and the shopping cart for generating receipts.

Open the same [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-tkassa/apps/storefront/src/lib/constants.tsx#L76-L108) and add the return address and the session data builder:

![Directory structure in the Medusa Storefront after updating the file for constants](/static/tkassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
/**
 * The address the customer comes back to after paying on the provider's own
 * page. `<html lang>` carries the locale the checkout was rendered in, so the
 * customer returns to the language they left the shop with.
 */
const paymentReturnUrl = (providerId: string, cartId: string) => {
  const origin =
    typeof window === "undefined" ? getBaseURL() : window.location.origin
  const locale =
    typeof document === "undefined"
      ? defaultLocale
      : document.documentElement.lang || defaultLocale

  return `${origin}/api/payment-return?provider=${providerId}&cart_id=${cartId}&locale=${locale}`
}

const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isTkassa(providerId),
    // T-Kassa builds a receipt out of the cart, and the receipt needs the
    // buyer's email and phone. Initiating the session before the checkout
    // collected them creates a payment without one.
    isReady: (cart) => Boolean(cart.email && cart.shipping_address),
    build: (cart) => {
      const returnUrl = paymentReturnUrl("tkassa", cart.id)

      return {
        SuccessURL: returnUrl,
        FailURL: returnUrl,
        cart,
      }
    },
  },
]
```

When initiating a payment for T-Kassa, `build` passes `SuccessURL` and `FailURL`, both pointing at the same return address.

Both addresses point to your storefront's `/api/payment-return` route and are used for both successful and failed payment attempts.

The `cart` object is included to build a receipt compliant with Federal Law No. 54. `isReady` holds the session back until the cart carries an email and a shipping address, since the receipt needs the buyer's email and phone.

## Step 3: Create Payment Button

The storefront needs a dedicated payment button component for each payment provider. Using the payment session data, it sends the customer to the T-Kassa payment page. The order itself is placed later, when the customer comes back through `/api/payment-return`, or earlier through the webhook if that arrives first.

Create [`src/modules/checkout/components/payment-button/providers/tkassa.tsx`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-tkassa/apps/storefront/src/modules/checkout/components/payment-button/providers/tkassa.tsx) and add the following code:

![Directory structure in the Medusa Storefront after creating the file for the T-Kassa payment button](/static/tkassa/storefront/src-modules-checkout-components-payment-button-providers-tkassa.webp)

```ts title="src/modules/checkout/components/payment-button/providers/tkassa.tsx"
"use client"

import type { HttpTypes } from "@medusajs/types"
import { useTranslations } from "next-intl"
import { useState } from "react"
import { PaymentButtonShell, type PaymentProviderButtonProps } from "../shared"

const paymentUrl = (cart: HttpTypes.StoreCart) => {
  const session = cart.payment_collection?.payment_sessions?.find((s) =>
    s.provider_id.startsWith("pp_tkassa")
  )

  return (session?.data as { PaymentURL?: string } | undefined)?.PaymentURL
}

/**
 * T-Kassa collects the payment on its own page. The session the checkout
 * created carries the address to send the customer to, and the order is placed
 * once they come back through `/api/payment-return` — or by the webhook, if
 * that arrives first.
 */
const TkassaPaymentButton = ({
  cart,
  notReady,
  label,
  cartUpdating,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) => {
  const t = useTranslations("Errors")
  const [submitting, setSubmitting] = useState(false)
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  const handlePayment = () => {
    const url = paymentUrl(cart)

    if (!url) {
      setErrorMessage(t("paymentFailed"))
      return
    }

    setSubmitting(true)
    window.location.assign(url)
  }

  return (
    <PaymentButtonShell
      label={label}
      onClick={handlePayment}
      disabled={notReady}
      loading={submitting || cartUpdating}
      errorMessage={errorMessage}
      errorTestId="tkassa-payment-error-message"
      data-testid={dataTestId ?? "submit-order-button"}
    />
  )
}

export default TkassaPaymentButton
```

This component finds the T-Kassa `payment_session` in the active cart and extracts the value of `data.PaymentURL`. When the customer clicks the payment button, they're redirected to this URL to complete the payment on the T-Kassa page.

If the `PaymentURL` is missing, the button shows an error message instead of navigating anywhere.

## Step 5: Handle Payment Return

After the customer completes payment on the T-Kassa page, they're redirected back to the storefront. T-Kassa reports the payment status through both this redirect and a webhook, so the shared route checks the cart for an order before placing one itself.

Open [`src/app/api/payment-return/route.ts`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-tkassa/apps/storefront/src/app/api/payment-return/route.ts#L29-L80) with the following content:

![Directory structure in the Medusa Storefront after creating the file for API route](/static/tkassa/storefront/src-app-api-payment-return-route.webp)

```ts title="src/app/api/payment-return/route.ts"
type ReturnContext = {
  cartId: string
  locale: string
  origin: string
}

/**
 * Comes back from a provider that takes the customer to its own payment page
 * and returns them with nothing but the cart id — T-Kassa among them.
 *
 * The provider's webhook and this redirect race each other, and whichever
 * arrives first places the order, so the cart is checked for an order before
 * one is placed.
 */
async function redirectProviderReturn({
  cartId,
  locale,
  origin,
}: ReturnContext) {
  const cart = await sdk.client
    .fetch<HttpTypes.StoreCartResponse>(`/store/carts/${cartId}`, {
      method: "GET",
      query: { fields: "id,order_link.order_id" },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    })
    .then(({ cart }) => cart)
    .catch(() => null)

  if (!cart) {
    return NextResponse.redirect(
      `${origin}/${locale}/cart?error=payment_failed`
    )
  }

  const orderId = (cart as unknown as { order_link?: { order_id?: string } })
    .order_link?.order_id

  if (orderId) {
    const orderCacheTag = await getCacheTag("orders")
    revalidateTag(orderCacheTag)
    await removeCartId()

    return NextResponse.redirect(
      `${origin}/${locale}/order/${orderId}/confirmed`
    )
  }

  // The customer backed out or the payment was declined, so they land back on
  // the checkout with their cart intact and can pick a method again.
  await setCartId(cartId)

  try {
    await placeOrder(cartId)
  } catch (error) {
    unstable_rethrow(error)

    return NextResponse.redirect(
      `${origin}/${locale}/checkout?error=payment_failed`
    )
  }

  return NextResponse.redirect(
    `${origin}/${locale}/checkout?error=payment_failed`
  )
}
```

Then route T-Kassa's return to `redirectProviderReturn`, in `GET`:

```ts title="src/app/api/payment-return/route.ts"
  if (provider === "tkassa") {
    return redirectProviderReturn({ cartId, locale, origin })
  }
```

This route handles the return from T-Kassa after a payment attempt. It always fetches the cart's latest state, uncached, so it doesn't miss changes made during payment.

If the cart already has an order, the confirmation already arrived through the webhook. The route revalidates the order cache, removes the cart cookie, and sends the customer to the confirmation page. This ensures a consistent post-payment experience while keeping storefront data up to date.

Otherwise the route tries to place the order itself. If successful, the customer ends up on the order confirmation page. If an error happens, the customer is sent back to the checkout with `error=payment_failed` so they can pick a method again.

## Step 6: Add Provider Labels to Storefront Locales

Add `pp_tkassa_tkassa` to [`messages/en.json`](https://github.com/gorgojs/medusa-integrations/blob/5c7c2f15ccfb90f15d5d94abe7d303137550a421/examples/payment-tkassa/apps/storefront/messages/en.json#L529) and to every other locale under `messages/`:

```json title="messages/en.json"
{
  "PaymentMethods": {
    // ...
    "pp_tkassa_tkassa": {
      "title": "T-Kassa",
      "subtitle": "Cards, SBP"
    }
  }
}
```

A locale missing an entry falls back to the English `title` and `subtitle` from `paymentInfoMap` in [Step 1](#step-1-configure-payment-provider).
