# {frontmatter.title}

Для интеграции платёжного провайдера PayPal в storefront [Medusa DTC Starter от Gorgo](https://github.com/gorgojs/medusa-dtc-starter) начните с добавления необходимых UI-компонентов. Таким образом провайдер будет отображаться на странице оформления заказа наряду с другими доступными методами оплаты.

Когда покупатель нажимает кнопку PayPal на шаге оплаты или в ряду экспресс-оплаты, оформление заказа инициализирует платёжную сессию, а провайдер создаёт для неё заказ на стороне PayPal. Затем покупатель подтверждает оплату в окне PayPal.

После подтверждения оплаты витрина завершает корзину и создаёт новый заказ в Medusa. Если покупатель закрыл вкладку после того, как PayPal списал деньги, заказ создаст вебхук `PAYMENT.CAPTURE.COMPLETED`.

Для витрины на Next.js необходимо внести следующие изменения:

## Шаг 1: Установите JS SDK PayPal

Кнопки берутся из официальной React-обёртки JS SDK PayPal. Установите её в витрину:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn add @paypal/react-paypal-js@^8.9.2
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```bash
    npm install @paypal/react-paypal-js@^8.9.2
    ```
  </CodeTab>
</CodeTabs>

Версия 8 пакета `@paypal/react-paypal-js` загружает JavaScript SDK PayPal с `www.paypal.com/sdk/js` и даёт компонент `PayPalButtons`, колбэк `onShippingAddressChange` которого сообщает адрес, выбранный покупателем в окне PayPal.

## Шаг 2: Настройте платёжный провайдер

Чтобы сделать PayPal доступным в качестве способа оплаты на странице оформления заказа витрины магазина, необходимо добавить его конфигурацию в маппинг платёжных провайдеров в файле с константами вашей витрины. Этот маппинг определяет, как каждый провайдер отображается в интерфейсе.

Откройте [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/lib/constants.tsx#L45-L49) и добавьте следующий код:

![Структура проекта Medusa Storefront после обновления файла с константами](/static/paypal/storefront/src-lib-constants.webp)

```tsx title="src/lib/constants.tsx"
export const paymentInfoMap: Record<string, PaymentInfo> = {
  // ...
  pp_paypal_paypal: {
    title: "PayPal",
    subtitle: "Cards, wallet",
    icon: <PayPal />,
  },
  // ...
}

// ...

export const isPaypal = (providerId?: string) => {
  return providerId?.startsWith("pp_paypal")
}
```

Вы расширяете объект `paymentInfoMap`, добавляя в него запись `pp_paypal_paypal`. Эта запись определяет заголовок, подпись и иконку, которые будут отображаться для PayPal на странице оформления заказа, а также служит резервным значением, когда для локали нет перевода. Иконка `PayPal` входит в стартер и находится в `src/modules/common/icons/paypal.tsx`.

Вспомогательная функция `isPaypal` проверяет, принадлежит ли переданный `providerId` к PayPal. Она используется диспетчером ниже и функцией сборки данных платёжной сессии из следующего шага.

## Шаг 3: Инициализируйте платёжную сессию

Чтобы создать заказ PayPal, платёжная сессия должна быть корректно инициализирована с необходимыми параметрами, включая адрес доставки и данные покупателя для формы оплаты картой PayPal.

Откройте тот же файл [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/lib/constants.tsx#L63-L86) и добавьте функцию сборки данных сессии:

![Структура проекта Medusa Storefront после обновления файла с константами](/static/paypal/storefront/src-lib-constants.webp)

```tsx title="src/lib/constants.tsx"
const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isPaypal(providerId),
    // The PayPal order carries the cart's total and the delivery address, so the
    // session starts once the checkout has an email, an address and a shipping
    // method. Earlier, PayPal gets an order for a cart that has none of them.
    isReady: (cart) =>
      Boolean(
        cart.email &&
          cart.shipping_address?.address_1 &&
          (cart.shipping_methods?.length ?? 0) > 0
      ),
    // The email, the name and the billing address fill in PayPal's card form.
    build: (cart) => ({
      shipping_address: cart.shipping_address,
      billing_address: cart.billing_address,
      email: cart.email,
    }),
  },
]
```

При инициализации платежа для PayPal `build` передаёт адрес доставки, billing-адрес и email. Провайдер ставит адрес доставки в заказ PayPal, а email, имя и billing-адрес заполняют форму PayPal, когда покупатель платит картой.

`isReady` удерживает сессию, пока в корзине не появятся email, адрес доставки и способ доставки, поскольку заказу PayPal нужны итог корзины и адрес доставки. Кнопка оплаты читает тот же `isReady`, поэтому кнопка PayPal на шаге оплаты остаётся неактивной до этого момента.

## Шаг 4: Загрузите настройки PayPal и данные покупателя

Витрина получает от бэкенда два вида данных. Чтобы показать кнопки PayPal, она загружает публичные настройки PayPal для SDK. После экспресс-оплаты она получает контакты и адрес доставки, которые покупатель выбрал в PayPal, и заполняет ими корзину.

Создайте файл [`src/lib/data/paypal.ts`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/lib/data/paypal.ts) и добавьте следующий код:

![Структура проекта Medusa Storefront после создания файла с загрузчиками данных PayPal](/static/paypal/storefront/src-lib-data-paypal.webp)

```ts title="src/lib/data/paypal.ts"
"use server"

import { sdk } from "@lib/config"
import { getAuthHeaders, getCartId } from "./cookies"

/** What the storefront needs to load the PayPal JS SDK, from `GET /store/paypal/config`. */
export type PayPalConfig = {
  provider_id: string
  client_id: string
  environment: "sandbox" | "live"
  intent: "capture" | "authorize"
}

/** The buyer of an approved PayPal order, from `GET /store/paypal/orders/:id/payer`. */
export type PayPalPayer = {
  amount: { currency_code: string; value: string } | null
  email: string | null
  phone: string | null
  shipping_address: {
    first_name: string | null
    last_name: string | null
    address_1: string | null
    address_2: string | null
    city: string | null
    province: string | null
    postal_code: string | null
    country_code: string | null
    phone: string | null
  } | null
}

/**
 * The public PayPal settings of the only PayPal integration, or null while it is
 * not configured. The client ID and the intent change only in the Admin, so the
 * answer is cached for a minute.
 */
export async function getPayPalConfig(): Promise<PayPalConfig | null> {
  return sdk.client
    .fetch<{ config: PayPalConfig }>("/store/paypal/config", {
      method: "GET",
      next: { revalidate: 60 },
    })
    .then(({ config }) => config)
    .catch(() => null)
}

/**
 * The contact and the shipping address the buyer chose in PayPal, and the amount
 * they approved. The backend answers only for an order created for this cart.
 */
export async function getPayPalPayer(orderId: string): Promise<PayPalPayer> {
  const cartId = await getCartId()
  if (!cartId) {
    throw new Error("No existing cart found for the PayPal order")
  }

  const { payer } = await sdk.client.fetch<{ payer: PayPalPayer }>(
    `/store/paypal/orders/${encodeURIComponent(orderId)}/payer`,
    {
      method: "GET",
      query: { cart_id: cartId },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    }
  )
  return payer
}
```

В файле две функции:

- `getPayPalConfig` возвращает Client ID, окружение и способ списания из `GET /store/paypal/config`. Если в магазине нет включённой и полностью настроенной интеграции PayPal, функция возвращает `null`, и витрина не показывает кнопки PayPal.
- `getPayPalPayer` возвращает email, телефон и адрес доставки покупателя из `GET /store/paypal/orders/:order_id/payer`, а также сумму, которую он одобрил в PayPal. Функция передаёт в запросе ID корзины, и бэкенд отвечает только по заказу PayPal, созданному для этой корзины. Так никто не сможет прочитать чужой адрес, подобрав ID заказа.

Обе функции работают с единственной интеграцией PayPal в магазине. Если вы подключили несколько интеграций PayPal, добавьте параметр `provider_id` в оба запроса.

## Шаг 5: Загрузите SDK PayPal

Кнопки PayPal работают только внутри компонента, который загружает JS SDK PayPal. Кнопке оплаты и кнопке экспресс-оплаты нужен SDK с одинаковыми Client ID, способом списания и валютой, поэтому обе используют один компонент-обёртку.

Создайте файл [`src/modules/checkout/components/paypal-scope/index.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/paypal-scope/index.tsx) и добавьте следующий код:

![Структура проекта Medusa Storefront после создания файла с обёрткой SDK PayPal](/static/paypal/storefront/src-modules-checkout-components-paypal-scope-index.webp)

```tsx title="src/modules/checkout/components/paypal-scope/index.tsx"
"use client"

import { getPayPalConfig, type PayPalConfig } from "@lib/data/paypal"
import { PayPalScriptProvider } from "@paypal/react-paypal-js"
import { unstable_rethrow } from "next/navigation"
import { type ReactNode, useEffect, useState } from "react"

// One request per page, shared by every PayPal button on it.
let configRequest: Promise<PayPalConfig | null> | null = null

/** The PayPal settings, `undefined` while they load and `null` without a PayPal integration. */
export const usePayPalConfig = () => {
  const [config, setConfig] = useState<PayPalConfig | null | undefined>(undefined)

  useEffect(() => {
    let active = true
    configRequest ??= getPayPalConfig().catch(() => null)
    configRequest.then((value) => {
      if (active) setConfig(value)
    })
    return () => {
      active = false
    }
  }, [])

  return config
}

/**
 * True for the control-flow error a placed order's `redirect()` throws. The
 * router follows the redirect on its own, so a PayPal callback that meets it
 * returns instead of reporting a failure over the placed order.
 */
export const isNavigation = (error: unknown) => {
  try {
    unstable_rethrow(error)
    return false
  } catch {
    return true
  }
}

/**
 * Loads the PayPal JS SDK for the buttons inside it, with the client ID and the
 * intent the backend creates orders with and the cart's currency. Keyed by the
 * currency, because the provider reads its options once and a change inside a
 * mounted provider leaves the buttons blank.
 */
export default function PayPalScope({
  currencyCode,
  onUnavailable,
  children,
}: {
  currencyCode?: string | null
  /** Called when the store has no PayPal integration configured. */
  onUnavailable?: () => void
  children: ReactNode
}) {
  const config = usePayPalConfig()

  useEffect(() => {
    if (config === null) onUnavailable?.()
  }, [config, onUnavailable])

  if (!config) {
    return null
  }

  const currency = (currencyCode || "usd").toUpperCase()
  return (
    <PayPalScriptProvider
      key={currency}
      options={{
        clientId: config.client_id,
        currency,
        intent: config.intent,
        components: "buttons",
      }}
    >
      {children}
    </PayPalScriptProvider>
  )
}
```

Что экспортирует файл:

- `PayPalScope` загружает SDK с Client ID и способом списания из настроек бэкенда и с валютой корзины. Кнопки PayPal размещаются внутри него. Пока настройки загружаются, компонент ничего не показывает, а если интеграции PayPal в магазине нет, вызывает `onUnavailable`.
- `usePayPalConfig` запрашивает настройки PayPal один раз на страницу, сколько бы кнопок PayPal на ней ни было.
- `isNavigation` отличает переход после оформления заказа от настоящей ошибки. Когда заказ оформлен, `redirect()` в Next.js выбрасывает служебную ошибку, чтобы открыть страницу подтверждения заказа. `isNavigation` распознаёт её, и кнопка PayPal не показывает ошибку поверх уже оформленного заказа.

Проп `key` с валютой корзины пересоздаёт `PayPalScriptProvider` при смене валюты. Провайдер читает параметры только один раз, и без `key` SDK остался бы загружен со старой валютой.

## Шаг 6: Создайте кнопку оплаты

В витрине для каждого платёжного провайдера необходим отдельный компонент кнопки оплаты. На шаге оплаты PayPal показывает свою кнопку вместо кнопки оформления заказа. Кнопка открывает окно PayPal, а когда покупатель подтверждает в нём оплату, компонент оформляет заказ. Пока покупатель не заполнил всё, что нужно для заказа, например адрес доставки, компонент показывает неактивную кнопку оформления заказа.

Создайте файл [`src/modules/checkout/components/payment-button/providers/paypal.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/payment-button/providers/paypal.tsx) и добавьте следующий код:

![Структура проекта Medusa Storefront после создания файла с кнопкой оплаты PayPal](/static/paypal/storefront/src-modules-checkout-components-payment-button-providers-paypal.webp)

```tsx title="src/modules/checkout/components/payment-button/providers/paypal.tsx"
"use client"

import { buildPaymentSessionData, isPaypal } from "@lib/constants"
import { startExpressPayment } from "@lib/data/express-checkout"
import { Button } from "@medusajs/ui"
import ErrorMessage from "@modules/checkout/components/error-message"
import PayPalScope, {
  isNavigation,
} from "@modules/checkout/components/paypal-scope"
import { PayPalButtons, usePayPalScriptReducer } from "@paypal/react-paypal-js"
import { type PaymentProviderButtonProps, usePlaceOrder } from "../shared"

function PayPalButtonsInner({
  cart,
  notReady,
  cartUpdating,
  label,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) {
  const [{ isResolved, isRejected }] = usePayPalScriptReducer()
  const { setSubmitting, errorMessage, setErrorMessage, completeOrder } =
    usePlaceOrder()

  const providerId =
    cart.payment_collection?.payment_sessions?.find((s) =>
      isPaypal(s.provider_id)
    )?.provider_id ?? "pp_paypal_paypal"

  // The PayPal buttons show once the checkout has what the order needs.
  if (notReady || cartUpdating) {
    return (
      <Button
        disabled
        size="large"
        isLoading={cartUpdating}
        className="w-full"
        data-testid={dataTestId}
      >
        {label}
      </Button>
    )
  }
  if (isRejected) {
    return <ErrorMessage error="payment failed" data-testid={dataTestId} />
  }
  if (!isResolved) {
    return (
      <div className="h-12 rounded-md bg-ui-bg-component" aria-hidden="true" />
    )
  }

  // `isolate` keeps the SDK's iframe, at z-index 100, under the checkout modals.
  return (
    <div className="isolate" data-testid={dataTestId}>
      <PayPalButtons
        style={{
          layout: "vertical",
          color: "gold",
          shape: "rect",
          label: "paypal",
          height: 48,
        }}
        // The order of the session the checkout started when the cart was ready.
        // Without one, a new session at the click carries the cart as it is now.
        createOrder={async () => {
          setErrorMessage(null)
          const pending = cart.payment_collection?.payment_sessions?.find(
            (s) => isPaypal(s.provider_id) && s.status === "pending"
          )?.data?.paypal_order_id
          if (typeof pending === "string" && pending) {
            return pending
          }
          const data = await startExpressPayment(
            providerId,
            buildPaymentSessionData(providerId, cart) ?? {}
          )
          const orderId = data.paypal_order_id
          if (typeof orderId !== "string" || !orderId) {
            throw new Error("PayPal payment session has no order")
          }
          return orderId
        }}
        onApprove={async () => {
          setSubmitting(true)
          try {
            await completeOrder()
          } catch (err) {
            if (isNavigation(err)) return
            throw err
          }
        }}
        onCancel={() => setSubmitting(false)}
        onError={(err) => {
          setErrorMessage(err instanceof Error ? err.message : "payment failed")
          setSubmitting(false)
        }}
      />
      <ErrorMessage
        error={errorMessage}
        data-testid="paypal-payment-error-message"
      />
    </div>
  )
}

/** The PayPal button at the payment step, in place of the order button. */
const PayPalPaymentButton = (props: PaymentProviderButtonProps) => (
  <PayPalScope currencyCode={props.cart.currency_code}>
    <PayPalButtonsInner {...props} />
  </PayPalScope>
)

export default PayPalPaymentButton
```

Как работает компонент:

- `createOrder` возвращает ID заказа PayPal из платёжной сессии корзины. Если сессии ещё нет, компонент создаёт её в момент клика. Тогда заказ PayPal соответствует корзине на момент оплаты, а PayPal показывает адрес доставки из корзины и не спрашивает его у покупателя.
- `onApprove` оформляет заказ через `usePlaceOrder`, тот же хук, что используют остальные кнопки оплаты.

## Шаг 8: Добавьте PayPal в ряд экспресс-оплаты

Ряд экспресс-оплаты стартера показывает кнопку каждого платёжного провайдера, который есть в его реестре и включён в регионе корзины. При экспресс-оплате покупатель выбирает адрес доставки в окне PayPal, поэтому кнопка также пересчитывает доставку и итог. Как устроен ряд и что получает кнопка, читайте в разделе [Настройка экспресс-оплаты](/tools/medusa-dtc-starter/setup-express-checkout).

Создайте файл [`src/modules/checkout/components/express-checkout/buttons/paypal.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/express-checkout/buttons/paypal.tsx) и добавьте следующий код:

![Структура проекта Medusa Storefront после создания файла с кнопкой PayPal для экспресс-оплаты](/static/paypal/storefront/src-modules-checkout-components-express-checkout-buttons-paypal.webp)

```tsx title="src/modules/checkout/components/express-checkout/buttons/paypal.tsx" collapsibleLines="1-54"
"use client"

import {
  quoteExpressShipping,
  saveExpressContact,
  startExpressPayment,
} from "@lib/data/express-checkout"
import { getPayPalPayer } from "@lib/data/paypal"
import PayPalScope, {
  isNavigation,
} from "@modules/checkout/components/paypal-scope"
import { PayPalButtons, usePayPalScriptReducer } from "@paypal/react-paypal-js"
import { useEffect, useRef } from "react"
import type { ExpressButtonProps } from "../registry"

/** Rendered by `PayPalButtons` when PayPal is not available to this customer. */
function Unavailable({ onMount }: { onMount: () => void }) {
  useEffect(onMount, [onMount])
  return null
}

const orderIdOf = (data: Record<string, unknown>) => {
  const id = data.paypal_order_id
  if (typeof id !== "string" || !id) {
    throw new Error("PayPal payment session has no order")
  }
  return id
}

function PayPalWalletButton({
  providerId,
  shippingOptionId,
  onUnavailable,
  onError,
  onBusy,
  placeOrder,
  onClosed,
}: ExpressButtonProps) {
  const [{ isResolved, isRejected }] = usePayPalScriptReducer()
  const orderRef = useRef<string | null>(null)

  useEffect(() => {
    if (isRejected) onUnavailable()
  }, [isRejected, onUnavailable])

  if (isRejected) {
    return null
  }
  if (!isResolved) {
    return (
      <div className="h-12 rounded-md bg-ui-bg-component" aria-hidden="true" />
    )
  }

  // The SDK puts its iframe at z-index 100. `isolate` keeps it under the
  // checkout modals, which would otherwise open beneath the button.
  return (
    <div className="isolate">
      <PayPalButtons
        fundingSource="paypal"
        style={{
          layout: "horizontal",
          color: "gold",
          shape: "rect",
          label: "paypal",
          height: 48,
          tagline: false,
          disableMaxWidth: true,
        }}
        createOrder={async () => {
          onError(null)
          const orderId = orderIdOf(
            await startExpressPayment(providerId, { express: true })
          )
          orderRef.current = orderId
          return orderId
        }}
        onShippingAddressChange={async (data, actions) => {
          const orderId = data.orderID || orderRef.current
          if (!orderId) return actions.reject()
          let shipsThere = false
          try {
            const quote = await quoteExpressShipping(
              {
                country_code: data.shippingAddress.countryCode ?? "",
                province: data.shippingAddress.state,
                city: data.shippingAddress.city,
                postal_code: data.shippingAddress.postalCode,
              },
              shippingOptionId
            )
            shipsThere = quote.ok
            if (shipsThere) {
              // A new total makes Medusa drop the session, so the order the
              // customer is approving moves to a new one, which patches its amount.
              await startExpressPayment(
                providerId,
                { express: true, paypal_order_id: orderId },
                "paypal_order_id"
              )
            }
          } catch {
            return actions.reject()
          }
          if (!shipsThere) {
            // PayPal shows the thrown message, so the customer learns why the
            // address is refused. The SDK puts its own wording in `data.errors`,
            // which its types leave out.
            const { errors } = data as typeof data & {
              errors?: { ADDRESS_ERROR?: string }
            }
            throw new Error(
              errors?.ADDRESS_ERROR ??
                "Your order can't be shipped to this address."
            )
          }
        }}
        onApprove={async (data) => {
          onBusy(true)
          try {
            const payer = await getPayPalPayer(data.orderID)
            const approved = payer.amount
              ? Number(payer.amount.value)
              : undefined
            const saved = await saveExpressContact(
              {
                email: payer.email,
                phone: payer.phone,
                shipping_address: payer.shipping_address,
              },
              shippingOptionId,
              approved
            )
            if (!saved.ok) {
              onError(
                saved.reason === "totalChanged"
                  ? {
                      code: "totalChanged",
                      total: saved.total,
                      currency_code: saved.currency_code,
                    }
                  : { code: saved.reason }
              )
              onBusy(false)
              onClosed()
              return
            }
            // The saved address may have changed the total once more.
            await startExpressPayment(
              providerId,
              { express: true, paypal_order_id: data.orderID },
              "paypal_order_id"
            )
            await placeOrder()
          } catch (err) {
            if (isNavigation(err)) return
            onError({ code: "failed", cause: err })
            onBusy(false)
            onClosed()
          }
        }}
        onCancel={() => onClosed()}
        onError={(err) => {
          onError({ code: "failed", cause: err })
          onClosed()
        }}
      >
        <Unavailable onMount={onUnavailable} />
      </PayPalButtons>
    </div>
  )
}

/**
 * PayPal in the express checkout row. The customer picks the address in the
 * PayPal window, the row answers with the shipping and the new total, and the
 * order is placed once they approve.
 */
export default function PayPalExpressButton(props: ExpressButtonProps) {
  return (
    <PayPalScope
      currencyCode={props.cart.currency_code}
      onUnavailable={props.onUnavailable}
    >
      <PayPalWalletButton {...props} />
    </PayPalScope>
  )
}
```

Кнопка обрабатывает три колбэка PayPal:

- `createOrder` создаёт платёжную сессию с `express: true`. Тогда провайдер создаёт заказ PayPal без адреса, и PayPal спрашивает адрес у покупателя.
- `onShippingAddressChange` срабатывает, когда покупатель выбирает адрес в окне PayPal. Колбэк пересчитывает доставку и итог для этого адреса и обновляет сумму заказа PayPal. Если регион корзины не доставляет по этому адресу, колбэк выбрасывает ошибку, и окно PayPal сообщает об этом покупателю, чтобы он выбрал другой адрес.
- `onApprove` сохраняет в корзине контакты и адрес покупателя из `getPayPalPayer`, проверяет, что итог не превысил одобренную покупателем сумму, и оформляет заказ.

Когда итог меняется, Medusa удаляет платёжную сессию. Поэтому кнопка создаёт новую сессию с тем же `paypal_order_id`, а провайдер привязывает к ней заказ PayPal и обновляет его сумму.

Проверка итога нужна, потому что PayPal не всегда сообщает адрес до подтверждения оплаты, например при гостевой оплате картой. Доставка по этому адресу может увеличить итог, и тогда кнопка не оформляет заказ, а показывает сообщение с новым итогом и просит оплатить заново.

## Шаг 9: Добавьте подписи провайдера в локали витрины

Добавьте `pp_paypal_paypal` в [`messages/ru.json`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/messages/ru.json#L517-L520) и в каждую другую локаль под `messages/`:

```json title="messages/ru.json"
  "PaymentMethods": {

      "subtitle": "Карты, кошелёк"
    }
  }
}
```

Если для локали нет записи, используются английские `title` и `subtitle` из `paymentInfoMap` в [Шаге 2](#шаг-2-настройте-платёжный-провайдер).
