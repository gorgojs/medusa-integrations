# {frontmatter.title}

To integrate the PayPal payment provider into the [Medusa DTC Starter by Gorgo](https://github.com/gorgojs/medusa-dtc-starter) storefront, add the PayPal JS SDK and two PayPal buttons, one in the express checkout row above the checkout form and one at the payment step. The starter already names PayPal and shows its icon at the checkout, through `paymentInfoMap` in `src/lib/constants.tsx` and the `PaymentMethods.pp_paypal_paypal` label in every locale, so the labels need no change.

Both buttons load the SDK with the client ID and the intent the backend returns from `GET /store/paypal/config`. A click starts a payment session, and the provider creates a PayPal order for it. In the express checkout row, the customer picks the address in the PayPal window, the storefront recalculates the shipping and the total for it, and the provider updates the amount of the same PayPal order. Once the customer approves, the storefront reads the buyer from `GET /store/paypal/orders/:order_id/payer`, saves their contact and address on the cart and places the order, which captures or authorizes the payment.

When the customer closes the tab after PayPal has captured the payment, the `PAYMENT.CAPTURE.COMPLETED` webhook places the order instead. See [Webhook Setup](/medusa-integrations/paypal/getting-started#webhook-setup).

For the storefront on Next.js, you need to make the following changes:

## Step 1: Install the PayPal JS SDK

The buttons come from the official React wrapper of the PayPal JS SDK. Install it in the storefront:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn add @paypal/react-paypal-js@^8.9.2
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```bash
    npm install @paypal/react-paypal-js@^8.9.2
    ```
  </CodeTab>
</CodeTabs>

Version 8 of `@paypal/react-paypal-js` loads the PayPal JavaScript SDK from `www.paypal.com/sdk/js` and provides `PayPalButtons`, whose `onShippingAddressChange` callback reports the address the customer picks in the PayPal window.

## Step 2: Load PayPal Settings and the Buyer

The storefront asks the backend for two things. The public settings tell the SDK which app and intent to load, and the buyer of an approved order fills the cart in an express checkout.

Create [`src/lib/data/paypal.ts`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/lib/data/paypal.ts) with the following content:

![Directory structure in the Medusa Storefront after creating the file for PayPal data loaders](/static/paypal/storefront/src-lib-data-paypal.webp)

```ts title="src/lib/data/paypal.ts"
"use server"

import { sdk } from "@lib/config"
import { getAuthHeaders, getCartId } from "./cookies"

/** What the storefront needs to load the PayPal JS SDK, from `GET /store/paypal/config`. */
export type PayPalConfig = {
  provider_id: string
  client_id: string
  environment: "sandbox" | "live"
  intent: "capture" | "authorize"
}

/** The buyer of an approved PayPal order, from `GET /store/paypal/orders/:id/payer`. */
export type PayPalPayer = {
  amount: { currency_code: string; value: string } | null
  email: string | null
  phone: string | null
  shipping_address: {
    first_name: string | null
    last_name: string | null
    address_1: string | null
    address_2: string | null
    city: string | null
    province: string | null
    postal_code: string | null
    country_code: string | null
    phone: string | null
  } | null
}

/**
 * The public PayPal settings of the only PayPal integration, or null while it is
 * not configured. The client ID and the intent change only in the Admin, so the
 * answer is cached for a minute.
 */
export async function getPayPalConfig(): Promise<PayPalConfig | null> {
  return sdk.client
    .fetch<{ config: PayPalConfig }>("/store/paypal/config", {
      method: "GET",
      next: { revalidate: 60 },
    })
    .then(({ config }) => config)
    .catch(() => null)
}

/**
 * The contact and the shipping address the buyer chose in PayPal, and the amount
 * they approved. The backend answers only for an order created for this cart.
 */
export async function getPayPalPayer(orderId: string): Promise<PayPalPayer> {
  const cartId = await getCartId()
  if (!cartId) {
    throw new Error("No existing cart found for the PayPal order")
  }

  const { payer } = await sdk.client.fetch<{ payer: PayPalPayer }>(
    `/store/paypal/orders/${encodeURIComponent(orderId)}/payer`,
    {
      method: "GET",
      query: { cart_id: cartId },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    }
  )
  return payer
}
```

`getPayPalConfig` returns `null` when the backend has no enabled, fully configured PayPal integration to answer with, which hides the buttons. `getPayPalPayer` passes the cart id along, because the backend answers only for an order created for that cart's payment collection, so a storefront cannot read someone else's address by order id. The `amount` it returns is what the customer approved in PayPal. Both functions read the store's only PayPal integration. With several, pass `provider_id` as a query parameter to both routes.

## Step 3: Load the PayPal SDK

Both buttons need the SDK loaded with the same client ID, intent and currency, so one component wraps them.

Create [`src/modules/checkout/components/paypal-scope/index.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/paypal-scope/index.tsx) with the following content:

![Directory structure in the Medusa Storefront after creating the file for the PayPal SDK wrapper](/static/paypal/storefront/src-modules-checkout-components-paypal-scope-index.webp)

```tsx title="src/modules/checkout/components/paypal-scope/index.tsx"
"use client"

import { getPayPalConfig, type PayPalConfig } from "@lib/data/paypal"
import { PayPalScriptProvider } from "@paypal/react-paypal-js"
import { unstable_rethrow } from "next/navigation"
import { type ReactNode, useEffect, useState } from "react"

// One request per page, shared by every PayPal button on it.
let configRequest: Promise<PayPalConfig | null> | null = null

/** The PayPal settings, `undefined` while they load and `null` without a PayPal integration. */
export const usePayPalConfig = () => {
  const [config, setConfig] = useState<PayPalConfig | null | undefined>(undefined)

  useEffect(() => {
    let active = true
    configRequest ??= getPayPalConfig().catch(() => null)
    configRequest.then((value) => {
      if (active) setConfig(value)
    })
    return () => {
      active = false
    }
  }, [])

  return config
}

/**
 * True for the control-flow error a placed order's `redirect()` throws. The
 * router follows the redirect on its own, so a PayPal callback that meets it
 * returns instead of reporting a failure over the placed order.
 */
export const isNavigation = (error: unknown) => {
  try {
    unstable_rethrow(error)
    return false
  } catch {
    return true
  }
}

/**
 * Loads the PayPal JS SDK for the buttons inside it, with the client ID and the
 * intent the backend creates orders with and the cart's currency. Keyed by the
 * currency, because the provider reads its options once and a change inside a
 * mounted provider leaves the buttons blank.
 */
export default function PayPalScope({
  currencyCode,
  onUnavailable,
  children,
}: {
  currencyCode?: string | null
  /** Called when the store has no PayPal integration configured. */
  onUnavailable?: () => void
  children: ReactNode
}) {
  const config = usePayPalConfig()

  useEffect(() => {
    if (config === null) onUnavailable?.()
  }, [config, onUnavailable])

  if (!config) {
    return null
  }

  const currency = (currencyCode || "usd").toUpperCase()
  return (
    <PayPalScriptProvider
      key={currency}
      options={{
        clientId: config.client_id,
        currency,
        intent: config.intent,
        components: "buttons",
      }}
    >
      {children}
    </PayPalScriptProvider>
  )
}
```

The SDK loads with the cart's currency, and the provider is keyed by it, because `PayPalScriptProvider` reads its options once and would otherwise keep the SDK loaded with the old currency. `isNavigation` recognizes the `redirect()` a placed order ends in, so a PayPal callback that meets it returns instead of showing an error over the placed order.

## Step 4: Start the Payment Session When the Cart Is Ready

The checkout starts a payment session as soon as the customer selects a payment method. The PayPal order carries the cart's total and the delivery address, so a session started before the cart has them creates an order for a cart that has neither. An entry in `paymentSessionDataBuilders` makes the checkout wait.

Open [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/lib/constants.tsx#L63-L86) and add the following entry to `paymentSessionDataBuilders`:

![Directory structure in the Medusa Storefront after updating the file for constants](/static/paypal/storefront/src-lib-constants.webp)

```tsx title="src/lib/constants.tsx"
const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isPaypal(providerId),
    // The PayPal order carries the cart's total and the delivery address, so the
    // session starts once the checkout has an email, an address and a shipping
    // method. Earlier, PayPal gets an order for a cart that has none of them.
    isReady: (cart) =>
      Boolean(
        cart.email &&
          cart.shipping_address?.address_1 &&
          (cart.shipping_methods?.length ?? 0) > 0
      ),
    // The email, the name and the billing address fill in PayPal's card form.
    build: (cart) => ({
      shipping_address: cart.shipping_address,
      billing_address: cart.billing_address,
      email: cart.email,
    }),
  },
]
```

`isReady` holds the session back until the cart has an email, a delivery address and a shipping method, and `build` hands the cart's details to the provider. The provider sets the delivery address on the PayPal order, and the email, the name and the billing address fill in PayPal's card form when the customer pays by card. The payment button reads the same `isReady`, so the PayPal button at the payment step stays disabled until then.

## Step 5: Create Payment Button

{/* TODO: screenshot of the PayPal button at the payment step */}

At the payment step, the PayPal button takes the place of the order button when the customer selects PayPal. While the cart is not ready, a disabled order button stands there instead.

Create [`src/modules/checkout/components/payment-button/providers/paypal.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/payment-button/providers/paypal.tsx) with the following content:

![Directory structure in the Medusa Storefront after creating the file for the PayPal payment button](/static/paypal/storefront/src-modules-checkout-components-payment-button-providers-paypal.webp)

```tsx title="src/modules/checkout/components/payment-button/providers/paypal.tsx"
"use client"

import { buildPaymentSessionData, isPaypal } from "@lib/constants"
import { startExpressPayment } from "@lib/data/express-checkout"
import { Button } from "@medusajs/ui"
import ErrorMessage from "@modules/checkout/components/error-message"
import PayPalScope, {
  isNavigation,
} from "@modules/checkout/components/paypal-scope"
import { PayPalButtons, usePayPalScriptReducer } from "@paypal/react-paypal-js"
import { type PaymentProviderButtonProps, usePlaceOrder } from "../shared"

function PayPalButtonsInner({
  cart,
  notReady,
  cartUpdating,
  label,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) {
  const [{ isResolved, isRejected }] = usePayPalScriptReducer()
  const { setSubmitting, errorMessage, setErrorMessage, completeOrder } =
    usePlaceOrder()

  const providerId =
    cart.payment_collection?.payment_sessions?.find((s) =>
      isPaypal(s.provider_id)
    )?.provider_id ?? "pp_paypal_paypal"

  // The PayPal buttons show once the checkout has what the order needs.
  if (notReady || cartUpdating) {
    return (
      <Button
        disabled
        size="large"
        isLoading={cartUpdating}
        className="w-full"
        data-testid={dataTestId}
      >
        {label}
      </Button>
    )
  }
  if (isRejected) {
    return <ErrorMessage error="payment failed" data-testid={dataTestId} />
  }
  if (!isResolved) {
    return (
      <div className="h-12 rounded-md bg-ui-bg-component" aria-hidden="true" />
    )
  }

  // `isolate` keeps the SDK's iframe, at z-index 100, under the checkout modals.
  return (
    <div className="isolate" data-testid={dataTestId}>
      <PayPalButtons
        style={{
          layout: "vertical",
          color: "gold",
          shape: "rect",
          label: "paypal",
          height: 48,
        }}
        // The order of the session the checkout started when the cart was ready.
        // Without one, a new session at the click carries the cart as it is now.
        createOrder={async () => {
          setErrorMessage(null)
          const pending = cart.payment_collection?.payment_sessions?.find(
            (s) => isPaypal(s.provider_id) && s.status === "pending"
          )?.data?.paypal_order_id
          if (typeof pending === "string" && pending) {
            return pending
          }
          const data = await startExpressPayment(
            providerId,
            buildPaymentSessionData(providerId, cart) ?? {}
          )
          const orderId = data.paypal_order_id
          if (typeof orderId !== "string" || !orderId) {
            throw new Error("PayPal payment session has no order")
          }
          return orderId
        }}
        onApprove={async () => {
          setSubmitting(true)
          try {
            await completeOrder()
          } catch (err) {
            if (isNavigation(err)) return
            throw err
          }
        }}
        onCancel={() => setSubmitting(false)}
        onError={(err) => {
          setErrorMessage(err instanceof Error ? err.message : "payment failed")
          setSubmitting(false)
        }}
      />
      <ErrorMessage
        error={errorMessage}
        data-testid="paypal-payment-error-message"
      />
    </div>
  )
}

/** The PayPal button at the payment step, in place of the order button. */
const PayPalPaymentButton = (props: PaymentProviderButtonProps) => (
  <PayPalScope currencyCode={props.cart.currency_code}>
    <PayPalButtonsInner {...props} />
  </PayPalScope>
)

export default PayPalPaymentButton
```

`createOrder` returns the order of the session the checkout started when the cart was ready. Without one, it starts a session at the click, so the order carries the cart as it is when the customer pays, and PayPal shows its address instead of asking for one. `onApprove` places the order through `usePlaceOrder`, the same hook the other payment buttons use.

## Step 7: Add PayPal to the Express Checkout Row

{/* TODO: screenshot of the express checkout row with the PayPal button */}

The express checkout row of the starter shows a button for every payment provider listed in its registry and enabled in the cart's region. How the row works and what a button receives is described in [Set Up Express Checkout](/tools/medusa-dtc-starter/setup-express-checkout).

Create [`src/modules/checkout/components/express-checkout/buttons/paypal.tsx`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/express-checkout/buttons/paypal.tsx) with the following content:

![Directory structure in the Medusa Storefront after creating the file for the PayPal express checkout button](/static/paypal/storefront/src-modules-checkout-components-express-checkout-buttons-paypal.webp)

```tsx title="src/modules/checkout/components/express-checkout/buttons/paypal.tsx" collapsibleLines="1-54"
"use client"

import {
  quoteExpressShipping,
  saveExpressContact,
  startExpressPayment,
} from "@lib/data/express-checkout"
import { getPayPalPayer } from "@lib/data/paypal"
import PayPalScope, {
  isNavigation,
} from "@modules/checkout/components/paypal-scope"
import { PayPalButtons, usePayPalScriptReducer } from "@paypal/react-paypal-js"
import { useEffect, useRef } from "react"
import type { ExpressButtonProps } from "../registry"

/** Rendered by `PayPalButtons` when PayPal is not available to this customer. */
function Unavailable({ onMount }: { onMount: () => void }) {
  useEffect(onMount, [onMount])
  return null
}

const orderIdOf = (data: Record<string, unknown>) => {
  const id = data.paypal_order_id
  if (typeof id !== "string" || !id) {
    throw new Error("PayPal payment session has no order")
  }
  return id
}

function PayPalWalletButton({
  providerId,
  shippingOptionId,
  onUnavailable,
  onError,
  onBusy,
  placeOrder,
  onClosed,
}: ExpressButtonProps) {
  const [{ isResolved, isRejected }] = usePayPalScriptReducer()
  const orderRef = useRef<string | null>(null)

  useEffect(() => {
    if (isRejected) onUnavailable()
  }, [isRejected, onUnavailable])

  if (isRejected) {
    return null
  }
  if (!isResolved) {
    return (
      <div className="h-12 rounded-md bg-ui-bg-component" aria-hidden="true" />
    )
  }

  // The SDK puts its iframe at z-index 100. `isolate` keeps it under the
  // checkout modals, which would otherwise open beneath the button.
  return (
    <div className="isolate">
      <PayPalButtons
        fundingSource="paypal"
        style={{
          layout: "horizontal",
          color: "gold",
          shape: "rect",
          label: "paypal",
          height: 48,
          tagline: false,
          disableMaxWidth: true,
        }}
        createOrder={async () => {
          onError(null)
          const orderId = orderIdOf(
            await startExpressPayment(providerId, { express: true })
          )
          orderRef.current = orderId
          return orderId
        }}
        onShippingAddressChange={async (data, actions) => {
          const orderId = data.orderID || orderRef.current
          if (!orderId) return actions.reject()
          let shipsThere = false
          try {
            const quote = await quoteExpressShipping(
              {
                country_code: data.shippingAddress.countryCode ?? "",
                province: data.shippingAddress.state,
                city: data.shippingAddress.city,
                postal_code: data.shippingAddress.postalCode,
              },
              shippingOptionId
            )
            shipsThere = quote.ok
            if (shipsThere) {
              // A new total makes Medusa drop the session, so the order the
              // customer is approving moves to a new one, which patches its amount.
              await startExpressPayment(
                providerId,
                { express: true, paypal_order_id: orderId },
                "paypal_order_id"
              )
            }
          } catch {
            return actions.reject()
          }
          if (!shipsThere) {
            // PayPal shows the thrown message, so the customer learns why the
            // address is refused. The SDK puts its own wording in `data.errors`,
            // which its types leave out.
            const { errors } = data as typeof data & {
              errors?: { ADDRESS_ERROR?: string }
            }
            throw new Error(
              errors?.ADDRESS_ERROR ??
                "Your order can't be shipped to this address."
            )
          }
        }}
        onApprove={async (data) => {
          onBusy(true)
          try {
            const payer = await getPayPalPayer(data.orderID)
            const approved = payer.amount
              ? Number(payer.amount.value)
              : undefined
            const saved = await saveExpressContact(
              {
                email: payer.email,
                phone: payer.phone,
                shipping_address: payer.shipping_address,
              },
              shippingOptionId,
              approved
            )
            if (!saved.ok) {
              onError(
                saved.reason === "totalChanged"
                  ? {
                      code: "totalChanged",
                      total: saved.total,
                      currency_code: saved.currency_code,
                    }
                  : { code: saved.reason }
              )
              onBusy(false)
              onClosed()
              return
            }
            // The saved address may have changed the total once more.
            await startExpressPayment(
              providerId,
              { express: true, paypal_order_id: data.orderID },
              "paypal_order_id"
            )
            await placeOrder()
          } catch (err) {
            if (isNavigation(err)) return
            onError({ code: "failed", cause: err })
            onBusy(false)
            onClosed()
          }
        }}
        onCancel={() => onClosed()}
        onError={(err) => {
          onError({ code: "failed", cause: err })
          onClosed()
        }}
      >
        <Unavailable onMount={onUnavailable} />
      </PayPalButtons>
    </div>
  )
}

/**
 * PayPal in the express checkout row. The customer picks the address in the
 * PayPal window, the row answers with the shipping and the new total, and the
 * order is placed once they approve.
 */
export default function PayPalExpressButton(props: ExpressButtonProps) {
  return (
    <PayPalScope
      currencyCode={props.cart.currency_code}
      onUnavailable={props.onUnavailable}
    >
      <PayPalWalletButton {...props} />
    </PayPalScope>
  )
}
```

`createOrder` starts a payment session with `express: true`, so the provider lets PayPal ask for the address. `onShippingAddressChange` recalculates the shipping and the total for the address the customer picks, and starts a session with the same `paypal_order_id`. When the cart's region does not ship to that address, it throws PayPal's own `ADDRESS_ERROR` text, which the PayPal window shows so the customer picks another address. A new total makes Medusa drop the session, so the provider attaches the same PayPal order to the new session and updates its amount. `onApprove` saves the buyer's contact and address from `getPayPalPayer` on the cart, compares the total with the amount the customer approved, and places the order. A total above the approved amount stops there with a message, because PayPal does not always report the address before approval, for example for a guest paying by card, and the shipping for it can raise the total.

Then list the button in [`src/modules/checkout/components/express-checkout/registry.ts`](https://github.com/gorgojs/medusa-integrations/blob/main/examples/payment-paypal/apps/storefront/src/modules/checkout/components/express-checkout/registry.ts#L43-L48):

