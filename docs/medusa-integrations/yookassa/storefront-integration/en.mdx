# {frontmatter.title}

To integrate the YooKassa payment provider into the [Medusa DTC Starter by Gorgo](https://github.com/gorgojs/medusa-dtc-starter) storefront, start by adding the required UI components, so the provider is displayed on the checkout page alongside other available payment methods.

When the customer selects YooKassa, the checkout initiates a payment session, and the provider creates it on YooKassa's side and returns the payment address. The payment button then sends the customer there, where they can choose a payment method.

Once the payment is completed, YooKassa concurrently sends a webhook and redirects the customer back to the storefront.

For the storefront on Next.js, you need to make the following changes:

## Step 1: Configure Payment Provider

Open [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/a9a6c9ca380bf9d7807d71bfcdf85da082fafa87/examples/payment-yookassa/apps/storefront/src/lib/constants.tsx#L41-L44) and add YooKassa to the payment provider mapping, plus a helper to recognize its sessions:

{/* TODO: screenshot */}

```ts title="src/lib/constants.tsx"
export const paymentInfoMap: Record<
  string,
  { title: string; icon: React.JSX.Element }
> = {
  // ...
  pp_yookassa_yookassa: {
    title: "YooKassa",
    icon: <CreditCard />,
  },
  // ...
}

// ...

export const isYookassa = (providerId?: string) => {
  return providerId?.startsWith("pp_yookassa")
}
```

`paymentInfoMap`'s `title` is the fallback name shown at checkout when a locale has no translation. `isYookassa` is used by the dispatcher below and by the session data builder in the next step.

## Step 2: Initialize Payment Session

Open the same [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/a9a6c9ca380bf9d7807d71bfcdf85da082fafa87/examples/payment-yookassa/apps/storefront/src/lib/constants.tsx#L60-L90) and add the return address and the session data builder:

{/* TODO: screenshot */}

```ts title="src/lib/constants.tsx"
/**
 * The address the customer comes back to after paying on the provider's own
 * page. `<html lang>` carries the locale the checkout was rendered in, so the
 * customer returns to the language they left the shop with.
 */
const paymentReturnUrl = (providerId: string, cartId: string) => {
  const origin =
    typeof window === "undefined" ? getBaseURL() : window.location.origin
  const locale =
    typeof document === "undefined"
      ? defaultLocale
      : document.documentElement.lang || defaultLocale

  return `${origin}/api/payment-return?provider=${providerId}&cart_id=${cartId}&locale=${locale}`
}

const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isYookassa(providerId),
    // YooKassa builds a receipt out of the cart, and the receipt needs the
    // buyer's name, email and phone. Initiating the session before the checkout
    // collected them creates a payment without one.
    isReady: (cart) => Boolean(cart.email && cart.shipping_address),
    build: (cart) => ({
      confirmation: {
        type: "redirect",
        return_url: paymentReturnUrl("yookassa", cart.id),
      },
      cart,
    }),
  },
]
```

When initiating a payment for YooKassa, `build` passes a `confirmation` object with `type: "redirect"` and a `return_url`, plus the `cart` to build a compliant receipt. `isReady` holds the session back until the cart carries an email and a shipping address.

## Step 3: Create Payment Button

Create [`src/modules/checkout/components/payment-button/providers/yookassa.tsx`](https://github.com/gorgojs/medusa-integrations/blob/a9a6c9ca380bf9d7807d71bfcdf85da082fafa87/examples/payment-yookassa/apps/storefront/src/modules/checkout/components/payment-button/providers/yookassa.tsx):

{/* TODO: screenshot */}

```ts title="src/modules/checkout/components/payment-button/providers/yookassa.tsx"
"use client"

import type { HttpTypes } from "@medusajs/types"
import { useTranslations } from "next-intl"
import { useState } from "react"
import { PaymentButtonShell, type PaymentProviderButtonProps } from "../shared"

const confirmationUrl = (cart: HttpTypes.StoreCart) => {
  const session = cart.payment_collection?.payment_sessions?.find((s) =>
    s.provider_id.startsWith("pp_yookassa")
  )
  const confirmation = session?.data?.confirmation as
    | { confirmation_url?: string }
    | undefined

  return confirmation?.confirmation_url
}

/**
 * YooKassa collects the payment on its own page. The session the checkout
 * created carries the address to send the customer to, and the order is placed
 * once they come back through `/api/payment-return` — or by the webhook, if
 * that arrives first.
 */
const YookassaPaymentButton = ({
  cart,
  notReady,
  label,
  cartUpdating,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) => {
  const t = useTranslations("Errors")
  const [submitting, setSubmitting] = useState(false)
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  const handlePayment = () => {
    const url = confirmationUrl(cart)

    if (!url) {
      setErrorMessage(t("paymentFailed"))
      return
    }

    setSubmitting(true)
    window.location.assign(url)
  }

  return (
    <PaymentButtonShell
      label={label}
      onClick={handlePayment}
      disabled={notReady}
      loading={submitting || cartUpdating}
      errorMessage={errorMessage}
      errorTestId="yookassa-payment-error-message"
      data-testid={dataTestId ?? "submit-order-button"}
    />
  )
}

export default YookassaPaymentButton
```

This component finds the YooKassa `payment_session` in the active cart and extracts `data.confirmation.confirmation_url`. When the customer clicks, `handlePayment` sends them there directly with `window.location.assign`, since YooKassa's page isn't embedded in the storefront.

If the `confirmation_url` is missing, the button shows an error message instead of navigating anywhere.

## Step 5: Handle Payment Return

YooKassa reports the payment status through both a webhook and this redirect, so the shared route checks the cart for an order before placing one itself.

Open [`src/app/api/payment-return/route.ts`](https://github.com/gorgojs/medusa-integrations/blob/a9a6c9ca380bf9d7807d71bfcdf85da082fafa87/examples/payment-yookassa/apps/storefront/src/app/api/payment-return/route.ts#L29-L80) and add the following function:

{/* TODO: screenshot */}

```ts title="src/app/api/payment-return/route.ts"
type ReturnContext = {
  cartId: string
  locale: string
  origin: string
}

/**
 * Comes back from a provider that takes the customer to its own payment page
 * and returns them with nothing but the cart id — YooKassa among them.
 *
 * The provider's webhook and this redirect race each other, and whichever
 * arrives first places the order, so the cart is checked for an order before
 * one is placed.
 */
async function redirectProviderReturn({
  cartId,
  locale,
  origin,
}: ReturnContext) {
  const cart = await sdk.client
    .fetch<HttpTypes.StoreCartResponse>(`/store/carts/${cartId}`, {
      method: "GET",
      query: { fields: "id,order_link.order_id" },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    })
    .then(({ cart }) => cart)
    .catch(() => null)

  if (!cart) {
    return NextResponse.redirect(
      `${origin}/${locale}/cart?error=payment_failed`
    )
  }

  const orderId = (cart as unknown as { order_link?: { order_id?: string } })
    .order_link?.order_id

  if (orderId) {
    const orderCacheTag = await getCacheTag("orders")
    revalidateTag(orderCacheTag)
    await removeCartId()

    return NextResponse.redirect(
      `${origin}/${locale}/order/${orderId}/confirmed`
    )
  }

  // The customer backed out or the payment was declined, so they land back on
  // the checkout with their cart intact and can pick a method again.
  await setCartId(cartId)

  try {
    await placeOrder(cartId)
  } catch (error) {
    unstable_rethrow(error)

    return NextResponse.redirect(
      `${origin}/${locale}/checkout?error=payment_failed`
    )
  }

  return NextResponse.redirect(
    `${origin}/${locale}/checkout?error=payment_failed`
  )
}
```

Then route YooKassa's return to it, in `GET` itself:

```ts title="src/app/api/payment-return/route.ts"
  if (provider === "yookassa") {
    return redirectProviderReturn({ cartId, locale, origin })
  }
```

If the cart already has an order, the webhook won the race, so the route revalidates the order cache and sends the customer to the confirmation page. Otherwise it tries `placeOrder` itself, and on any failure sends the customer back to the checkout with `error=payment_failed` so they can pick a method again.

## Step 6: Add Provider Name to Storefront Locales

Add `pp_yookassa_yookassa` to [`messages/en.json`](https://github.com/gorgojs/medusa-integrations/blob/a9a6c9ca380bf9d7807d71bfcdf85da082fafa87/examples/payment-yookassa/apps/storefront/messages/en.json#L513) and to every other locale under `messages/`:

```json title="messages/en.json"
{
  "PaymentMethods": {
    // ...
    "pp_yookassa_yookassa": "YooKassa"
  }
}
```

A locale missing an entry falls back to the English `title` from `paymentInfoMap` in [Step 1](#step-1-configure-payment-provider). YooKassa's own name stays the same across locales, except in Russian it's `ЮKassa`.
