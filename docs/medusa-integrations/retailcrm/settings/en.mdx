# {frontmatter.title}

In this guide, you'll learn how to manage the settings of the RetailCRM integration.

## View RetailCRM Details

To open the RetailCRM settings page:

1. Open the Medusa Admin.
2. Go to **Settings → Integrations → RetailCRM**.

This opens the settings page. The left column holds the integration status, the **Connection** and **Changes from the CRM** sections and the **Order statuses**, **Payment types** and **Delivery types** tables. The right column holds the **Sales channel**, **Payment statuses** and **Order methods** cards.

The plugin loads the CRM statuses, types and order methods from your account as soon as the connection has its URL, API key and store code saved. The integration doesn't have to be enabled for that. The plugin loads them again each time you open the page or a side panel, so an entry just added in the CRM shows up in the list right away. When an entry is deleted in Medusa or no longer available in the CRM, it carries a **Not in Medusa** or **Not in CRM** mark.

## Edit the Connection

The **Connection** section holds three required fields:

- **RetailCRM URL** – the address of your RetailCRM or Simla.com account, such as `https://example.retailcrm.ru`. Only `https` is accepted.
- **API key** – a key from **Settings → Integration → API access keys** in the CRM. It needs access to orders, customers and reference data, which is the `order_read`, `order_write`, `customer_read`, `customer_write` and `reference_read` scopes.
- **Store code** – the symbolic code of the store from **Stores** in the CRM settings. One instance works with one store.

To edit the connection:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Connection** section, click the action menu in the section header.
3. Choose **Edit**.
4. In the side panel that opens, fill in the three fields.
5. Click **Save**.

## Choose the Sales Channel

The **Sales channel** card sets the Medusa sales channel this instance works with. Orders of this channel go to the CRM store, and orders created in the CRM land in this channel. The instance ignores orders of other channels. Without a sales channel, the integration stays **Incomplete** and doesn't exchange data, so the card marks the setting as required and reads **Not selected** until you choose a channel. The card shows the selected channel as a link to its page in the Medusa Admin.

When the same channel is selected in another RetailCRM instance, the card shows a warning. An order goes to one instance by its channel, so the second instance with the same channel gets no orders.

To choose the sales channel:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Sales channel** card, click the action menu in the card header.
3. Choose **Edit**.
4. In the side panel that opens, find the sales channel by its name and choose it. A channel already selected in another RetailCRM instance is marked in the list.
5. Click **Save**.

## Check the Connection

The connection test calls the CRM. It checks that the API key has the five scopes, that it gives access to the store with this code and that the store exists in the account. Then it checks the entries chosen in the settings against the CRM references:

- the order statuses, payment types, delivery types and payment statuses must be active reference entries;
- the payment and delivery types must be available to the store of this instance;
- a payment type must not belong to a CRM payment module;
- the status in **Payment captured**, when one is chosen, must be marked in the CRM as a completed payment.

The **Test connection** action appears once the integration is fully configured and enabled.

To check the connection:

1. Go to **Settings → Integrations → RetailCRM**.
2. Open the action menu next to the integration's name.
3. If the integration is still disabled, choose **Enable** and open the menu again.
4. Choose **Test connection**.

When the test passes, the notification reads **Connection OK**. When it fails, the notification lists everything that is missing, so you can fix the settings in one go. The test doesn't reject an address outside the `retailcrm.ru`, `simla.com` and `retailcrm.pro` domains, so check such an address yourself.

## Manage the Order Statuses

The **Order statuses** table links an order event in Medusa to the CRM status the order gets. The plugin sends the status when the order is placed, completed or canceled. When a manager changes an order's status in the CRM, the plugin acts on the status group, not the code, as described in [Edit the Changes from the CRM](#edit-the-changes-from-the-crm). The statuses here only affect what the plugin sends.

By default, a placed order gets the standard RetailCRM status of the New group, a completed one that of the Completed group, and a canceled one that of the Cancelled group. When an event is mapped to **Don't send**, the plugin doesn't send the order to the CRM on that event. For an event without a mapping, the plugin sends the order without a status, and a new order gets the CRM default status.

To add or change a mapping:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Order statuses** table, click **Add**, or open the action menu in a row and choose **Edit**.
3. In the side panel that opens, choose the **Medusa event**.
4. Choose the **CRM status** from the list the plugin loads from your account, or **Don't send**.
5. Click **Save**.

## Manage the Payment Types

The **Payment types** table links a Medusa payment provider to a CRM payment type. Medusa's system provider `pp_system_default` is listed as **Manual payment**, and the plugin builds the names of the others from their IDs. Disabled providers aren't offered for a new row.

The CRM requires a type on every payment, so without a mapping the plugin uses the payment type set as the API default in your account, and shows its name under the table. When there is no such type or it's closed to the store of this instance, payments of providers without a mapping don't go to the CRM.

Payment types that belong to a CRM payment module, such as an online acquiring module, aren't offered, because the CRM doesn't allow editing their payments through the API. Types closed to the store of this instance aren't offered either.

To add or change a mapping:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Payment types** table, click **Add**, or open the action menu in a row and choose **Edit**.
3. In the side panel that opens, choose the **Payment provider**.
4. Choose the **CRM payment type**, or **Don't send** to keep this provider's payments out of the CRM.
5. Click **Save**.

## Manage the Delivery Types

The **Delivery types** table links a Medusa shipping option type to a CRM delivery type. You set up the types in the Medusa Admin under **Settings → Locations & Shipping → Shipping Option Types**, and choose a shipping option's type when you create or edit it. The mapping goes by the type code, so one row covers the shipping options of that type in every delivery zone. Types that share a code are listed as one entry.

The plugin sends the CRM delivery type by the type of the order's shipping option. When the type has no mapping, or is mapped to **No type**, the delivery goes to the CRM with its cost and address but without a type. CRM delivery types closed to the store of this instance aren't offered.

The mapping works in the other direction too. When a manager changes the delivery type in the CRM, the plugin gives the order a shipping option of the mapped type from the same zone as its current one. When the order has no Medusa shipping option, the plugin looks in the zone that covers the country of the shipping address. This works while **Apply item and delivery changes** is on. When there is no such option, the delivery stays as it is, and the CRM delivery type is recorded in the order's metadata.

An order created in the CRM gets a shipping option of the mapped type from the zone that covers the country of its address. When there is no such option, the order gets the delivery with the cost from the CRM, but without a Medusa shipping option. A later change of only that delivery's cost is recorded in the metadata.

To add or change a mapping:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Delivery types** table, click **Add**, or open the action menu in a row and choose **Edit**.
3. In the side panel that opens, choose the **Shipping option type**.
4. Choose the **CRM delivery type**, or **No type**.
5. Click **Save**.

## Edit the Payment Statuses

The **Payment statuses** card sets the CRM payment statuses the plugin puts on a payment:

- **Payment captured** – the CRM status for a payment captured in Medusa. The plugin sets it when the payment is captured in Medusa, and when the order first goes to the CRM with the payment already captured. The default is the CRM's standard paid status. The list holds only statuses the CRM treats as a completed payment.
- **Uncaptured or refunded** – the CRM status for a payment that isn't captured yet or is fully refunded. The plugin sets it when the order first goes to the CRM with the payment not captured, and when the payment is fully refunded in Medusa. The default is the CRM's standard unpaid status. The list holds only statuses the CRM doesn't treat as a completed payment. A partial refund doesn't change the status. The plugin only adds a comment to the payment.

You can clear a status. The card then reads **Not sent**, and the plugin sends the payment without a status. A new payment gets the status the CRM sets, and an existing one keeps its status.

To edit the payment statuses:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Payment statuses** card, click the action menu in the card header.
3. Choose **Edit**.
4. In the side panel that opens, choose the statuses. To stop sending a status, clear it with the cross in the field.
5. Click **Save**.

## Edit the Changes from the CRM

The **Changes from the CRM** section decides how often the plugin checks the CRM for changes and what it applies:

- **CRM check interval, min** – how often the plugin fetches order and customer changes from the CRM. The default is five minutes.
- **Apply item and delivery changes** – on by default. Items, the delivery type and the delivery cost changed in the CRM become an order edit in Medusa. When off, the plugin only records them in the order's metadata. The delivery address, the email and the customer of the order change in Medusa whatever the switch says.
- **Create orders** – on by default. A new order in the CRM, such as a phone order, appears in Medusa, and the CRM order gets the Medusa order ID. The [Order methods](#choose-the-order-methods) card limits it to the methods you choose.
- **Cancel orders** – off by default. When on, a CRM status from the Cancelled group, or deleting the order in the CRM, cancels the order in Medusa. Cancellation can't be undone. The plugin skips a completed order and an order with a fulfillment that isn't canceled.
- **Complete orders** – off by default. When on, a CRM status from the Completed group completes the order in Medusa.
- **Capture manual payments** – off by default. When on, a completed payment status in the CRM captures the order's payment made through Medusa's system payment provider, and a paid CRM payment with no Medusa counterpart marks the order's unpaid payment collection as paid. The plugin never captures payments of other providers.

To edit the section:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Changes from the CRM** section, click the action menu in the section header.
3. Choose **Edit**.
4. In the side panel that opens, set the interval and the switches.
5. Click **Save**.

## Choose the Order Methods

In the **Order methods** card, you choose the CRM order methods whose orders the plugin creates in Medusa. The plugin loads the methods from your account. With none selected, the card reads **All methods**, and the plugin creates orders of every method. Below the names, the card shows for how many of the CRM methods orders are created. The card is shown while **Create orders** is on.

The card shows only the selected methods that exist and are active in the CRM. When none of them is left in the CRM, the card reads **None of the selected methods are in the CRM**, and the plugin creates no orders from the CRM until you change the selection.

To choose the order methods:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Order methods** card, click the action menu in the card header.
3. Choose **Edit**.
4. In the side panel that opens, pick the methods in the field, or remove them all to create orders of all methods. Methods that are no longer in the CRM leave the settings when you save.
5. Click **Save**.
