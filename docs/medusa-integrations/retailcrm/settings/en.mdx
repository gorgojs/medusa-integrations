In this guide, you'll learn how to manage the settings of the RetailCRM integration.

## View RetailCRM Details

To open the RetailCRM settings page:

1. Open the Medusa Admin.
2. Go to **Settings → Integrations → RetailCRM**.

This opens the settings page with the integration status, the **Connection**, **Payment statuses** and **Changes from the CRM** sections, and three sections added by the plugin, **Order statuses**, **Payment types** and **Delivery types**.

## Edit the Connection

The **Connection** section holds four required fields:

- **Account address** – the address of your account, such as `https://example.retailcrm.ru`. Only `https` is accepted.
- **API key** – an API key from **Settings → Integration → API keys** of the CRM with the `order_read`, `order_write`, `customer_read`, `customer_write` and `reference_read` scopes.
- **Store code** – the code of the CRM store this instance writes to. One instance is one store, and every request to the CRM carries this code.
- **Sales channel ID** – the Medusa sales channel whose orders go to this store. Orders of other channels are ignored by this instance.

To edit the connection:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Connection** section, click the action menu in the section header.
3. Choose **Edit**.
4. In the side panel that opens, fill in the four fields.
5. Click **Save**.

## Check the Connection

The connection test calls the CRM. It checks that the API key has the five scopes, that it covers the store code, that the store exists in the account, and that every code in the status, payment type, delivery type and payment status settings is an active entry of the matching CRM reference. The result names everything that is missing in one message, so you fix the settings in one go.

To check the connection:

1. Go to **Settings → Integrations → RetailCRM**.
2. Open the action menu next to the integration's name.
3. Choose **Test connection**.

The result appears in a notification. An address outside the `retailcrm.ru`, `simla.com` and `retailcrm.pro` domains passes the test with a warning in the message.

## Manage the Order Statuses

The **Order statuses** section links an order event in Medusa to the CRM status the order gets. The plugin sends the status when the order is placed, completed or canceled. A manager's status changes in the CRM come back by the status group, as described in [Edit the Changes from the CRM](#edit-the-changes-from-the-crm), so the codes here only matter for what Medusa sends.

The defaults are `new` for a placed order, `complete` for a completed one and `cancel-other` for a canceled one, the standard codes of a RetailCRM account. An event mapped to **Do not send** keeps the order out of the CRM when it happens.

To add or change a mapping:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Order statuses** section, click **Add**, or open the action menu in a row and choose **Edit**.
3. In the side panel that opens, choose the Medusa event.
4. Choose the CRM status from the list the plugin loads from your account, or **Do not send**.
5. Click **Save**.

## Manage the Payment Types

The **Payment types** section links a Medusa payment provider to a CRM payment type. The CRM requires a type on every payment, so without a mapping the plugin uses the payment type your account marks as the default for the API. Payment types that belong to a CRM payment module, such as an online acquiring module, are not offered, because the CRM doesn't allow editing their payments through the API.

To add a mapping:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Payment types** section, click **Add**.
3. In the side panel that opens, choose the Medusa payment provider.
4. Choose the CRM payment type, or **Do not send** to keep this provider's payments out of the CRM.
5. Click **Save**.

## Manage the Delivery Types

The **Delivery types** section links a Medusa shipping option to a CRM delivery type. Without a mapping the delivery goes to the CRM with its cost and address but without a type. The same mapping works in the other direction: when a manager changes the delivery type in the CRM, the plugin replaces the shipping method of the Medusa order with the mapped shipping option.

To add a mapping:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Delivery types** section, click **Add**.
3. In the side panel that opens, choose the Medusa shipping option.
4. Choose the CRM delivery type, or **Do not send**.
5. Click **Save**.

## Edit the Payment Statuses

The **Payment statuses** section holds the two CRM payment status codes the plugin sets:

- **Paid status code** – the status a CRM payment gets when the payment is captured in Medusa. The default is `paid`. The connection test requires this status to be marked as payment complete in the CRM.
- **Unpaid status code** – the status a CRM payment gets when the payment is fully refunded in Medusa. The default is `not-paid`.

To edit the payment statuses:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Payment statuses** section, click the action menu in the section header.
3. Choose **Edit**.
4. In the side panel that opens, enter the codes.
5. Click **Save**.

## Edit the Changes from the CRM

The **Changes from the CRM** section decides how often the plugin reads the CRM history and what it applies:

- **Poll interval, minutes** – how often the plugin reads the change history. The default is five minutes.
- **Apply item, delivery and address edits** – on by default. Items, delivery and address changed in the CRM become an order edit in Medusa. When off, the plugin only records them in the order's metadata.
- **Import orders created in the CRM** – on by default. An order a manager creates in the CRM appears in Medusa, and the CRM gets the Medusa order ID back.
- **Order methods to import** – CRM order method codes separated by commas, such as `phone, shopping-cart`. Empty means every method.
- **Cancel orders from the CRM** – off by default. When on, a CRM status from the `cancel` group cancels the order in Medusa. Cancellation can't be undone, and an order with an open fulfillment stays as it is.
- **Complete orders from the CRM** – off by default. When on, a CRM status from the `complete` group completes the order in Medusa.
- **Capture manual payments from the CRM** – off by default. When on, a paid status in the CRM captures the order's payment made through Medusa's system payment provider. Payments of other providers are never captured from the CRM.

To edit the section:

1. Go to **Settings → Integrations → RetailCRM**.
2. In the **Changes from the CRM** section, click the action menu in the section header.
3. Choose **Edit**.
4. In the side panel that opens, set the interval and the switches.
5. Click **Save**.
