В этом руководстве вы узнаете, как управлять настройками интеграции с RetailCRM.

## Просмотр данных RetailCRM

Чтобы открыть страницу настроек RetailCRM:

1. Откройте Medusa Admin.
2. Перейдите в **Настройки → Интеграции → RetailCRM**.

Откроется страница настроек со статусом интеграции, секциями **Подключение**, **Статусы оплаты** и **Изменения из CRM** и тремя секциями, которые добавляет плагин, **Статусы заказа**, **Типы оплаты** и **Типы доставки**.

## Редактирование подключения

Секция **Подключение** содержит четыре обязательных поля:

- **Адрес аккаунта** – адрес вашего аккаунта, например `https://example.retailcrm.ru`. Принимается только `https`.
- **Ключ API** – ключ API из раздела **Настройки → Интеграция → Ключи API** в CRM с правами `order_read`, `order_write`, `customer_read`, `customer_write` и `reference_read`.
- **Код магазина** – код магазина CRM, в который пишет этот инстанс. Один инстанс это один магазин, и каждый запрос к CRM несёт этот код.
- **ID канала продаж** – канал продаж Medusa, заказы которого уходят в этот магазин. Заказы других каналов этот инстанс не трогает.

Чтобы отредактировать подключение:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Подключение** откройте меню действий в заголовке секции.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели заполните четыре поля.
5. Нажмите **Сохранить**.

## Проверка соединения

Проверка соединения обращается к CRM. Она проверяет, что у ключа API есть все пять прав, что он покрывает код магазина, что магазин есть в аккаунте и что каждый код в настройках статусов, типов оплаты, типов доставки и статусов оплаты это активная запись соответствующего справочника CRM. Результат называет всё недостающее одним сообщением, так что настройки правятся за один заход.

Чтобы проверить соединение:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. Откройте меню действий рядом с названием интеграции.
3. Выберите **Проверить соединение**.

Результат появится в уведомлении. Адрес вне доменов `retailcrm.ru`, `simla.com` и `retailcrm.pro` проходит проверку с предупреждением в сообщении.

## Управление статусами заказа

Секция **Статусы заказа** связывает событие заказа в Medusa со статусом CRM, который получает заказ. Плагин отправляет статус при оформлении, завершении и отмене заказа. Смены статуса менеджером в CRM возвращаются по группе статуса, как описано в разделе [Редактирование изменений из CRM](#редактирование-изменений-из-crm), поэтому коды здесь влияют только на то, что отправляет Medusa.

По умолчанию это `new` для оформленного заказа, `complete` для завершённого и `cancel-other` для отменённого, стандартные коды аккаунта RetailCRM. Событие, сопоставленное с **Не отправлять**, не передаёт заказ в CRM, когда оно происходит.

Чтобы добавить или изменить соответствие:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Статусы заказа** нажмите **Добавить** или откройте меню действий в строке и выберите **Редактировать**.
3. В открывшейся боковой панели выберите событие Medusa.
4. Выберите статус CRM из списка, который плагин загружает из вашего аккаунта, или **Не отправлять**.
5. Нажмите **Сохранить**.

## Управление типами оплаты

Секция **Типы оплаты** связывает провайдера оплаты Medusa с типом оплаты CRM. CRM требует тип у каждого платежа, поэтому без соответствия плагин берёт тип оплаты, который ваш аккаунт отмечает как умолчание для API. Типы оплаты, принадлежащие платёжному модулю CRM, например модулю интернет-эквайринга, не предлагаются, потому что CRM не позволяет править их платежи через API.

Чтобы добавить соответствие:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Типы оплаты** нажмите **Добавить**.
3. В открывшейся боковой панели выберите провайдера оплаты Medusa.
4. Выберите тип оплаты CRM или **Не отправлять**, чтобы платежи этого провайдера не уходили в CRM.
5. Нажмите **Сохранить**.

## Управление типами доставки

Секция **Типы доставки** связывает опцию доставки Medusa с типом доставки CRM. Без соответствия доставка уходит в CRM со стоимостью и адресом, но без типа. То же соответствие работает и в обратную сторону: когда менеджер меняет тип доставки в CRM, плагин заменяет способ доставки заказа Medusa на сопоставленную опцию доставки.

Чтобы добавить соответствие:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Типы доставки** нажмите **Добавить**.
3. В открывшейся боковой панели выберите опцию доставки Medusa.
4. Выберите тип доставки CRM или **Не отправлять**.
5. Нажмите **Сохранить**.

## Редактирование статусов оплаты

Секция **Статусы оплаты** содержит два кода статусов оплаты CRM, которые ставит плагин:

- **Код статуса «оплачен»** – статус, который получает платёж CRM при захвате платежа в Medusa. По умолчанию `paid`. Проверка соединения требует, чтобы этот статус был отмечен в CRM как «заказ оплачен».
- **Код статуса «не оплачен»** – статус, который получает платёж CRM при полном возврате платежа в Medusa. По умолчанию `not-paid`.

Чтобы отредактировать статусы оплаты:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Статусы оплаты** откройте меню действий в заголовке секции.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели введите коды.
5. Нажмите **Сохранить**.

## Редактирование изменений из CRM

Секция **Изменения из CRM** определяет, как часто плагин читает историю CRM и что применяет:

- **Интервал опроса, минут** – как часто плагин читает историю изменений. По умолчанию пять минут.
- **Применять правки позиций, доставки и адреса** – включено по умолчанию. Изменённые в CRM позиции, доставка и адрес становятся правкой заказа в Medusa. Когда выключено, плагин только записывает их в метаданные заказа.
- **Заводить заказы, созданные в CRM** – включено по умолчанию. Заказ, который менеджер завёл в CRM, появляется в Medusa, а CRM получает идентификатор заказа Medusa обратно.
- **Способы оформления для заведения** – коды способов оформления CRM через запятую, например `phone, shopping-cart`. Пусто значит все способы.
- **Отменять заказы из CRM** – выключено по умолчанию. Когда включено, статус CRM из группы `cancel` отменяет заказ в Medusa. Отмену нельзя отменить, а заказ с незакрытой отгрузкой остаётся как есть.
- **Завершать заказы из CRM** – выключено по умолчанию. Когда включено, статус CRM из группы `complete` завершает заказ в Medusa.
- **Захватывать ручные платежи из CRM** – выключено по умолчанию. Когда включено, статус «оплачен» в CRM захватывает платёж заказа, сделанный через системный провайдер оплаты Medusa. Платежи других провайдеров из CRM не захватываются никогда.

Чтобы отредактировать секцию:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Изменения из CRM** откройте меню действий в заголовке секции.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели задайте интервал и переключатели.
5. Нажмите **Сохранить**.
