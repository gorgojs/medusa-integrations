# {frontmatter.title}

В этом руководстве вы узнаете, как управлять настройками интеграции с RetailCRM.

## Просмотр данных RetailCRM

Чтобы открыть страницу настроек RetailCRM:

1. Откройте Medusa Admin.
2. Перейдите в **Настройки → Интеграции → RetailCRM**.

Откроется страница настроек. В левой колонке находятся статус интеграции, секции **Подключение** и **Изменения из CRM** и таблицы **Статусы заказа**, **Типы оплаты** и **Типы доставки**. В правой колонке находятся карточки **Канал продаж**, **Статусы оплаты** и **Способы оформления**.

Статусы, типы и способы оформления CRM плагин загружает из вашего аккаунта, как только в подключении сохранены адрес, ключ API и код магазина. Включать интеграцию для этого не нужно. Если запись удалена в Medusa или больше недоступна в CRM, рядом с ней стоит пометка **Нет в Medusa** или **Нет в CRM**.

## Редактирование подключения

Секция **Подключение** содержит три обязательных поля:

- **Адрес RetailCRM** – адрес вашей RetailCRM или Simla.com, например `https://example.retailcrm.ru`. Принимается только `https`.
- **Ключ API** – ключ API из раздела **Настройки → Интеграция → Ключи API** в CRM с правами `order_read`, `order_write`, `customer_read`, `customer_write` и `reference_read`.
- **Код магазина** – символьный код магазина в RetailCRM. Один инстанс работает с одним магазином.

Чтобы отредактировать подключение:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Подключение** откройте меню действий в заголовке секции.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели заполните три поля.
5. Нажмите **Сохранить**.

## Выбор канала продаж

Карточка **Канал продаж** задаёт канал продаж Medusa, с которым работает этот инстанс. Заказы этого канала уходят в магазин CRM, а заказы, созданные в CRM, попадают в этот канал. Заказы других каналов инстанс не трогает. Без канала продаж интеграция считается настроенной не полностью.

Если тот же канал выбран в другом инстансе RetailCRM, карточка показывает предупреждение. Заказ уходит в один инстанс по своему каналу, поэтому второй инстанс с тем же каналом заказов не получит.

Чтобы выбрать канал продаж:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В карточке **Канал продаж** откройте меню действий в заголовке карточки.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели выберите канал продаж. Канал, который уже выбран в другом инстансе RetailCRM, отмечен в списке.
5. Нажмите **Сохранить**.

## Проверка соединения

Проверка соединения обращается к CRM. Она проверяет, что у ключа API есть все пять прав, что ключ даёт доступ к магазину с этим кодом и что такой магазин есть в аккаунте. Затем она сверяет коды из настроек со справочниками CRM:

- статусы заказа, типы оплаты, типы доставки и статусы оплаты должны быть активными записями справочников;
- типы оплаты и доставки должны быть доступны магазину этого инстанса;
- тип оплаты не должен принадлежать платёжному модулю CRM;
- статус **Оплачен** должен быть отмечен в CRM как завершённая оплата.

Пункт **Проверить соединение** появляется, когда интеграция настроена полностью и включена.

Чтобы проверить соединение:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. Откройте меню действий рядом с названием интеграции.
3. Если интеграция ещё выключена, выберите **Включить** и снова откройте меню.
4. Выберите **Проверить соединение**.

Если проверка прошла, в уведомлении написано **Соединение установлено**. Если нет, уведомление перечисляет всё, чего не хватает, поэтому настройки можно исправить за один раз. Адрес вне доменов `retailcrm.ru`, `simla.com` и `retailcrm.pro` проверка не отклоняет, поэтому такой адрес сверьте сами.

## Управление статусами заказа

Таблица **Статусы заказа** связывает событие заказа в Medusa со статусом CRM, который получает заказ. Плагин отправляет статус при оформлении, завершении и отмене заказа. Когда менеджер меняет статус заказа в CRM, плагин смотрит на группу статуса, а не на код, как описано в разделе [Редактирование изменений из CRM](#редактирование-изменений-из-crm). Поэтому коды в этой таблице влияют только на то, что плагин отправляет.

По умолчанию заданы стандартные коды RetailCRM. Оформленный заказ получает `new`, завершённый `complete`, отменённый `cancel-other`. Если событие сопоставлено с **Не отправлять**, плагин не передаёт заказ в CRM, когда оно происходит. Для события без соответствия плагин отправляет заказ без статуса, и новый заказ получает статус CRM по умолчанию.

Чтобы добавить или изменить соответствие:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В таблице **Статусы заказа** нажмите **Добавить** или откройте меню действий в строке и выберите **Редактировать**.
3. В открывшейся боковой панели выберите **Событие в Medusa**.
4. Выберите **Статус в CRM** из списка, который плагин загружает из вашего аккаунта, или **Не отправлять**.
5. Нажмите **Сохранить**.

## Управление типами оплаты

Таблица **Типы оплаты** связывает провайдера оплаты Medusa с типом оплаты CRM. Системный провайдер Medusa `pp_system_default` называется в списке **Ручная оплата**, названия остальных плагин собирает из их идентификаторов. Выключенные провайдеры для новой строки не предлагаются.

CRM требует тип у каждого платежа, поэтому без соответствия плагин берёт тип оплаты, заданный в аккаунте по умолчанию для API, и показывает его название под таблицей. Если такого типа нет или он закрыт для магазина этого инстанса, платежи провайдеров без соответствия в CRM не уходят.

Типы оплаты, принадлежащие платёжному модулю CRM, например модулю интернет-эквайринга, не предлагаются, потому что CRM не позволяет править их платежи через API. Не предлагаются и типы, закрытые для магазина этого инстанса.

Чтобы добавить или изменить соответствие:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В таблице **Типы оплаты** нажмите **Добавить** или откройте меню действий в строке и выберите **Редактировать**.
3. В открывшейся боковой панели выберите **Провайдер оплаты**.
4. Выберите **Тип в CRM** или **Не отправлять**, чтобы платежи этого провайдера не уходили в CRM.
5. Нажмите **Сохранить**.

## Управление типами доставки

Таблица **Типы доставки** связывает тип способов доставки Medusa с типом доставки CRM. Типы вы задаёте в Medusa Admin в разделе **Настройки → Локации и доставка → Типы способов доставки**, а тип способа доставки выбираете при его создании или редактировании. Соответствие задаётся по коду типа, поэтому одна строка действует для способов этого типа во всех зонах доставки. Типы с одинаковым кодом в списке представлены одной записью.

Плагин передаёт в CRM тип доставки по типу способа доставки заказа. Если тип не сопоставлен или сопоставлен с **Без типа**, доставка уходит в CRM со стоимостью и адресом, но без типа. Типы доставки CRM, закрытые для магазина этого инстанса, не предлагаются.

Соответствие работает и в обратную сторону. Когда менеджер меняет тип доставки в CRM, плагин ставит заказу способ доставки сопоставленного типа из той же зоны, что и текущий способ. Если у заказа нет способа доставки Medusa, плагин ищет способ в зоне, которая покрывает страну адреса доставки. Это работает, пока включён переключатель **Применять правки заказов**. Если подходящего способа нет, доставка не меняется, а тип доставки CRM записывается в метаданные заказа.

Заказ, созданный в CRM, получает способ доставки сопоставленного типа из зоны, которая покрывает страну адреса. Если такого способа нет, заказ получает доставку со стоимостью из CRM, но без способа доставки Medusa. Позднее изменение только стоимости такой доставки плагин записывает лишь в метаданные.

Чтобы добавить или изменить соответствие:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В таблице **Типы доставки** нажмите **Добавить** или откройте меню действий в строке и выберите **Редактировать**.
3. В открывшейся боковой панели выберите **Тип в Medusa**.
4. Выберите **Тип в CRM** или **Без типа**.
5. Нажмите **Сохранить**.

## Редактирование статусов оплаты

Карточка **Статусы оплаты** задаёт статусы оплаты CRM, которые плагин ставит платежу:

- **Оплачен** – статус захваченного платежа. Плагин ставит его при захвате платежа в Medusa и при первой отправке заказа с уже захваченным платежом. По умолчанию `paid`. В списке только статусы, которые CRM считает завершённой оплатой.
- **Не оплачен** – статус платежа, который ещё не захвачен или возвращён полностью. Плагин ставит его при первой отправке заказа с незахваченным платежом и при полном возврате платежа в Medusa. По умолчанию `not-paid`. В списке только статусы, которые CRM не считает завершённой оплатой. Частичный возврат статус не меняет. Плагин только добавляет платежу комментарий.

Чтобы отредактировать статусы оплаты:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В карточке **Статусы оплаты** откройте меню действий в заголовке карточки.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели выберите оба статуса.
5. Нажмите **Сохранить**.

## Редактирование изменений из CRM

Секция **Изменения из CRM** определяет, как часто плагин читает историю CRM и что применяет:

- **Интервал опроса, мин** – как часто плагин читает историю изменений. По умолчанию пять минут.
- **Применять правки заказов** – включено по умолчанию. Изменённые в CRM позиции и доставка становятся правкой заказа в Medusa. Когда выключено, плагин только записывает их в метаданные заказа. Адрес доставки, email и покупатель заказа меняются в Medusa при любом положении переключателя.
- **Создавать новые заказы** – включено по умолчанию. Заказ, который менеджер оформил в CRM, появляется в Medusa, а в заказ CRM записывается идентификатор заказа Medusa. Карточка [Способы оформления](#выбор-способов-оформления) ограничивает создание выбранными способами.
- **Отменять заказы** – выключено по умолчанию. Когда включено, статус CRM из группы `cancel` отменяет заказ в Medusa. Отмена необратима. Завершённый заказ и заказ с неотменённой отгрузкой плагин не отменяет.
- **Завершать заказы** – выключено по умолчанию. Когда включено, статус CRM из группы `complete` завершает заказ в Medusa.
- **Захватывать ручные платежи** – выключено по умолчанию. Когда включено, статус завершённой оплаты в CRM захватывает платёж заказа, сделанный через системный провайдер оплаты Medusa, а оплаченный платёж CRM без пары в Medusa отмечает неоплаченную платёжную коллекцию заказа как оплаченную. Платежи других провайдеров плагин не захватывает никогда.

Чтобы отредактировать секцию:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В секции **Изменения из CRM** откройте меню действий в заголовке секции.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели задайте интервал и переключатели.
5. Нажмите **Сохранить**.

## Выбор способов оформления

В карточке **Способы оформления** вы выбираете способы оформления CRM, заказы которых плагин создаёт в Medusa. Список способов плагин загружает из вашего аккаунта. Если ничего не выбрано, в карточке написано **Все способы**, и плагин создаёт заказы всех способов. Карточка видна, пока включён переключатель **Создавать новые заказы**.

Чтобы выбрать способы оформления:

1. Перейдите в **Настройки → Интеграции → RetailCRM**.
2. В карточке **Способы оформления** откройте меню действий в заголовке карточки.
3. Выберите **Редактировать**.
4. В открывшейся боковой панели отметьте нужные способы или снимите все отметки, чтобы создавать заказы всех способов.
5. Нажмите **Сохранить**.
