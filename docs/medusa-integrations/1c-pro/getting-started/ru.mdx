# {frontmatter.title}

В этой документации вы узнаете, как установить плагин 1С:Предприятие, подключить его к Medusa и настроить обмен в 1С.

<Note type="success" title="Плагин доступен участникам бета-тестирования">

Плагин публикуется в закрытом реестре пакетов Gorgo. Чтобы установить его, [подайте заявку на бету](https://gorgojs.ru/beta/medusa-1c). После одобрения заявки вы получите токен доступа к реестру.

</Note>

## Требования

- Medusa v2.17.2 или новее
- Node.js v20 или новее
- [Модуль интеграций](/medusa-modules/integration) v0.1.4 или новее
- Токен доступа к реестру пакетов Gorgo

---

## Установка

Пакеты `@gorgo-pro` находятся в реестре `registry.gorgojs.com`, а не в общем реестре npm. Укажите менеджеру пакетов этот реестр для пакетов `@gorgo-pro` и передайте ему токен. Yarn начиная со второй версии берёт настройки из `.yarnrc.yml`, npm из `.npmrc`:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```yaml title=".yarnrc.yml"
    npmScopes:
      gorgo-pro:
        npmRegistryServer: "https://registry.gorgojs.com"
        npmAuthToken: "${GORGO_TOKEN}"
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```text title=".npmrc"
    @gorgo-pro:registry=https://registry.gorgojs.com/
    //registry.gorgojs.com/:_authToken=${GORGO_TOKEN}
    ```
  </CodeTab>
</CodeTabs>

Токен оба файла берут из переменной окружения `GORGO_TOKEN`, так что в репозиторий проекта он не попадает. Задайте эту переменную везде, где ставятся зависимости, то есть на своей машине и в CI.

Установите плагин вместе с Модулем интеграций:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn add @gorgo/medusa-integration @gorgo-pro/medusa-erp-1c@0.1.0-beta.1
    ```
  </CodeTab>
  <CodeTab label="npm" value="npm">
    ```bash
    npm install @gorgo/medusa-integration @gorgo-pro/medusa-erp-1c@0.1.0-beta.1
    ```
  </CodeTab>
</CodeTabs>

## Настройка

Добавьте конфигурацию плагина в `medusa-config.ts` вашего приложения Medusa:

```ts title="medusa-config.ts"
// ...

module.exports = defineConfig({
  // ...
  plugins: [
    // ...
    {
      resolve: "@gorgo/medusa-integration",
      options: {
        providers: [
          {
            resolve: "@gorgo-pro/medusa-erp-1c/providers/integration-1c",
            options: {},
          },
        ],
      },
    },
    {
      resolve: "@gorgo-pro/medusa-erp-1c",
      options: {},
    },
  ],
})
```

Первая запись регистрирует провайдера 1С в Модуле интеграций, и его настройки появляются в Medusa Admin. Вторая подключает сам плагин с адресом обмена для 1С, виджетами панели администратора и воркфлоу обмена.

<Note type="default" title="">

Параметров в `medusa-config` у плагина нет. Канал продаж, регион, типы цен и остальное вы задаёте в Medusa Admin, как описано на странице [Настройка в Medusa Admin](/medusa-integrations/1c-pro/settings). Секретных полей у плагина тоже нет, поэтому `encryptionKey` Модулю интеграций ради него задавать не нужно.

</Note>

## Миграция

Модуль интеграций хранит настройки в своих таблицах. Выполните следующую команду, чтобы применить миграции базы данных:

<CodeTabs>
  <CodeTab label="yarn" value="yarn">
    ```bash
    yarn medusa db:migrate
    ```
  </CodeTab>
  <CodeTab label="npx" value="npx">
    ```bash
    npx medusa db:migrate
    ```
  </CodeTab>
</CodeTabs>

## Настройка обмена в 1С

Обмен запускает 1С. В настройках обмена с сайтом в вашей конфигурации 1С укажите:

- **Адрес сайта** – `https://<адрес бэкенда Medusa>/hooks/erp/1c`
- **Пользователь** – email пользователя Medusa Admin
- **Пароль** – пароль этого пользователя

Плагин проверяет логин и пароль так же, как Medusa Admin при входе. Заведите для обмена отдельного пользователя, чтобы в 1С не хранился пароль сотрудника и чтобы этого пользователя можно было удалить или сменить пароль, не задев остальных.

Сжатие и размер частей настраивать не нужно. Плагин сам сообщает 1С, что принимает zip-архивы и части файла до 1 МБ. Из полученных файлов он сначала импортирует каталог (`import*.xml`), затем предложения (`offers*.xml`) и заказы (`orders*.xml`).

<Note type="warning">

Плагин хранит сессию обмена в памяти процесса Medusa. Если сервер перезапустится посреди обмена, обмен прервётся, и его придётся повторить. Если бэкенд запущен в нескольких инстансах, направьте все запросы к `/hooks/erp/1c` на один из них. Иначе запрос, попавший на другой инстанс, получит отказ авторизации, хотя логин и пароль верны.

</Note>

## Журнал обмена

Записи обмена в журнале Medusa начинаются с `[1C Integration]`. После каждой пачки каталога и предложений плагин пишет строку прогресса:

```
[1C Integration] import: progress catalog 40% (200/500 products, batch 2/5)
```

Плагин фиксирует пачки по одной, и прерванный обмен оставляет записанными те, что успели пройти. Повторять обмен целиком безопасно, потому что товары сопоставляются по `Ид` 1С, а варианты по SKU.

Когда обмен завершается ошибкой, 1С получает ответ `failure` с причиной, и та же причина попадает в журнал. Длительность каждого шага импорта видна на уровне `debug`, например с переменной окружения `LOG_LEVEL=debug`.
