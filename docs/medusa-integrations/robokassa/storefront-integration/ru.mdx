# {frontmatter.title}

Для интеграции платёжного провайдера Robokassa в storefront [Medusa DTC Starter от Gorgo](https://github.com/gorgojs/medusa-dtc-starter) начните с добавления необходимых UI-компонентов. Таким образом провайдер будет отображаться на странице оформления заказа наряду с другими доступными методами оплаты.

Когда покупатель выбирает Robokassa, оформление заказа инициализирует платёжную сессию, а провайдер создаёт её на своей стороне и возвращает адрес для оплаты. Кнопка оплаты отправляет покупателя на эту страницу, где он может заплатить картой или через СБП.

После завершения оплаты Robokassa одновременно отправляет вебхук и перенаправляет покупателя обратно в витрину.

Для витрины на Next.js необходимо внести следующие изменения:

## Шаг 1: Настройте платёжный провайдер

Откройте [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-robokassa/apps/storefront/src/lib/constants.tsx#L56-L60) и добавьте Robokassa в маппинг платёжных провайдеров, а также вспомогательную функцию, распознающую её сессии:

![Структура проекта Medusa Storefront после обновления файла с константами](/static/robokassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
export type PaymentInfo = {
  title: string
  subtitle?: string
  icon: React.JSX.Element
}

export const paymentInfoMap: Record<string, PaymentInfo> = {
  // ...
  pp_robokassa_robokassa: {
    title: "Robokassa",
    subtitle: "Cards, SBP",
    icon: <Robokassa />,
  },
  // ...
}

// ...

export const isRobokassa = (providerId?: string) => {
  return providerId?.startsWith("pp_robokassa")
}
```

`title` называет способ оплаты на странице оформления заказа, а `subtitle` задаёт строку помельче под ним, куда попадают способы оплаты, которые принимает Robokassa. Оба служат резервными значениями, когда для локали нет перевода. `isRobokassa` использует диспетчер ниже и построитель данных платёжной сессии из следующего шага.

Компонент для `icon` вы добавляете сами. В примере стрелка Robokassa нарисована тёмно-серой, а не фирменным бело-на-тёмном-квадрате знаком, поскольку тёмный знак сам по себе лучше читается на светлой рамке, которую рисует вокруг него страница оформления заказа:

```tsx title="src/modules/common/icons/robokassa.tsx"
import type React from "react"

import type { IconProps } from "types/icon"

const Robokassa: React.FC<IconProps> = ({
  size = "16",
  color: _color,
  ...attributes
}) => {
  return (
    <svg
      width={size}
      height={size}
      viewBox="54 129 404 254"
      role="img"
      fill="none"
      xmlns="http://www.w3.org/2000/svg"
      {...attributes}
    >
      <title>Robokassa icon</title>
      <path d="M239 129L54 383H274L458 129H239Z" fill="#333339" />
    </svg>
  )
}

export default Robokassa
```

## Шаг 2: Инициализируйте платёжную сессию

Откройте тот же файл [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-robokassa/apps/storefront/src/lib/constants.tsx#L76-L114) и добавьте вспомогательную функцию активной локали, адрес возврата и построитель данных сессии:

![Структура проекта Medusa Storefront после обновления файла с константами](/static/robokassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
/**
 * Локаль, в которой отображалось оформление заказа. `<html lang>` хранит её,
 * поэтому страница оплаты и возврат с неё остаются на том языке, на котором
 * покупатель ушёл из магазина.
 */
const activeLocale = () =>
  typeof document === "undefined"
    ? defaultLocale
    : document.documentElement.lang || defaultLocale

const paymentReturnUrl = (providerId: string, cartId: string) => {
  const origin =
    typeof window === "undefined" ? getBaseURL() : window.location.origin

  return `${origin}/api/payment-return?provider=${providerId}&cart_id=${cartId}&locale=${activeLocale()}`
}

const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isRobokassa(providerId),
    // Robokassa формирует чек из корзины и берёт из неё адрес покупателя.
    // Инициализация сессии до того, как оформление заказа собрало эти данные,
    // создаёт платёж без чека.
    isReady: (cart) => Boolean(cart.email && cart.shipping_address),
    build: (cart) => {
      const returnUrl = paymentReturnUrl("robokassa", cart.id)

      return {
        SuccessUrl2: returnUrl,
        SuccessUrl2Method: "GET",
        FailUrl2: returnUrl,
        FailUrl2Method: "GET",
        EMail: cart.email,
        // Собственная страница оплаты Robokassa говорит по-русски или по-английски.
        Culture: activeLocale() === "ru" ? "ru" : "en",
        cart,
      }
    },
  },
]
```

Robokassa нужна активная локаль не только для адреса возврата, поэтому она вынесена в отдельную функцию `activeLocale`, а не встроена напрямую. `build` передаёт `SuccessUrl2` и `FailUrl2`, оба указывающие на один и тот же адрес возврата, их `Method`, email покупателя в `EMail`, `Culture` для языка, на котором откроется собственная страница оплаты Robokassa, и `cart` для формирования чека. `isReady` удерживает сессию, пока в корзине не появятся email и адрес доставки.

## Шаг 3: Создайте кнопку оплаты

Создайте файл [`src/modules/checkout/components/payment-button/providers/robokassa.tsx`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-robokassa/apps/storefront/src/modules/checkout/components/payment-button/providers/robokassa.tsx):

![Структура проекта Medusa Storefront после создания файла для кнопки оплаты Robokassa](/static/robokassa/storefront/src-modules-checkout-components-payment-button-providers-robokassa.webp)

```ts title="src/modules/checkout/components/payment-button/providers/robokassa.tsx"
"use client"

import type { HttpTypes } from "@medusajs/types"
import { useTranslations } from "next-intl"
import { useState } from "react"
import { PaymentButtonShell, type PaymentProviderButtonProps } from "../shared"

const paymentUrl = (cart: HttpTypes.StoreCart) => {
  const session = cart.payment_collection?.payment_sessions?.find((s) =>
    s.provider_id.startsWith("pp_robokassa")
  )

  return (session?.data as { paymentUrl?: string } | undefined)?.paymentUrl
}

/**
 * Robokassa принимает оплату на собственной странице. Сессия, созданная
 * оформлением заказа, хранит подписанный адрес, куда отправить покупателя, а
 * заказ оформляется, когда он вернётся через `/api/payment-return`, либо по
 * вебхуку, если тот придёт раньше.
 */
const RobokassaPaymentButton = ({
  cart,
  notReady,
  label,
  cartUpdating,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) => {
  const t = useTranslations("Errors")
  const [submitting, setSubmitting] = useState(false)
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  const handlePayment = () => {
    const url = paymentUrl(cart)

    if (!url) {
      setErrorMessage(t("paymentFailed"))
      return
    }

    setSubmitting(true)
    window.location.assign(url)
  }

  return (
    <PaymentButtonShell
      label={label}
      onClick={handlePayment}
      disabled={notReady}
      loading={submitting || cartUpdating}
      errorMessage={errorMessage}
      errorTestId="robokassa-payment-error-message"
      data-testid={dataTestId ?? "submit-order-button"}
    />
  )
}

export default RobokassaPaymentButton
```

Этот компонент находит `payment_session` Robokassa в активной корзине и извлекает `data.paymentUrl`. При нажатии `handlePayment` отправляет покупателя туда напрямую через `window.location.assign`, поскольку страница Robokassa не встраивается в витрину.

Если `paymentUrl` отсутствует, кнопка показывает сообщение об ошибке вместо перехода.

## Шаг 5: Обработайте возврат с оплаты

Robokassa сообщает статус платежа и через вебхук, и через этот редирект, поэтому общий роут проверяет, есть ли у корзины заказ, прежде чем оформлять его сам.

Откройте [`src/app/api/payment-return/route.ts`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-robokassa/apps/storefront/src/app/api/payment-return/route.ts#L29-L80) и добавьте следующую функцию:

![Структура проекта Medusa Storefront после создания файла для API route](/static/robokassa/storefront/src-app-api-payment-return-route.webp)

```ts title="src/app/api/payment-return/route.ts"
type ReturnContext = {
  cartId: string
  locale: string
  origin: string
}

/**
 * Обрабатывает возврат от провайдера, который принимает оплату на собственной
 * странице и возвращает покупателя только с идентификатором корзины —
 * Robokassa в их числе.
 *
 * Вебхук провайдера и этот редирект соревнуются друг с другом, и какой из них
 * ни пришёл бы первым, он оформляет заказ, поэтому перед оформлением
 * проверяется, нет ли у корзины уже заказа.
 */
async function redirectProviderReturn({
  cartId,
  locale,
  origin,
}: ReturnContext) {
  const cart = await sdk.client
    .fetch<HttpTypes.StoreCartResponse>(`/store/carts/${cartId}`, {
      method: "GET",
      query: { fields: "id,order_link.order_id" },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    })
    .then(({ cart }) => cart)
    .catch(() => null)

  if (!cart) {
    return NextResponse.redirect(
      `${origin}/${locale}/cart?error=payment_failed`
    )
  }

  const orderId = (cart as unknown as { order_link?: { order_id?: string } })
    .order_link?.order_id

  if (orderId) {
    const orderCacheTag = await getCacheTag("orders")
    revalidateTag(orderCacheTag)
    await removeCartId()

    return NextResponse.redirect(
      `${origin}/${locale}/order/${orderId}/confirmed`
    )
  }

  // Покупатель отменил оплату, либо она была отклонена, поэтому он возвращается
  // на страницу оформления заказа с нетронутой корзиной и может выбрать способ
  // оплаты заново.
  await setCartId(cartId)

  try {
    await placeOrder(cartId)
  } catch (error) {
    unstable_rethrow(error)

    return NextResponse.redirect(
      `${origin}/${locale}/checkout?error=payment_failed`
    )
  }

  return NextResponse.redirect(
    `${origin}/${locale}/checkout?error=payment_failed`
  )
}
```

Затем направьте возврат Robokassa в эту функцию прямо в `GET`:

```ts title="src/app/api/payment-return/route.ts"
  if (provider === "robokassa") {
    return redirectProviderReturn({ cartId, locale, origin })
  }
```

Если у корзины уже есть заказ, в гонке победил вебхук, и роут обновляет кэш заказа и отправляет покупателя на страницу подтверждения. Иначе он пытается оформить заказ сам, а при любой ошибке отправляет покупателя обратно на оформление заказа с `error=payment_failed`, чтобы он мог выбрать способ оплаты заново.

## Шаг 6: Добавьте подписи провайдера в локали витрины

Добавьте `pp_robokassa_robokassa` в [`messages/en.json`](https://github.com/gorgojs/medusa-integrations/blob/5c7c2f15ccfb90f15d5d94abe7d303137550a421/examples/payment-robokassa/apps/storefront/messages/en.json#L514) и в каждую другую локаль под `messages/`:

```json title="messages/en.json"
{
  "PaymentMethods": {
    // ...
    "pp_robokassa_robokassa": {
      "title": "Robokassa",
      "subtitle": "Cards, SBP"
    }
  }
}
```

Если для локали нет записи, используются английские `title` и `subtitle` из `paymentInfoMap` в [Шаге 1](#шаг-1-настройте-платёжный-провайдер), а способ оплаты без подписи отрисовывается одним названием. Собственное название Robokassa не меняется от локали к локали, за исключением русской, где это `Робокасса`. Подпись переводится наравне с любой другой строкой, поэтому в русской локали она читается как `Карты, СБП`.
