# {frontmatter.title}

To integrate the Robokassa payment provider into the [Medusa DTC Starter by Gorgo](https://github.com/gorgojs/medusa-dtc-starter) storefront, start by adding the required UI components, so the provider is displayed on the checkout page alongside other available payment methods.

When the customer selects Robokassa, the checkout initiates a payment session, and the provider creates it on Robokassa's side and returns the payment address. The payment button then sends the customer there, where they can choose a payment method.

Once the payment is completed, Robokassa concurrently sends a webhook and redirects the customer back to the storefront. Whichever event arrives first completes the cart and creates a new order in Medusa.

For the storefront on Next.js, you need to make the following changes:

## Step 1: Configure Payment Provider

To make Robokassa available as a payment method on the storefront checkout page, you must add its configuration to the payment provider mapping in your storefront's constants file. This mapping determines how each payment provider is displayed in the UI.

Open [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-robokassa/apps/storefront/src/lib/constants.tsx#L56-L60) and add the following code:

![Directory structure in the Medusa Storefront after updating the file for constants](/static/robokassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
export type PaymentInfo = {
  title: string
  subtitle?: string
  icon: React.JSX.Element
}

export const paymentInfoMap: Record<string, PaymentInfo> = {
  // ...
  pp_robokassa_robokassa: {
    title: "Robokassa",
    subtitle: "Cards, SBP",
    icon: <Robokassa />,
  },
  // ...
}

// ...

export const isRobokassa = (providerId?: string) => {
  return providerId?.startsWith("pp_robokassa")
}
```

You extend the `paymentInfoMap` object to include a `pp_robokassa_robokassa` entry. This entry defines the title, the subtitle, and the icon that will be shown for Robokassa on the checkout page, and also serves as the fallback when a locale carries no translation.

The helper function `isRobokassa` checks whether a given `providerId` belongs to Robokassa. It's used by the dispatcher below and by the session data builder in the next step.

Add the `icon` component for Robokassa:

```tsx title="src/modules/common/icons/robokassa.tsx"
import type React from "react"

import type { IconProps } from "types/icon"

const Robokassa: React.FC<IconProps> = ({
  size = "16",
  color: _color,
  ...attributes
}) => {
  return (

      width={size}

      viewBox="54 129 404 254"
      role="img"
      fill="none"

      {...attributes}
    >
      <title>Robokassa icon</title>
      <path d="M239 129L54 383H274L458 129H239Z" fill="#333339" />
    </svg>

```

This component is passed as `icon: <Robokassa />` in the `paymentInfoMap` entry. It displays the icon for the Robokassa payment method on the checkout page.

## Step 2: Initialize Payment Session

To redirect a customer to Robokassa, the payment session must be properly initialized with the required parameters, including the return address for the post-payment callback and the shopping cart for generating receipts.

Open the same [`src/lib/constants.tsx`](https://github.com/gorgojs/medusa-integrations/blob/4db4c78b5af5a75285b9ed658192b6c6c818eeb6/examples/payment-robokassa/apps/storefront/src/lib/constants.tsx#L76-L114) and add the active locale helper, the return address and the session data builder:

![Directory structure in the Medusa Storefront after updating the file for constants](/static/robokassa/storefront/src-lib-constants.webp)

```ts title="src/lib/constants.tsx"
/**
 * The locale the checkout was rendered in. `<html lang>` carries it, so a
 * payment page and the return from it both stay in the language the customer
 * left the shop with.
 */
const activeLocale = () =>
  typeof document === "undefined"
    ? defaultLocale
    : document.documentElement.lang || defaultLocale

const paymentReturnUrl = (providerId: string, cartId: string) => {
  const origin =
    typeof window === "undefined" ? getBaseURL() : window.location.origin

  return `${origin}/api/payment-return?provider=${providerId}&cart_id=${cartId}&locale=${activeLocale()}`
}

const paymentSessionDataBuilders: Array<{
  test: (providerId?: string) => boolean | undefined
  isReady?: (cart: HttpTypes.StoreCart) => boolean
  build: (cart: HttpTypes.StoreCart) => Record<string, unknown>
}> = [
  {
    test: (providerId) => isRobokassa(providerId),
    // Robokassa builds a receipt out of the cart and takes the buyer's address
    // for it. Initiating the session before the checkout collected them creates
    // a payment without one.
    isReady: (cart) => Boolean(cart.email && cart.shipping_address),
    build: (cart) => {
      const returnUrl = paymentReturnUrl("robokassa", cart.id)

      return {
        SuccessUrl2: returnUrl,
        SuccessUrl2Method: "GET",
        FailUrl2: returnUrl,
        FailUrl2Method: "GET",
        EMail: cart.email,
        // Robokassa's own payment page speaks Russian or English.
        Culture: activeLocale() === "ru" ? "ru" : "en",
        cart,
      }
    },
  },
]
```

Robokassa needs the active locale for more than the return address, so it's factored out into its own `activeLocale` helper rather than being inlined. `build` passes `SuccessUrl2` and `FailUrl2`, both pointing at the same return address, their `Method`, the buyer's `EMail`, and `Culture` for the language Robokassa's own payment page opens in.

Both addresses point to your storefront's `/api/payment-return` route and are used for both successful and failed payment attempts.

The `cart` object is included to build a receipt compliant with Federal Law No. 54.

`isReady` holds the session back until the cart carries an email and a shipping address, since the receipt needs the buyer's address.

## Step 3: Create Payment Button

The storefront needs a dedicated payment button component for each payment provider. Using the payment session data, it sends the customer to the Robokassa payment page. The order itself is placed later, when the customer comes back through `/api/payment-return`, or earlier through the webhook if that arrives first.

Create [`src/modules/checkout/components/payment-button/providers/robokassa.tsx`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-robokassa/apps/storefront/src/modules/checkout/components/payment-button/providers/robokassa.tsx) and add the following code:

![Directory structure in the Medusa Storefront after creating the file for the Robokassa payment button](/static/robokassa/storefront/src-modules-checkout-components-payment-button-providers-robokassa.webp)

```ts title="src/modules/checkout/components/payment-button/providers/robokassa.tsx"
"use client"

import type { HttpTypes } from "@medusajs/types"
import { useTranslations } from "next-intl"
import { useState } from "react"
import { PaymentButtonShell, type PaymentProviderButtonProps } from "../shared"

const paymentUrl = (cart: HttpTypes.StoreCart) => {
  const session = cart.payment_collection?.payment_sessions?.find((s) =>
    s.provider_id.startsWith("pp_robokassa")
  )

  return (session?.data as { paymentUrl?: string } | undefined)?.paymentUrl
}

/**
 * Robokassa collects the payment on its own page. The session the checkout
 * created carries the signed address to send the customer to, and the order is
 * placed once they come back through `/api/payment-return` — or by the webhook,
 * if that arrives first.
 */
const RobokassaPaymentButton = ({
  cart,
  notReady,
  label,
  cartUpdating,
  "data-testid": dataTestId,
}: PaymentProviderButtonProps) => {
  const t = useTranslations("Errors")
  const [submitting, setSubmitting] = useState(false)
  const [errorMessage, setErrorMessage] = useState<string | null>(null)

  const handlePayment = () => {
    const url = paymentUrl(cart)

    if (!url) {
      setErrorMessage(t("paymentFailed"))
      return
    }

    setSubmitting(true)
    window.location.assign(url)
  }

  return (
    <PaymentButtonShell
      label={label}
      onClick={handlePayment}
      disabled={notReady}
      loading={submitting || cartUpdating}
      errorMessage={errorMessage}
      errorTestId="robokassa-payment-error-message"
      data-testid={dataTestId ?? "submit-order-button"}
    />
  )
}

export default RobokassaPaymentButton
```

This component finds the Robokassa `payment_session` in the active cart and extracts the value of `data.paymentUrl`. When the customer clicks the payment button, they're redirected to this URL to complete the payment on the Robokassa page.

If `paymentUrl` is missing, the button shows an error message instead of navigating anywhere.

## Step 5: Handle Payment Return

After the customer completes payment on the Robokassa page, they're redirected back to the storefront. Robokassa reports the payment status through both this redirect and a webhook, so the shared route checks the cart for an order before placing one itself.

Open [`src/app/api/payment-return/route.ts`](https://github.com/gorgojs/medusa-integrations/blob/350802b8704d370bd65f634f1934bd1b642e7ab3/examples/payment-robokassa/apps/storefront/src/app/api/payment-return/route.ts#L29-L80) with the following content:

![Directory structure in the Medusa Storefront after creating the file for API route](/static/robokassa/storefront/src-app-api-payment-return-route.webp)

```ts title="src/app/api/payment-return/route.ts"
type ReturnContext = {
  cartId: string
  locale: string
  origin: string
}

/**
 * Comes back from a provider that takes the customer to its own payment page
 * and returns them with nothing but the cart id — Robokassa among them.
 *
 * The provider's webhook and this redirect race each other, and whichever
 * arrives first places the order, so the cart is checked for an order before
 * one is placed.
 */
async function redirectProviderReturn({
  cartId,
  locale,
  origin,
}: ReturnContext) {
  const cart = await sdk.client
    .fetch<HttpTypes.StoreCartResponse>(`/store/carts/${cartId}`, {
      method: "GET",
      query: { fields: "id,order_link.order_id" },
      headers: { ...(await getAuthHeaders()) },
      cache: "no-store",
    })
    .then(({ cart }) => cart)
    .catch(() => null)

  if (!cart) {
    return NextResponse.redirect(
      `${origin}/${locale}/cart?error=payment_failed`
    )
  }

  const orderId = (cart as unknown as { order_link?: { order_id?: string } })
    .order_link?.order_id

  if (orderId) {
    const orderCacheTag = await getCacheTag("orders")
    revalidateTag(orderCacheTag)
    await removeCartId()

    return NextResponse.redirect(
      `${origin}/${locale}/order/${orderId}/confirmed`
    )
  }

  // The customer backed out or the payment was declined, so they land back on
  // the checkout with their cart intact and can pick a method again.
  await setCartId(cartId)

  try {
    await placeOrder(cartId)
  } catch (error) {
    unstable_rethrow(error)

    return NextResponse.redirect(
      `${origin}/${locale}/checkout?error=payment_failed`
    )
  }

  return NextResponse.redirect(
    `${origin}/${locale}/checkout?error=payment_failed`
  )
}
```

Then route Robokassa's return to `redirectProviderReturn`, in `GET`:

```ts title="src/app/api/payment-return/route.ts"
  if (provider === "robokassa") {
    return redirectProviderReturn({ cartId, locale, origin })
  }
```

This route handles the return from Robokassa after a payment attempt. It always fetches the cart's latest state, uncached, so it doesn't miss changes made during payment.

If the cart already has an order, the confirmation already arrived through the webhook. The route revalidates the order cache, removes the cart cookie, and sends the customer to the confirmation page. This ensures a consistent post-payment experience while keeping storefront data up to date.

Otherwise the route tries to place the order itself. If successful, the customer ends up on the order confirmation page. If an error happens, the customer is sent back to the checkout with `error=payment_failed` so they can pick a method again.

## Step 6: Add Provider Labels to Storefront Locales

Add `pp_robokassa_robokassa` to [`messages/en.json`](https://github.com/gorgojs/medusa-integrations/blob/5c7c2f15ccfb90f15d5d94abe7d303137550a421/examples/payment-robokassa/apps/storefront/messages/en.json#L514) and to every other locale under `messages/`:

```json title="messages/en.json"
{
  "PaymentMethods": {
    // ...
    "pp_robokassa_robokassa": {
      "title": "Robokassa",
      "subtitle": "Cards, SBP"
    }
  }
}
```

A locale missing an entry falls back to the English `title` and `subtitle` from `paymentInfoMap` in [Step 1](#step-1-configure-payment-provider).
